# WS-25 第一课题：ClassReserve v1 与远程预飞行协议

状态：本地审计完成、预飞行远程身份已冻结，尚未远程执行；2026-10-02。该文件只准入正确性和独立校准 pilot，不是正式效果预注册。WS-25 全部验收项仍以 [执行清单](../project-state/WS25_FIRST_PAPER_EXECUTION.md) 为准。

## 1. 历史证据与可证伪假说

本地从既有原始结果重跑 `scripts/verify_ws11_formal.py`：40/40 格，192 档 MoE 交互 5/5 正、中位 +35.90568060021436%，但背景安全失败，`phenomenon_go=false`。重跑 `scripts/verify_ws12_formal.py`：120/120 格、旧臂 FCT 哈希 40/40 相同；逐包 RR、随机、自适应、DRILL 的主 192 档 MoE 相对逐包哈希降幅中位分别 16.116/18.406/21.056/22.549%，四臂背景安全均失败。两验证器读取本机 `results/<实验ID>/` 的 metadata、raw、输入哈希和资源收据，旧结论不变。WS-19/20 固定 `b52e66f...` 的三个独立需求显示 ToR/192 联合准入臂的 MoE 轮均均慢于 ECMP；背景 P99 与目的出口排队同现，但有反例，不能据相关性宣称单一因果。WS-23 隔离 NO-GO 和 WS-24 合成多 rail 结果仅是边界旁证。

**v1 假说：**在相同 16,384 条 MoE 与追加背景分布中，让 8 MiB 背景流每跳按首次选择固定路径，让 MoE 数据包在两个确定性候选间避开本地总排队和背景排队，可同时缩短 MoE 合成批次并限制背景 P99 损害。它比 WS-09 GuardHash 多了背景流首次队列选择和后续按流固定；MoE 评分固定为 `本地出口总排队字节 + 本地背景排队字节`，不读取下游反馈、不源端串行准入、不调参。背景首包只比较两个候选的总排队字节；无类别标签、控制包、单下一跳仍走原语义或唯一下一跳。

**失败预测：**背景和 MoE 在唯一目的主机出口相遇时，本地上游路径选择无法绕开末跳；类别队列为零时两候选的差异可能退化为普通双选；背景首次选路也可能把长流集中到另一处。若 MoE 改善而背景 P99 仍恶化、或者源 ToR 选择改变但目的出口/反馈并未改善，则 v1 双侧假说失败，保留 raw，不调整门槛追求正数。

观察链为：`WorkloadTag` → `DoLbClassReserve` → 源 ToR 各类别端口选择、背景流固定命中、双选/改选计数 → 本地类别队列字节守恒 → FCT/批次和 P99。已有 WS-13 逐 QP/逐跳诊断仅在部分场景开启，最终分析仍须核实目的出口、NACK/超时和乱序所需原始观测；空 queue 文件不得填零。

候选台账：`v1=classreserve (LB_MODE 21)`，当前唯一新候选；诊断修正次数 0/1。后续至多再有 v2、v3，各版至多一次修正，修正用新 SHA/ID。历史 WS-09/12/18 原型不算本课题新候选，也不代替五个原始模式。

## 2. 五原始模式兼容性审计

原始仓库固定 `a8d2db5f057172ce89730b4f6344c531e34a9302` 定义的模式号：ECMP 0、DRILL 2、CONGA 3、LetFlow 6、ConWeave 9。本 fork 的 `run.py` 仍保留映射；`CongaRouting`、`LetflowRouting`、`ConWeaveRouting` 源文件相对该 SHA 未变。`switch-node.cc` 在五个既有分支之外增加了模式与观测，但共同传输、输入解析和 MMU 已随 WS-06 以后变化，因此 **本阶段是同一新 SHA/传输条件下的五个原始选路模式，不是把六列 trace 直接喂给原始 a8d 二进制**。a8d 的 `ReadFlowInput` 只消费五列，无法读类别列；新 fork 的五/六列解析、tag 通路和 `--flow-file` 是共同兼容层。原 `drill` 曾缺远程 CLI 白名单，本次补入；`packet-drill` 为 WS-12 的 tag=2 专用模式，不能代替原 DRILL 2。

静态拓扑核验：主拓扑 SHA-256 `74a6f7154ca10c3cd6dfd45046c4f8abf0ce27faa8ad11446b6a52920b83afba`；rail 0 的 40 个 ToR 两两可达，交换机最短路径跳数为 0/2/4，ConWeave 四端口 path id 的结构上限未被超过。拓扑含 10 ns 主机链路及 100 ns fabric 链路，而 ConWeave 源码仍按统一 `one_hop_delay=1000 ns` 估计各路径 base RTT；这是性能/超时口径风险，须在同条件正确性格观察，不凭静态连通性宣称 ConWeave 已通过。五模式共同使用 400 Gbps、9 MiB、DCQCN、PFC=0、IRN=1、相同 ns-3 seed=1、相同输入/拓扑/监控。模式专属控制开销如 CONGA/ConWeave 自身反馈应分别计入，不抹除其机制差异。

目前五模式的 **编译、六列同输入端到端完成率、字节守恒、动态分支覆盖尚未验证**。任何失败须按该模式原 ID、日志和源码定位；必要兼容修复使用新 SHA、新 ID，并重跑受影响的共同回归，不能丢弃该基线。最小运行只作正确性，不作效果排序。

## 3. 独立需求与指标口径

只读参考 `maplerime@470c580` 的 `config/gen_moe_flow_1280.py` 是原四档生成规则；本分支的 `scripts/make_ws25_demand.py` 以显式整数 seed 重抽：rail 0 的 320 主机中抽 256 专家节点，各源在其余专家中无放回抽 64 个目的；剩余 64 主机生成最多 192 个有向不重复背景对。专家/背景主机集合不交叠；全部同启于 2.000 s、PG 3，8 KiB/tag 2 与 8 MiB/tag 1，背景 64/128/192 嵌套。本地用 seed `2026` 回放四档，与迁入的原始四份 trace 逐行完全相同（原文件 CRLF 与新输出 LF 的字节差异不当作流量差异），因此生成规则有直接回归证据。单条 seed 是独立需求单位；同 seed 的各模式和档位必须字节级配对。固定 `RANDOM_SEED=1` 只控制模拟器随机过程，不代替需求 seed。原始输入组与 WS-11 的行顺序置换仅为旁证，不计独立需求。

预先分开的 seed 池：筛选 `20262511–20262514`；校准 pilot `20262501–20262504`；未见最终验证 `20262521–20262544`。这些整数不相交。每池实际使用数量和最终样本量在校准 raw 后按冻结方法确定；**最终 seed 在筛选/校准时不得查看结果**。当前仅生成校准 seed `20262501` 的四档，输出为 `config/ws25_seed20262501_b{0,64,128,192}.txt`，SHA-256 依次为 `5cfa832eaa871a2de7fcabe756f1fb7d475803ac9e04cb2d6aa8c83415be647f`、`f0c875871bf751cc494386e79767460c187008d4ac51d913984f7abe81a19114`、`795724826c798a5ad2511b91432b5bc59f244bca2b7de5416fab9ea74830ca93`、`9791006f71843ea74b044396f6ae112ea8340aa9781cf0d267876e0940b02f48`。一份八流同类/混合、同/跨 ToR 预飞行 trace 为 `config/ws25_preflight_seed20262501.txt`，SHA-256 `29ebe2dcf38c0e4d29326947c4bc4e111f6b56fe378c020c30ee788fbaa5effb`，仅测试路径和回退，不作效果样本。

主结果：输入 trace 为分母，只有 16,384 条 MoE 均完成，才定义合成批次时间 `max(完成绝对时刻)−2.000 s`；背景 P99 仅在对应 64/128/192 条均完成时定义，以输入逐流 ID 与 FCT 匹配、线性插值。未完成时该格判正确性失败，批次/P99 不用完成者截尾替代。0 档没有背景 P99。192 为唯一主档；0 档检查无背景退化，64/128 为预设方向和伤害约束。逐格保存背景吞吐、uplink 利用率/不均衡、源端选择、队列字节与丢包、目的出口、CNP/PFC、乱序/重传可用性；缺少的项明示不可得并在正式协议前补齐或明确机制主张限制。批次是合成同步集合，不称真实 job CCT。

校准 pilot 只估计独立需求间的配对波动、可检测幅度及资源，**不得充当最终验证**。校准完成后，在任何最终格启动前，单独冻结：MoE 相对五基线的主比较方法与改善下限、背景 P99 容许损害、0/64/128 约束、独立最终 seed 数、置信/多重比较方法、停止条件和全部最终 ID。当前没有这些数值，正式矩阵禁止启动。历史 5% 仅为旧协议线，不自动移植为新 SLO。
