# WS-25 正式矩阵反例与下一候选门槛

日期：2026-10-06。以下是已揭盲 v1 正式数据的**事后诊断**，只用于解释 v1 和提出可证伪的新问题；不得据此在原 24 个最终需求 seed 上修改 v1 并重判确认性收益。

## 从正式 raw 复核的两个尾部反例

在 64 条背景流档，seed `20262543` 的背景 P99 从 ECMP 的 674.964 µs 升为 ClassReserve 的 983.066 µs，变化 +45.647%。两格原 ID 分别为 `20261004-070000-ws25-formal-s43-b064-fecmp` 和 `20261004-070000-ws25-formal-s43-b064-classreserve`；其 FCT 原始文件 SHA-256 分别为 `2447c24415711a30e025a04df23319ad36871061ea40d312775a92617e793cb8`、`02bbd3324a22a9a1cb128efb0bf4f8a9319bb068f7f21ed2797902ed35a2980c`。按相同 `src,dst,size,start_ns` 配对 64 条背景流，逐流 FCT 差值的中位数约 −2.147 µs，但最严重的五条恶化约 +256 至 +351 µs，其中五条目的主机均为 `1040` 或 `1052`。拓扑原始文件将这两个主机都接到 ToR `1408`。ClassReserve 在该格仅有 7 次背景首次选路的第二候选避让，记录了 284 次背景新流选择和 2,382,192 次背景缓存复用；ECN 计数由 ECMP 的 143 升至 209。平均活跃 ToR 端口不均衡指标从 3.111 降至 2.950，然而背景 P99 恶化。由此不能把总 uplink 不均衡改善直接当作尾部改善。

在 192 档，seed `20262524` 的背景 P99 从 1,300.271 µs 升为 1,467.689 µs，变化 +12.876%。原 ID 分别为 `20261004-070000-ws25-formal-s24-b192-fecmp`、`20261004-070000-ws25-formal-s24-b192-classreserve`；FCT SHA-256 分别为 `48453a24b8c32fdd0d44bea7bfefbf40fcfb4cf96ac05a1c5e9cba544e70b834`、`aadffa71291fbaf6fab0fce7635b54bad0f3729fdb59c5841c817c3ba99acb8e`。192 条背景流的逐流差值中位数约 −0.937 µs，最大两条恶化 +519.400 与 +493.035 µs，目的主机同为 `1176`，接到 ToR `1412`。该格 ClassReserve 的 882 次背景新流选择中有 58 次第二候选避让；平均活跃 ToR 端口不均衡从 2.943 降至 2.488，ECN 计数从 1,297 升至 1,417。MoE 批次同时从 19.671 µs 缩短到 17.733 µs。

这两个反例说明**个别目的端汇聚的长流变慢足以影响 P99**，即使大多数背景流差值接近零、全局 uplink 不均衡看起来较好。目的主机聚集、ECN 计数变化和尾部恶化是同现线索；目前没有逐流路径、目的出口的物理队列占用和逐 QP 重传时标，尚不能证明末跳拥塞或某一次首次选路是唯一原因。ECN 计数也不等于重传数。

[WS-19 探索小样](ws19-admission-pilot-report.md)和[WS-20 反例审查](ws20-counterexample-gate-review.md)在另一套准入/路径联合机制中也观察到目的出口排队与背景尾部同现，同时记录了排队峰值升高而个别流仍变快的反例。[WS-13 反馈探针](evidence/ws13-feedback-probe-analysis.json)属于单 seed、局部逐 QP/逐跳诊断。这些历史结果说明目的出口值得观测，也说明其排队峰值不足以独自解释 FCT；它们的 SHA、输入和机制与本次正式矩阵不同，不能并入 v1 的 24 个确认性需求 seed。

## 迭代决定与新的证据门

v1 的确认性结论保持 NO-GO，唯一一次诊断修正额度已用（1/1）。**准入下一步为 v2 机制诊断设计，而非直接打开第二个正式矩阵。**待解决的问题是：背景首次选择后逐流固定，是否在目的端汇聚时形成持续热点；以及本地队列分数对背景尾部是否有足够预测力。现有正式 raw 可以生成假说，不能作为新版本的独立确认数据。

先在不改变流量语义的前提下审查可加的非扰动观测：背景流级路径/目的 ToR 汇聚、交换机实际出口 MMU 队列随时间、源/目的端 ECN 与重传时标。若观测可实现，先用筛选或新的诊断 seed 与独立 ID 检验两项反例预测，明确调度/选路可控点及可能的 MoE 代价；不得将 ConWeave VOQ 当作物理 MMU 队列。若源于唯一目的主机出口且选路没有可控路径，v2 设计应如实说明该限制，不把本地下一跳微调当作已解决。只有形成具体机制、正确性预飞行、独立校准、固定新 SHA/输入/ID/判据后，才能用未见需求 seed 评估 v2；同样保留 0/64/128 档约束及两项共同主结果。第二课题的状态反馈研究仍在第一课题之后，不并行启动。
