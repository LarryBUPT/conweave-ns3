# WS-21 路径身份诊断与反馈工程契约（待技术验证）

更新：2026-09-29。此阶段在模式 20 加入默认关闭的 `WS21_IDENTITY` 与 `WS21_PORT_EVENTS` 诊断；不改变选路，也不产生反馈包。前者检验源首口与目的 ToR 入端口逐 QP 关联，后者记录目的主机共享出口队列事件。固定 40 流同 SHA 开/关技术 pair 已通过路径身份和端口事件子门槛；完整技术 pilot 尚未就绪，效果矩阵 no-go 仍有效。

## 已落地的可观测边界

初始化时从 `nextHop` 最短路径 DAG 枚举每个源 ToR 到各目标主机的所有首跳及目标 ToR 入端口。若同一 `(源 ToR, 目的 ToR, 入端口)` 对应不同首口，初始化直接失败，不选择性忽略冲突。收包时 `QbbNetDevice::Receive` 已写入端口 `FlowIdTag`；目标 ToR 在进入 `SendToDev` 及最终出口 ECN 标记前读入端口与 `CustomHeader` 的 CE 位。源 ToR 在 `DoLbWs18` 返回后记录该 QP 的实际首口。两侧只在各自交换机中累积四元组、包数、首次/末次 ns、首口和一致性计数，仿真结束写 `_out_ws21_identity.txt`；**目的侧诊断状态没有送达源侧，也不能用于选路**。

`scripts/verify_ws21_identity.py` 将该文件与同 ID `_out_ws18.txt`、拓扑逐 QP 对齐，要求每条跨 ToR 已完成流有且仅有两侧记录、首口一致、没有未映射或变口、时间顺序在 release–finish 内。它同时报告目的入包时的上游 CE 包数；这个计数可能包含源首跳之后多个上游节点的标记，尚未证明可区分两候选。此汇总没有逐包时序、RNIC 转折事件、控制包或资源峰值，因此通过此核验也只满足**路径身份子门槛**。

40 流技术 pair 固定 `config/ws18_1280_correctness.txt`（SHA-256 `4e7d0e6a68e3230e8960a174e570a0a788c191fa0b44922408867b02c25782cc`）、`config/topo_1280_400G_400G_OS1.txt`（SHA-256 `74a6f7154ca10c3cd6dfd45046c4f8abf0ce27faa8ad11446b6a52920b83afba`）、DCQCN/PFC=0/IRN=1/ns-3 seed=1、模式 20、准入与路径开关 `(0,0)`。同 SHA `2a5e7e8722814befc259d1ddece814ed17cbfcbc` 的开/关 ID 为 `20260929-070000-ws21-proof-off` / `20260929-073000-ws21-proof-on`；40/40 完成、33,849,344 B 守恒，FCT SHA `0f8fd036bc40602f50d1287369f642351fb4b64af60d052a28b1b744c6a7637e`、WS18 SHA `bc7004a69af353441a72e9808165a3794bc5d3659c73cec546dc0a4d1763d009` 开关完全一致。逐 QP 身份两侧各 40 条、零错误。该技术格不作收益样本。

## 已运行验收的共享出口事件流

`WS21_PORT_EVENTS=1` 时，模式 20 在每个目的主机出口端口记录仿真前后边界、设备队列的入队/出队/拒绝和链路关闭丢弃事件，行字段为 `(time_ns,tor,port,event,queue_bytes)`；默认上限 256 MiB，达到上限后停止写事件并累计溢出数。它按**端口**流式写盘，不用 64 µs 环形桶，也不为每条 QP 复制共同队列轨迹。`scripts/verify_ws21_port_events.py` 流式核对边界是否覆盖同 ID `_out_ws18.txt` 的最早 demand 至最晚 finish、时间与队列变化方向、原始事件/字节计数及 `overflow=0`。40 流技术 pair 的开启格覆盖 1280 个目的主机出口，记录 138,080 条事件、3,303,220 字节，队列峰值 308,456 B，`overflow=0`。这是本输入范围的技术验证；不能声称验证 WS-19 的 13.29 ms 背景长尾。

本次 pair 首次验证暴露并修正了三处 optimized 构建副作用：路径映射插入、端口事件 `fwrite` 和目的端 `PeekPacketTag` 曾放在 `NS_ASSERT_MSG` 参数中，optimized 模式会移除这些调用。另因固定拓扑由四个不连通分量构成，路径 DAG 初始化现跳过不可达源 ToR/目的主机组合，并记录跳过数；可达路径内部缺表仍为硬错误。完整逐 QP 时序仍缺其经过共享出口的入/出包汇总和带时间的 CNP、速率、NACK/SACK、重传及超时转折；端口事件流与完成时刻只能做离线窗口关联，不能单独确证某 QP 受压机制。当前 pair 未记录运行期间 CPU/内存峰值；若后续做长尾观测，仍需核对资源峰值、写入速率与 13.29 ms 覆盖。

## 显式反馈消息的待实现协议

候选消息应按 `(源 ToR, 目的 ToR, 源首口)` 建 key。目的 ToR 只用**最终主机出口标记之前**的上游 CE 样本形成有分子/分母的窗口记录；`denominator=0` 表示缺测，不能当 0% CE。首次技术实现应先固定消息字节布局和实际注入/转发机制，再冻结级别或 10 µs 新鲜度。建议字段为协议版本、源/目的 ToR、源首口、采样窗口起止 ns、CE 分子/分母、单调序号、订阅 epoch；报文另计 PPP/IP/UDP 等实际头部、序列化、传播、队列和处理耗时。`PacketTag`、静态映射表和 ns-3 全局对象只可作为本地诊断/初始化资料，不能充当跨 ToR 的反馈传输。

源端仅接受匹配订阅 epoch 且序号更新、`sample_end <= arrival <= decision` 的报告；还须有最大年龄、最大 key 数、超限淘汰、乱序/丢包计数和缺失/过期时回退本地臂。订阅只在存在该 `(源 ToR,目的 ToR,候选)` 待决策需求时打开，最后待决策流过后取消，空闲停止发送；无反向业务流也须通过显式控制包送达。报表必须分别记录**生成、送达、丢失、过期和被选路使用**的消息数、线上字节及年龄分布，不能拿上一轮静态 16 B 逻辑预算当实测。目的主机共同出口队列可用于解释或准入诊断，不能给不同候选赋不同分数。

停止条件：身份动态核验失败、候选无可区分的有效上游样本、无法给控制包真实转发与成本、或完整尾部观测溢出时，WS-21 仍停在技术诊断。旧 WS-10/11/12/19 及原 WS-20 no-go 不改；没有新的效果协议或结果。
