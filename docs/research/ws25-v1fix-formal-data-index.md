# WS-25 v1 正式矩阵逐格数据索引

本索引对应冻结仿真源码 `ce699dffe2845dc83e2171a1c309c6d96b96d2b3` 的 24 个需求 seed × 4 个背景档 × 6 个模式，共 576 个正式原 ID。全部原始结果保留在 Git 忽略的本地 `results/<ID>/`；表中给出相对工作区根目录的 raw FCT 路径、原始目录号、输入与输出 SHA，便于回查，不把 CSV 当作 raw 替代品。

- [576 格逐格指标表](evidence/ws25-v1fix-formal-cell-metrics.csv)：每格 MoE 与背景的完成数、FCT 均值及 P50/P90/P95/P99、slowdown 的 P50/P90/P99，以及合成批次时间。0 背景档的背景指标留空，完成数为 0。单位为微秒，slowdown 无量纲。
- [840 条逐 seed 配对表](evidence/ws25-v1fix-formal-seed-pairs.csv)：每个 seed、档位将 ClassReserve 与五个基线逐一配对；0 档只有 MoE 指标，其余档位各有 MoE 与背景 P99。变化率为 `100 × (ClassReserve/基线 − 1)`，负值表示候选较快。每个需求 seed 才是独立统计单位。
- [逐 seed 六臂 CDF 图索引](evidence/ws25-v1fix-formal-cdf-index.csv)：每个 seed × 档位有一张 MoE FCT 图；64/128/192 档另各有一张背景 FCT 图，共 168 张 SVG、1008 条模式—图—原始 ID 映射。图在 [CDF 目录](figures/ws25-v1fix-formal-cdf/)；每条曲线直接读取并核对其原始 FCT SHA。0 档没有背景流，故不画背景 CDF。
- [跨 seed 六臂与配对总览图](figures/ws25-v1fix-formal-seed-overview/)：0/64/128/192 档各有 MoE 批次图，非零背景档各有背景 P99 图；每项同时给出六臂绝对值与 ClassReserve 对 ECMP 的逐 seed 百分比变化。四档另各有上联活跃端口平均计数器等效率和上联端口不均衡图，共 22 张。横轴是 24 个需求 seed；SVG 点位悬停文本包含完整原始 ID 和准确值，不将相邻 seed 连成趋势线。
- [576 格上联采样换算表](evidence/ws25-v1fix-formal-uplink-metrics.csv)：逐格给出原始 uplink 路径与 SHA、实际采样时间跨度/间隔、1280 个上联端口中的活跃端口数、累计字节、平均与单样本峰值的**计数器等效率**。由 `python scripts/export_ws25_formal_uplink.py` 重建；每端口用相邻累计字节差和实际纳秒间隔计算 `8×字节差/纳秒差` Gbps，再除以配置的 400 Gbps。所有 576 格的时间间隔均为 10,000 ns，活跃端口各为 320；单样本峰值的等效占比可达 106.66%，说明该原始字节计数/采样口径不能当作物理链路实时利用率或容量违例。跨格比较须明确为计数器等效率。
- [96 格 ConWeave VOQ 原始采样表](evidence/ws25-v1fix-formal-conweave-voq.csv)及[24 seed × 四档热图](figures/ws25-v1fix-formal-voq/conweave-voq-max-packets-24seed.svg)：只读取 ConWeave 模式真实存在的逐 ToR 采样，不按期望样本数补零。96 格都有效；仅 seed `20262522`、192 档有一条非零采样，最大 1 个 VOQ、3 个缓存包，另有一条 per-destination 原始记录。其余图格的 0 是有效采样实际为零，不能解释为动态分支在所有未采样瞬间都未发生。这里的 VOQ 是 ConWeave 接收侧重排缓存，绝不是物理 MMU 队列。
- [192 档配对效应图](figures/ws25-v1fix-formal-192-effects.svg)与[正式分析和门槛](ws25-v1fix-formal-analysis.md)：共同主结果 NO-GO；上面两表为逐格和逐 seed 查询入口，不修改冻结判据。图包共 192 张 SVG：168 张 CDF、22 张跨 seed 总览、1 张 VOQ 热图和本张配对效应图。

重建命令：依次运行 `python scripts/export_ws25_formal_tables.py`、`python scripts/export_ws25_formal_uplink.py`、`python scripts/export_ws25_formal_voq.py`、`python scripts/plot_ws25_formal_cdfs.py` 与 `python scripts/plot_ws25_formal_seed_overview.py`。首个脚本要求分析 JSON 已逐格核验 576 格，从每个正式 ID 的 trace/FCT raw 重建类别统计、校验完成数及哈希，再写 CSV。P90 与 slowdown 直接由已完成流 FCT 原始行计算；合成批次和其余百分位与项目的 `analyze_moe_tags.py` 口径一致。本次重建得到 576 行与 840 条配对；192 档对 ECMP 的 MoE 中位变化 −3.536465%（20/24 改善）、背景 P99 −0.064643%（13/24 改善），与正式报告四舍五入值一致。CDF 图的横轴是微秒对数刻度、纵轴是已完成输入流的累计比例；同一图六条曲线共享同一 trace。正式 576 格均全部完成，因而图中完成流的分母与该格输入流数相同。MoE CDF 为减小 SVG 体积只在约 400 个分位点画线，包含 90/95/99/99.9/99.99 百分位与最大值；CSV 中的百分位始终从全部 16,384 条原始流计算，背景 CDF 则保留全部 64/128/192 条流的阶次。
