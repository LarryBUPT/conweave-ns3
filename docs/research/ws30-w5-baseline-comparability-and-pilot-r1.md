# W5 基线可比性审计与持续混合负载建议

日期：2026 年 10 月 26 日。本文冻结一个供主对话核验的设计建议。[机器计划](evidence/ws30-w5-proposed-pilot-design-r1.json)明确 `execution_enabled=false`；新增仿真未启动。W5 的负载广度与基线动态触发问题仍待实测解决，当前不以文字修改宣告完成。

## 1. 已有 ConWeave 的来源和动作条件

只读作者仓库本地参考 HEAD 为 `236a801a00e35de9078635e04acae2f701c21ded`，来源为 `conweave-project/conweave-ns3`。其 `conweave-routing.{cc,h}` 和 `conweave-voq.{cc,h}` 四个 Git blob，与本轮固定仿真 SHA `2c9f3a5` 完全相同。算法出处与 blob 值见[来源收据](evidence/ws30-v13-reference-and-baseline-audit-r1.json)。本项目的拓扑支持、传输修复和公共观测属于外围变化；原生路由/VOQ 实现的字节相同不等于外围环境完全相同。

源码在数据包到达源 ToR 时检查 `activeTime + txExpiryTime < now`，过期启动新 epoch；收到稳定回复后也可开启下一 epoch。非过期/非稳定且 replyTimer 已过时，当前包标 TAIL，后续包进入 phase 1 并使用下一路径，见 [conweave-routing.cc](../../src/point-to-point/model/conweave-routing.cc:466)。若 QP 已没有后续数据，超时条件本身不会凭空触发数据换路。`m_nReRoute` 统计选路分支执行，候选路径可能仍与原路相同；应联合公共实际 port-change 计数判断动作。

目的 ToR 的 RTT_REPLY、CLEAR 和 ECN NOTIFY，分别影响计时、阶段和路径忙状态。早到 phase 1 包可能进入 VOQ，随后按 TAIL/时间估计释放。短 QP 没有 VOQ 或改路属于该输入下的实际动作结果。持续背景 QP 和错峰短消息能观察新的时序条件，不能预先保证 ConWeave 将改善性能。

本轮建议沿用大拓扑已有的原生配置：DCQCN、PFC=0、IRN=1；extra reply deadline 4 μs、path pause 16 μs、extra VOQ flush 16 μs、default VOQ waiting 300 μs、tx expiry 1,000 μs。参数来自 [run.py](../../run.py:399) 对 `topo_1280_400G_400G_OS1` 的现有分支。实际 reply deadline 还包含该源/目的的 baseRTT。禁止用通用常量假设所有路径 RTT 相同，也不通过缩短这些计时器追求更高名次。

## 3. 冻结的同条件 pilot 建议

设计动机为持续 bulk RDMA 与周期短消息叠加。两种时间安排对应同步突发和后台传输已开始后到来的通信批次。该负载是可复现合成模型，尚未建立与真实训练 WQE 或某个业务 trace 的逐项映射。

沿用 `topo_1280_400G_400G_OS1`、400 Gbps NIC、9 MiB 交换机缓冲、DCQCN、PFC=0、IRN=1，共同 ns-3 seed 为 1。显式 trace 生成 seed 使用尚未运行的 20,263,101 和 20,263,102。新生成器借用 WS-25 的 256 个专家/64 个背景 host 抽样规则。

每个专家仍选择 64 个不同专家 peer，按固定 seeded permutation 分成 8 轮，每轮每源 8 个 peer。每轮共 2,048 条 8,192 B 消息，轮间隔 100 μs；八轮合计 16,384 条、128 MiB。背景使用 seeded 端点列表的前 32 条不同有向 pair，每条为一个持续发送的 64 MiB QP，合计 2 GiB。两种安排保持全部身份、尺寸、总字节和行序规则一致，仅将前台起点由背景同步改为晚 20 μs。

每条 64 MiB 背景 QP 在空闲 400 Gbps NIC 上也至少需约 1.342 ms 序列化，覆盖八轮最后一次释放的 0.700/0.720 ms。这个持续条件由固定字节数和物理速率决定，未根据算法运行结果挑选。短消息每 trace 行仍创建新 QP；持续背景单 QP 与真实应用连接复用分别表述。

比较清单固定为 E、CONGA、LetFlow、ConWeave、原生 DRILL、严格 Q12、R12 和 U12。2 个需求 seed × 2 种安排 × 8 方法为 32 格。Gemma、SeqBalance、DiffFlow 和 SGLB 的忠实度门槛尚未满足，暂不以简化版本填入该清单。

另外冻结 4 格 ConWeave 观测资格检查：`technical168` 与持续诊断输入各做观测关闭/汇总一对。持续诊断输入取 seed 20,263,101 的全部 32 条长背景和第 0 轮前 128 条短消息，使用同步时序。新状态观测只能读事件，不调用 RNG、不调度模拟事件、不添反馈包；需验证两对 FCT 哈希一致。共建议 36 格。新增 observer、输入和 source SHA 尚待工程与主对话验收；当前仅冻结设计，未分配远程 ID。

## 4. 动作和性能观测

动作层记录原生 RTT_REPLY、CLEAR、NOTIFY、reroute 分支、实际端口变化、epoch/phase/INIT/TAIL 状态事件、反馈年龄，以及 VOQ 分配、释放和最大占用。以原生分支数和真实端口变化的差异识别“重新选了同一路径”。状态事件只对固定诊断子集详细记录，设置 64 MiB 硬限，溢出即停止新格，保留失败原 ID。

性能层完整报告八轮各自的消息批时间和所有轮次的整体跨度，全部从原始需求计时；同时报告 32 条背景的每条 FCT、P50、线性 P99、最大值和完成比例。P99 在 32 条背景中尾部分辨率有限，须连同全部点和最大值交付。端侧 gap、SACK、实际重传字节、超时、共享队列与输入/完成守恒按标签保留。

只有两个独立需求 seed，统计定位为 pilot。轮次、包、同输入观测复跑不增加独立样本数。零 reroute、零 VOQ、双侧变慢或一侧获益均保留；参数冻结后不通过调整 timeout 改排名。若预定义条件没有触发目标分支，按实际动作覆盖报告，再由主对话决定是否另立新设计。

## 5. 资源、期限和未解决事项

资源建议沿用本轮已测 cap 8、单份 `-j2`、最多四份并行构建。36 格至少涉及 9 组隔离构建。以本轮约 7 分钟/构建组及 cap 8 仿真跨度 383 s 为预算依据；新输入有效字节是资源 pilot 的约 1.308 倍，运行时间不能按字节比例保证。预留远程构建/运行 2～4 小时、observer 和生成器 1～2 小时、回传分析 1.5～2 小时，合计约 4.5～8 小时。

此预算与正式 168 格的约 7.13 小时构建运行预算分别列示。主对话需要在期限和服务器新鲜资源下确定顺序；当前没有并行占用资源或扩大执行范围。原 46 格中非平凡 CC/SACK 与持久不同候选的科学覆盖问题也须具体承接，不能由本 W5 设计自动代替。

本节点参考复核保留固定 PDF 和技术附件哈希。借鉴限定为状态、计时、完整请求与成本的核验方法；候选文献不替代源码与实验 ID。ConWeave、Gemma 的交换机重排硬件条件，SeqBalance 的驱动/verbs 语义及 SGLB 的 ASIC/控制面能力均超出当前纯 ns-3 验证。W5 和正式 168 格继续等待主对话验收。
