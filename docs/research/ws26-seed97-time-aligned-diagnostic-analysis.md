# WS-26 seed 97 时间对齐诊断分析

状态：2026 年 10 月 10 日，四格原始结果和资源收据已验收。本报告只分析已揭盲的 seed `20262697`。WS-26 仍为 ACTIVE；ClassReserve v3 和 ClassLane v4 r2 的双侧 NO-GO 不变，第三候选及正式矩阵继续关闭。

## 结论与证据范围

本轮定位了两种不同的尾部时间。背景反例 `1124→628:10000/102` 在 v4 下多用 392.383 μs；几乎全部差值已经出现在最后一次发包时刻。该 QP 收到更多 CNP，观测到的最低发送速率更低，但现有记录不能把差值唯一归因于反馈。v4 最晚的 3 条 MoE QP 则几乎同时完成发包，最后一包沿共同的上游路径各等待约 11.3 μs。ECMP 的另 3 条最晚 MoE QP 在 v4 下换路后变快，说明尾流身份发生迁移。

这些是同一个已揭盲输入上的机制观察。23 条预选 QP 是嵌套观测，不是 23 次独立实验。路径变化、其他流的改道、共享出口和传输反馈相互影响；时间先后与同身份配对不能单独证明其中一项造成全部 FCT 差值。

## 时间对齐口径

分析脚本 [`analyze_ws26_seed97_time_aligned.py`](../../scripts/analyze_ws26_seed97_time_aligned.py)从原始 trace 还原每条 QP 的四元组与类别，再读取 FCT、源端 `send`／`ack`／`cnp`／速率事件和交换机逐包记录。23 条 QP 的每次 `send` 均能以 UID 和序号匹配完整逐跳链；`complete` 时间与原始 FCT 完全一致。时间均相对共同的 `2.000 s` 起点。单包等待是同一 UID 各跳 `dequeue_ns−enqueue_ns` 的和；跨包、跨时刻的区域峰值没有相加为 FCT。

下文的“最低速率”是事件日志中的瞬时最小值，不是平均吞吐。`ecn` 表示该跳出队时作出的标记决定。目的 ToR 的出口等待属于设备队列观测，不等于 MMU 物理总占用。CNP 次数和发送速率只能说明时序关联；本诊断没有隔离反馈、路径和其他流改道的单独消融。

## 背景尾流：差值主要出现在发送完成前

| 同一背景 QP | ECMP FCT → v4 FCT | 最后发包时刻 ECMP → v4 | 源端 CNP ECMP → v4 | 最低速率 ECMP → v4 |
| --- | ---: | ---: | ---: | ---: |
| `1124→628:10000/102` | 1,561.055 → 1,953.438 μs | 1,560.469 → 1,952.874 μs | 79 → 110 | 39.467 → 14.300 Gbit/s |
| `692→628:10005/104` | 1,394.156 → 1,778.733 μs | 1,393.994 → 1,778.597 μs | 88 → 119 | 48.941 → 27.555 Gbit/s |
| `896→628:10000/100` | 1,146.787 → 1,790.425 μs | 1,145.433 → 1,789.861 μs | 98 → 105 | 50.852 → 14.510 Gbit/s |

对 `1124→628`，FCT 差值为 +392.383 μs，最后发包时刻相差 +392.405 μs。两模式最后一包的总出口等待为 0.022 μs 和 0 μs。该 QP 在发出 25% 数据对应序号时，ECMP 已用 351.230 μs，v4 用 709.817 μs；滞后较早形成。首次 CNP 分别在 20.595 μs 和 14.511 μs 到达，v4 的 CNP 次数和速率下降事件也更多。其目的出口单包最大等待分别为 4.380 μs 和 4.390 μs；源端与中转区域最大等待在 v4 反而下降。已测得的单包排队无法直接填满 392.383 μs。反馈触发的发送节奏变化是合理线索，但其他 QP 的路径与排队变化仍可能共同改变反馈。

`692→628` 是固定路径反例：两模式完整交换机路径同为 `1349:10→1505:4→1347:6`，FCT 仍增加 384.577 μs，最后发包时刻增加 384.603 μs。该 QP 的 CNP 从 88 增至 119，首次 CNP 从 23.884 μs 提前到 17.331 μs。它证明自身改道不是出现此类退化的必要条件；共享路径上的其他流及反馈时序仍未隔离。`896→628` 增加 643.638 μs，但 CNP 次数只增加 7 次，也提示不能以 CNP 总数线性解释时长。

5 条去重背景对照与目标共享目的 ToR `1347`，FCT 配对变化为 −34.09 μs 至 +203.75 μs，其中 2 条变慢、3 条变快。共同目的 ToR 不足以推出相同的尾部方向；对照也共享同一批流量，不能当作独立试验。

## MoE 尾流：最后一包在上游排队

| v4 最晚 QP | ECMP FCT → v4 FCT | 最后发包时刻 ECMP → v4 | 最后一包逐跳等待 ECMP → v4 |
| --- | ---: | ---: | ---: |
| `964→1148:10059/136` | 12.055 → 22.697 μs | 10.943 → 10.892 μs | 0.602 → 11.295 μs |
| `980→1128:10059/156` | 12.731 → 22.673 μs | 10.908 → 10.867 μs | 1.313 → 11.296 μs |
| `988→1120:10056/151` | 14.292 → 22.669 μs | 10.885 → 10.833 μs | 2.897 → 11.326 μs |

v4 将这 3 条 QP 从源 ToR `1382` 的同一端口 `16` 送入相同上游链：`1382:16→1543:10→1657:5→1575:4`，再到目的 ToR `1411` 的不同主机端口。以 `964→1148` 的最后一包为例，四个上游出口分别等待 1.707、3.769、4.707 和 1.112 μs，目的 ToR 出口等待为 0。逐包链合计 11.295 μs；其 FCT 相对 ECMP 增加 10.642 μs。另两条最后一包具有近似的上游等待与完成时刻。三条数据的最后发包时刻均比 ECMP 略早；自身发送结束时刻没有形成相应的完成差值。

ECMP 模式最晚的另 3 条 MoE QP 是 `1076→1120`、`1080→1148` 和 `1116→1128`。它们在 v4 下分别快 7.294、7.180 和 6.391 μs，最后一包的出口等待也同步下降。两组尾流身份不相同，故只比较两模式各自的最慢值会遮蔽转移过程。6 条 MoE 对照共享目的 ToR `1411`，FCT 变化为 −0.57 μs 至 +3.17 μs，没有出现 v4 目标组约 8～11 μs 的同方向延迟；对照的源端与具体路径仍不完全相同。

全量 trace 的 16,384 条 MoE 和 192 条背景流在两格均全部完成。该已揭盲 seed 的 MoE 合成批次为 18.472 → 22.697 μs，背景 P99 FCT 为 1,686.46 → 1,779.79 μs。这些数值提供尾流位置背景，不是新增独立效果样本，也不重判四 seed 的 v4 pilot。

## 竞争解释、失败分类与后续门槛

| 既有失败类别 | 本轮增加的证据 | 仍不能确定的部分 |
| --- | --- | --- |
| v3 MoE 改善不足 | 本轮没有 v3 格；既有诊断保持有效。 | v3 的路径碰撞、共享下游和反馈作用未被这两格分离。 |
| v3 背景 P99 恶化 | 本轮没有 v3 格；既有同路径退化反例保持有效。 | 无法把 v4 的具体时序套到 v3 机制。 |
| v4 MoE 尾部变慢 | 3 条新尾流的最后一包同走上游链，约 11.3 μs 等待；原 ECMP 尾流换路后变快。 | 多流汇聚与 ClassLane 的路径份额同时变化，尚无单因素消融；选中流不代表全部 MoE 流。 |
| v4 背景 P99 两升两降 | `1124→628` 和同路径 `692→628` 的延迟主要位于发送结束前，较早 CNP 与较低瞬时速率同现。 | 其他流改道、共享目的出口及 DCQCN 响应耦合；CNP 次数不能换算成 FCT 因果份额。 |

本轮没有观察 MMU 物理总占用、所有 QP 的发送端速率或真实网卡状态。单个 seed 已揭盲，目标与对照也在看过普通格后预注册。诊断支持“背景退化需要检查反馈与发送进度”和“v4 MoE 新尾部集中于同一上游链”两项具体机制线索；它仍不能确定一个新的在线可操纵信号或第三候选的双侧预测。ClassLane v4 r2 高档 NO-GO 保持，条件低档 24 格、正式主矩阵 576 格、传输敏感性矩阵 576 格和最终全任务验收仍列为 WS-26 未完成项，不能据阶段诊断宣布闭环。执行门槛见[WS-26 清单](ws26-classmix-execution-plan.md)。
