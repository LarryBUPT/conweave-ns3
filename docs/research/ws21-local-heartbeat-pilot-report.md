# WS-21 局部心跳小拓扑技术试验：检测时效与通信代价

日期：2026-09-30。证据等级：**单条长流、单 seed 的技术 pilot**。本报告从七个实验 ID 的本机回传原始文件重新核验；可重算的逐格收据为[机器摘要](evidence/ws21-local-heartbeat-pilot.json)，分析器为[`scripts/analyze_ws21_heartbeat_pilot.py`](../../scripts/analyze_ws21_heartbeat_pilot.py)。它只验证局部 HELLO/ACK 的传输、控制消息连续丢失后的状态变化和通信代价。`UNKNOWN` 尚不改变业务选路，因此不构成负载均衡或故障绕路收益。

## 流程与共同输入

按[事前预飞行](ws21-local-heartbeat-preflight.md)依次完成独立优化构建和 `devices-point-to-point` 单测、关闭格、200 µs 正常格、丢 HELLO、丢 ACK、50 µs 正常格、1000 µs 正常格。七个 ID 均有独立源码/日志/资源收据；单测资源状态为 `TESTED`，六个仿真状态均为 `SUCCEEDED`。单测报告同时给出 `WS-21 feedback header` 与 `WS-21 heartbeat header` 序列化校验 `PASS`。测试构建临时修正旧 core 测试辅助函数的一处 const 不匹配，测试后恢复；固定仿真源码未因此改变。

六个仿真都使用个人 fork `feature/ws21-downstream-feedback` 的固定源码 `770b6b5617657832393bd721e0d634c6639405fb`、ns-3 seed 1、`fat_k4_100G_OS2` 52 节点拓扑及同一条主机 0 到 8 的 67,108,864 B 跨 ToR 流。`WS18` 模式保持路径 1、准入关闭，`STATE` 反馈关闭，PFC=0、IRN=1。每格原始 `WS18_CONSERVATION` 都是输入/释放/完成 1/1/1，输入与完成字节均为 67,108,864 B；路由标签缺失 0。窗口内只有源 ToR 32 的端口 6 成为活跃心跳上联，峰值活跃端口数为 1。

拓扑哈希的表面差异来自换行符：Windows 工作副本的 CRLF 文件为 2,045 B、SHA-256 `445cf1e29b91813a5fcfec2e56966fb08e4436138d1f8f0771015ccfe6e24466`；固定 Git 提交中的 LF 内容为 1,979 B、SHA-256 `dcca23ca6992b9b81e5b71127a3698264441390455f3dd29b459e33db29915ad`。六格 `metadata.json` 和拓扑快照均为后者；前者将 CRLF 规范化为 LF 后也得到后者。固定 trace 及六格元数据/快照 SHA-256 均为 `032b6baaf3b1a6b4507a7699ef3a148eeadd1f343a13c61a12b79c65f1d49ff5`。因此可比输入一致，原预飞行表把本机工作副本哈希写为实验拓扑哈希的说法已更正。

## 正常工作时的代价

下表的“成功往返”是收到有效 ACK 的次数；“逐跳字节”是实际入队的 HELLO/ACK 包长累加，**不是**仅 10 B 的协议头长。每个消息在本拓扑的这条邻接链路上计 44 B。FCT 是同一条应用流的完成时间，差值以关闭格为基准。

| 格 / 实验 ID | 心跳周期 | 成功往返 | 逐跳控制字节 | FCT | 相对关闭格 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `20260930-020100-ws21hb-k4-off` | 关闭 | 0 | 0 B | 5.582475 ms | 0 ns |
| `20260930-020500-ws21hb-k4-50us` | 50 µs | 112 | 9,856 B | 5.582811 ms | +336 ns |
| `20260930-020200-ws21hb-k4-200us` | 200 µs | 28 | 2,464 B | 5.582559 ms | +84 ns |
| `20260930-020600-ws21hb-k4-1000us` | 1000 µs | 6 | 528 B | 5.582493 ms | +18 ns |

四个格的业务流均完整；三个正常开启格的 HELLO、ACK 生成数与有效接收数相等，超时、拒收、`UNKNOWN`、逐跳队列拒绝及事件日志溢出均为 0。50/200/1000 µs 对应的逐跳入队/出队各为 224/56/12，逐格守恒。50 µs 相比 200 µs 在这条流的存活期间产生 4 倍消息和 4 倍逐跳控制字节；1000 µs 仅产生约五分之一。作为标明分母的量，三档逐跳控制字节分别相当于 **67,108,864 B 应用输入字节**的 0.014687%、0.003672%、0.000787%；它们不是链路利用率，也未计全网其它业务。

单流 FCT 的 +18 至 +336 ns 是此次控制报文共用队列下的观察差异，样本数只有 1，没有随机需求重复、误差估计或显著性依据。既不能据此称心跳提高性能，也不能据此给出业务安全线。

## 连续丢失后的状态变化

两种故障格均保持 200 µs 周期。故障时间窗为仿真 `2.006100000–2.010000000 s`，仅注入心跳控制消息丢失：丢 HELLO 在邻居处执行，丢 ACK 在源 ToR 处执行；业务数据仍可走原链路。

| 格 / 实验 ID | 注入丢失 | 有效 ACK | 标为 `UNKNOWN` | 恢复 | 逐跳控制字节 | FCT |
| --- | ---: | ---: | --- | --- | ---: | ---: |
| `20260930-020300-ws21hb-k4-drophello` | 19 份 HELLO | 9/28 | 2.006801083 s | 2.010003168 s | 1,628 B | 5.582559 ms |
| `20260930-020400-ws21hb-k4-dropack` | 19 份 ACK | 9/28 | 2.006801083 s | 2.010003168 s | 2,464 B | 5.582559 ms |

两格都在连续三次未得到有效确认后各出现一次 `UNKNOWN`，窗口结束后的第一份有效 ACK 使状态各恢复一次；没有拒收、队列拒绝或日志溢出。实际检测时刻比故障窗开始晚 **701.083 µs**，比第一份被丢消息晚约 **599 µs**；恢复时刻比窗口结束晚 **3.168 µs**。`UNKNOWN` 之后仍持续探测，因此故障窗口内各有 19 次超时。丢 HELLO 时邻居只产生 9 份 ACK，链路中控制字节相应下降；丢 ACK 时邻居产生全部 28 份 ACK，ACK 已使用链路，故逐跳字节仍为 2,464 B。两格业务 FCT 与无故障的 200 µs 格相同，符合“只丢心跳、不改变选路”的试验设置，不能解释为故障恢复收益。

## 资源、时间与结论边界

七格资源观察器均形成逐点样本与终态摘要；六格仿真峰值进程树 RSS 为 649.6–880.8 MiB，最低可用内存不少于 122.17 GiB，最低剩余磁盘不少于 5,670 GiB，未触发预设资源停止线。六格各自的仿真实际墙钟时间只有 3–4 s；耗时主要来自每格隔离的 `optimized` 全量编译，各约 **346–347 s**，并以 `-j2` 限制编译并发。单测还需启用测试后的独立构建。这样的墙钟成本是为固定源码、独立目录和可追溯收据付出的实验成本，不能把它说成网络收敛慢。

本轮**通过**单测、固定输入守恒、正常往返与连续 HELLO/ACK 丢失后 `UNKNOWN`/恢复的技术子门槛。检测与通信代价呈可预期的取舍：更频繁的探测花更多字节，能够提供更短的理论计时机会；实际故障检测只在 200 µs 格测到约 0.701 ms。50/1000 µs 格没有注入故障，不能把三次未确认的 150/3000 µs 理论下界写成实测。没有可核验的故障恢复 SLO，当前不存在唯一“最优周期”。200 µs 可作为下一轮局部技术试验的已验证参考点，但不是全网配置结论。

未覆盖单份丢失不误报、旧/重复/乱序/跨端口 ACK、会话重启、显式链路 down/up，以及真正断链时业务是否绕路。该输入仅有一条 64 MiB 流、一个活跃上联和一个 ns-3 seed；不外推到 1,856 节点长尾拓扑的活跃端口比例或总通信成本。`STATE` 反馈与心跳在本轮分账且前者关闭；此前的[长尾 STATE 更新间隔报告](ws21-compact-longtail-interval-report.md)不能与本表合并成同一个“最优间隔”。

下一步先用短故障窗验证单份丢失不误报，再定向覆盖 ACK 身份、会话重启和链路状态；之后在固定长尾输入上量出实际活跃端口数和 `STATE+HELLO/ACK` 联合通信。若要讨论负载均衡收益，仍须让候选状态真实进入选路，记录 `adopted/fallback` 与候选区分，并在独立需求上设同输入双侧对照；在这些门槛通过前，WS-21 效果矩阵保持 **NO-GO**。
