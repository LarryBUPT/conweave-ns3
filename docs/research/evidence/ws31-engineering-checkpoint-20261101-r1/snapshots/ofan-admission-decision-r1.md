# 新增基线决定：实现 Ofan v2 算法移植

日期：2026 年 11 月 1 日。主已接受唯一副的准入评估，独立核对 23 份本地输入哈希、6 份固定源码哈希及片段，并重读 Gemma 机制原文和 Ofan v2 第 7 节。收据见 `evidence/baseline-admission-main-acceptance-r1.json`。

保留 ECMP、DRILL、CONGA、LetFlow、ConWeave 和 QueuePin。优先新增 Ofan v2 的选路算法移植，正确性通过后才进入正式效果表；不声称复现作者实验结果。Gemma 暂缓原名完整实现，HULA、SeqBalance 和 REPS 暂不扩入本轮集合。

## 1. 必要性与成本

Ofan 增加按目的地合并状态的逐包轮转，补充 QueuePin 的路径保持和 DRILL 的局部队列决策。选路不需要新增接收协议，但必须保留共同 DCQCN／IRN 的乱序恢复成本。依据固定 [arXiv:2507.21372v2，第 7 节](https://arxiv.org/html/2507.21372v2#S7)实现，不混入后稿 pOfan 或理想恢复条件。

Gemma 的新增成本集中在下游反馈、逐包改路及接收侧 phase/END 排序：需要有限队列、严格排空、重复／丢失 END 处理、独立暂停原因与 MMU 计费。现有八优先级和 ConWeave FIFO 不能直接替代这套契约。暂缓依据是当前比较的必要性及实现忠实性，不是用“没有找到源码”推断论文不可复现。具体比较见副目录 `baseline-admission-r1.md`。

## 2. Ofan 初始实现边界

只实现静态等价路径拓扑的算法。每个目的必经交换机和包长组维护独立轮转指针，以固定 seed 生成随机初始位置与遍历排列；每包推进，不按 QP 固定。按共同报文的实际线速长度使用两个固定包长组，初始分界为 128 B；这是适配当前模型的公开工程取值，论文未指定这一模型的分界。

数据及端到端 ACK/NACK 都进入调度，各按实际包长分组。链路本地 PFC 不参与；其他控制包保持公共路径。不会给 Ofan 提供理想恢复、额外接收器或全局未来信息。

目的地分组必须从实际最短路径图求得。对同一目的地，将所有可达最短路径的必经节点求交，取分叉后的首个必经交换机。源 ToR 应得到目的 ToR，aggregation 应得到与目的 ToR 相邻的必经 aggregation；同组可达出口集合必须一致。任何不满足条件的拓扑拒绝以该版本运行，不用交换机 ID 除法猜分组。

已用独立 Python 图检查核对四份实际拓扑：128 主机脊叶、fat-k4、fat-k8、1,280 主机拓扑。分组与集合兼容性检查均无错误，证据在 `evidence/ofan-topology-grouping-r1.json`。这是静态图证据，尚不代表运行时初始化和逐包动态验收通过。
