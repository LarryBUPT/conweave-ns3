CCB 仅检查评审给出的一个值：在记录的线速队列字节域中，以 8,192 B 为比较差值。未扫描其他值，未把该值选为正式参数或成功门槛。真正改变动作的条件是类别 2、候选不同，且 `0 < Q1−Q2 ≤ 8192`。因此，类别 2 的 23 次“队列接近”中，只有 9 次实际改变原选择；平局和第二候选本来更差时不算改变。

CCPB 只在类别 2 严格平局时比较计数：同一源交换机内，第二候选此前分到的同类请求数更少才改选。5 次符合条件的平局中有 3 次存在这样的计数差异。

这里数的是旧轨迹中此前所有源首次分配，不是活跃 QP 数，也没有按完成删除。它是一个明确的历史分配计数口径，不能被解释为当前未完成负载。若后续主张必须依赖活跃计数，还要设计完成通知、原类别归属及清理语义。
