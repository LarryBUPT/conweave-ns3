# WS-31 端点生命周期与证据核心契约

日期：2026 年 11 月 1 日。状态：可移植核心已固定并推送，尚未编译；真实 NS-3 接线及网络正反例待实现。

## 1. 作用和边界

固定源码为 `20bc2d9f7c7c435bf832ba2fcaf0e07df00cf5da`，父源为已验默认兼容的 1f。差异仅有端点账本头文件和独立核心测试两个新增文件。它们未在 Waf 注册，也未被现有 NS-3 运行路径包含；1f 的默认兼容验收不能转移为新端点能力证明。

本版承接[独立静态审查](../independent/endpoint-ledger-local-review-r1-report.md)及[主验收](evidence/endpoint-ledger-local-review-main-acceptance-r1.json)。原 WIP、审查报告和旧设计原字节保留。后续工程范围见[快照接口表](endpoint-snapshot-interface-audit-r1.md)，本版的完成位策略覆盖该表此前允许清空组的草案建议。

## 2. 身份、资源和状态

每条请求保留完整 `(sip, dip, sport, dport, pg)`、唯一 flow_id、generation、原业务标签、字节数，以及 demand／launch／finish 时刻。状态依次为：

`CREATED → ACTIVE → ACK_COMPLETE → ENDPOINTS_RETIRED → DRAINED → SWITCH_CLEARED`

不同完整 tuple 可能共享实际 TX／RX packed key；C1／C3 的交换机域又不含 pg。新核心单独登记源节点与 TX 键、目的节点与 RX 键及四元组的所有者。本最小夹具永久拒绝跨 tuple 的资源别名，包括旧代已清理的情况，避免借用另一身份的排空证书。实际适配器仍须直接调用生产键函数并核完整对象身份；可移植测试中的键表达式只是固定源的镜像。

同 tuple 只允许 generation 加一。新需求须在旧代清理后登记；当前完成型夹具不接需求先到、清理后才放行的排队模型，也不提供取消终态。若后续扩展，须分别保存原需求与准入时刻，不改变原需求计时。

## 3. 快照和最终复用门

每次快照必须绑定旧代 flow_id、tuple、generation 和当前观察时刻，并标明八类字段已观察。包括映射、QP 事件、设备事件、保留 QP、队列、串行化、完成历史和交换机状态。该标记只是调用方履约声明，实际测量仍由适配器与原日志证明。

映射退出和 QP 事件退役构成 Retired 条件；Quiet 另要求设备事件、待发送载荷、物理数据队列、ACK 队列和串行化都为空，保留 QP 全部累计确认完成。Reusable 再要求两侧完成历史已按协议处理，固定路径、预算和配额条目均为空。

合法但返回 false 的观察也推进证据时钟。身份错配、字段缺失和时刻过期的快照抛出异常，不伪造观察结果。最终 Begin 必须在创建同一事件内提供新的旧代 Reusable 快照，不能仅凭历史状态枚举再次创建。实际适配器必须在该事件中先重新核真实映射、对象、事件、队列及所有权，再执行 AddQueuePair。

## 4. 传输凭据

每次发送使用独立 serial，链路身份为源节点／源接口／目的节点／目的接口。同 UID、同链路的多次发送与 held copy 均独立记账。闭合时校验全部身份、token 类别及原因：channel 仅接受 Receive 返回，held copy 仅接受明确丢弃。

held copy 当前是未入网的测试副本；丢弃闭合不能称作旧包实际到达后的原生接收隔离。后续若送入网络，须另建明确的持有转交协议。本版不把 channel 与 held 的 serial 混用。

## 5. 真实适配器接线要求

生产队列组 `Clear()` 只清向量，不清 finished 位。最小夹具将保留已完成旧 QP 并追加新 QP，记录旧对象、原 finished 位和只读累计确认结果；不 Clear 后复用索引，也不改写基线键或调度器。真实正例仍须覆盖旧完成位已置位，以及第二代真实发送、完成的分支。核心测试不覆盖生产位图。

`QpComplete` 在完成回调后才删除 TX 映射。回调只能标记 ACK_COMPLETE，保存即将退出的 TX／RX 对象；退役和排空检查须等待外层 Receive 返回及对应 token 闭合。只读快照不调用会写 finished 位或暂停统计的调度器，不出队、取消事件或清表。

对旧设计作一项事实修正：ACK／NACK 构造只在输入包存在 `FlowIDNUMTag` 时复制，不能写成无条件复制。夹具必须在应追踪数据／反馈的观测入口验证身份标签；缺失或未知归属时拒绝认证。PFC 等共享控制流量另按设备和事件范围检查。

最小网络范围冻结为无背景、旧 lifecycle／composition／动态标签 profile 为 0。全部相关端口、回向 ACK、当前发送器、pacing／resume 事件和保留对象均须观察。实际历史处理与交换机清理须保留前后原始收据，操作与观察分开。

## 6. 本轮核心预检与后继验收

[核心预检](endpoint-ledger-core-preflight-r2.json)仅允许唯一副先独立审源，再经新资源、进程和 ID 门进行一次独立 g++ 编译、一次新核心运行。使用 C++11 和 `-DNDEBUG`；测试通过运行时异常检查，不依赖标准 assert。没有全量 NS-3 构建、旧核心重跑或网络授权。

测试包含两代完整账本状态、实际键别名、同 UID 多凭据、错误闭合来源、快照身份／时刻／字段缺失、非零设备与队列、RX 复活、历史／交换机残留和最终复用重查。手工快照数量不能作为真实端点测量数。

后继仍须实现真实快照、默认关闭的链路接收包装、实际上下文 G1 和网络正例／拒绝例；然后另冻源码、输入、ID 和资源门。独立 C1 V0、三候选业务批次与背景尾部、状态及运行成本继续必做。
