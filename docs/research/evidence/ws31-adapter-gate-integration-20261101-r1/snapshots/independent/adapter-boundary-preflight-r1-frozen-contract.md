# WS-31 适配器生命周期验证契约

日期：2026 年 11 月 1 日。状态：设计已落盘，C2 事件边界部分实现且未编译；尚未形成新冻结源码或远端执行许可。

## 1. 目标和依据

按 C1 → C2 → C3 顺序补齐[标签与生命周期契约](label-lifecycle-boundary-contract-r3.md)中的适配器边界。已有核心测试及 41 格技术网络主验均保留原身份；本契约不通过重复已验输入增加覆盖数。动态标签结果见[第十一节点](label-dynamic-node11-handoff.md)。

当前固定源码为 `1ec5eedc24cd863a289b7493e8b3865c70592ab5`。`ResetWs30V13Tuple` 确实清理 C1 路由、预算和 C3 条目，但旧日志的 `erased` 仅计旧基线表。不得用该字段证明新表清空。C1 读取实际 `QbbNetDevice` 的 `BEgressQueue`，夹具必须安装真实设备和队列。

## 2. C1：真实适配器与预算边界

新增专用 scratch 程序，以窄友元探针调用真实 `DoLbWs31C1` 并读取状态。包须由实际 PPP、IPv4、UDP 和序号头构造，再经 `CustomHeader` 解析；使用实际端口队列，不替换负载函数。探针只能配置空账本的容量及区间上限、调用生产入口和读取状态，不能重写预算算法。

逐事件保留包 uid、四元组、时间、序号、载荷、标签存在性、实际固定端口、预算与守恒快照。检查重复包不二次扣减，空洞与部分重叠只扣唯一字节，到期边界后迟到不重建预算。容量不足、区间超限和 32 位序号跨界必须撤销或拒绝预测，同时保持原固定路径。最后调用真实清理入口，检查三张相关表，再用同四元组的新首包确认允许重新准入。

这些动作属于适配器测试，不能单独证明真实端点退出和旧包排空。

## 3. C2：同刻事件与取消账

在 `RdmaClient::StartRequest` 完成生产计时和计数后，提取一个受保护的虚拟 `DispatchRequest(demandStartNs)`，其默认实现保留现有取得 `RdmaDriver` 并调用 `AddQueuePair` 的原参数及顺序。专用测试子类仅替换传输交付，记录实际调用时刻和需求原点；不替换 `StartApplication`、等待计算、`StartRequest` 或取消逻辑。窄友元探针仅负责调用私有生产入口和读取待放行事件身份。

Stop 和 Dispose 各测以下五种情况，共 10 例：放行前 1 ns、同刻且控制 event uid 较小、同刻且控制 event uid 较大、放行后 1 ns、零等待同步放行后的控制。等待值来自冻结哈希，先选定一个大于 1 ns 的四元组；零等待使用已知非等待类别。必须输出真实 Launch 和控制事件的 uid，并核对同刻两种大小关系确实发生。

每例检查请求与字节账：`demanded = launched + cancelled`、`demandBytes = launchBytes + cancelBytes`，无待放行和重复交付。取消例不调用传输；已放行例保留一次交付，控制操作不增加取消。重复 Stop／Dispose 和最终清理不二次计数。替身不产生真实完成，`finished` 和 `finishBytes` 必须为 0，不通过模拟完成来补账。

夹具限定标签 profile 0 和旧标签变换 0，拒绝继承的非零干预。该层验证生产事件与取消行为；真实 QP 创建、传输完成和 Stop 后的 QP 行为继续由端点验证承担。现有 Stop 不终止已创建 QP，此次不改变其语义。

## 4. C3：活动、残留与显式清理

以同类薄探针调用真实 `DoLbWs31C3`，使用实际设备和队列。先建立跨类别借用，再激活归属类别，记录逐包残留；改变后续标签不得改变首次缓存类别或路径。分别在 20,000 ns 前、恰好到期及到期后到达，核对活动状态和迟到续期，确认空闲只退活动租约、不删固定路由。真实清理后条目、租约及借用账守恒，同四元组新首包可重新按新标签准入。

探针读取缓存、租约和计数，不把专属首次事件与通用 CHOICE 混为相同日志模式。清理不能重置全局观察计数来掩盖两代动作。

## 5. 端点退出、排空与同四元组复用

专用端点阶段另冻实现和最小新网络计划。每个候选依次证明：第一代真实 QP 完成；发送端与接收端相关状态退出；旧数据、ACK／NACK、重传和相关事件已排空；交换机显式清理；同四元组第二代真实 QP 创建并完成。每步都有生产状态来源和时间收据，不能用固定等待时长替代排空判断。

跨代使用独立 flow_id 和显式 generation 观测账。当前标签夹具的 `generation=0` 不复用为跨代证据。需要固定的旧代延迟包反例来检查错误复用顺序能被拒绝；此反例属于测试控制，不改变候选策略。不恢复旧 WS-30 生命周期控制器。

若实际 RDMA 模型缺少可核查的端点清理或排空条件，先记录具体源码缺口并修复观察／生命周期接口，再冻结网络计划；不能将交换机清表测试升级为端点生命周期完成。

## 6. 验证顺序与停止条件

先实现并审查最小差异，保留固定 SHA、生产接口前后映射和夹具逐例预期。唯一副完成本地源审查；随后另冻一个工程预检 ID，完整构建和运行新增适配器夹具。旧核心和已验网络不重复。C2 默认调用路径有生产代码提取，仍需新源默认关闭回归，具体格数按实际差异冻结。

工程通过后，再完成端点契约、独立输入、ID、资源门和网络执行许可。任一身份、事件顺序、计时、预算、路径、端点清理或排空失败均停止后继步骤，保留失败源和 raw，新修复使用新 SHA／ID。不改变成功阈值。
