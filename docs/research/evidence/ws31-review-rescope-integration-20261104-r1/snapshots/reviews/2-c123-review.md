## 2. 多维度评审（第二步）

### 2.1 研究问题与共同框架

**问题本身真实、可测量、且是 QueuePin 主线的自然延伸。** QueuePin 稿件的核心命题是"首包读一次队列值多少钱"（类别无关）；WS-31 问的是同一操作点上"类别能否提供队列之外的信息"，三点分别对应信息（C1）、时机（C2）、准入集合（C3）。问题有明确的证伪条件（research-questions.md 的 RQ1–RQ5），不是不可证伪的框架。

**类别—大小混杂：在当前输入上不可识别，这是全项目最硬的方法论约束。** 三个候选的大小克隆控制均已实测与主模式完全等价：C1（94 次非零压力／2,239,360 B／峰值 58，`c1-controls-node6-handoff.md` L22）、C2（80 次正等待／18,002 ns／497 ns，`c23-controls-node7-handoff.md` L20）、C3（80 次限制／4 次借用／546 残留包／572,208 B，同文件 L22）。这是"类别可由大小重建"的直接实验证据，比推理更强。因此：
- 在当前双尺寸输入上可检验的只有"类别或大小先验相对 QueuePin 的价值"，**不可检验"业务语义超出大小"**；
- 解耦输入族（同尺寸异类别、同类别异尺寸）是任何类别主张的前置条件，必须先行冻结——这是我对被审文档 §9.1 顺序的最重要修改。

**源侧首包操作点是否存在收益空间：三层证据给出"有机会、没证明"。**
- 有机会：V0 技术重放中 92 对不同候选、83 对真实后续量不等、7 对双空队列（`v0-technical-replay-r1.json` L11–L15）；旧日志中 30 次双空队列里有 10 次存在"此后仍有已知 QP 包到达"（`c1-information-contract.md` L70–L72）。
- 机会稀疏：决定时队列通常不为空（双空仅 7/92），意味着"队列已经讲了一部分故事"，类别增量是残差。
- 改动作没改时间的反例已两次出现：WS-30 组成夹具（背景字节换向改变探针出口，探针 FCT 全部 25.665 μs、批次全部 45.665 μs，`failure-evidence-audit-r1.md` L106）；WS-26 v3（diverted 6,719–6,925 次首包选择，双主无稳定增量）。另 WS-28 三例批尾的最长单跳等待在 6,179–6,905 ns 且只有 1/3 新批尾在源 ToR 选了第二候选（`failure-evidence-audit-r1.md` L91）——批尾等待位置不在首跳的可能性必须量化。
- 结论：**首跳操作点的收益空间未被排除、也未被证明**；"按跳瓶颈分解＋固定分配下的 oracle 收益上界"应作为所有候选的共同前置门（见 §3），这一步比任何单一候选的机制深化都便宜，且能同时回答"空间是否大于零"。

## 3. 建议的后续方向（第三步）

### 3.1 组织原则：先廉价否决、后冻结效果矩阵

**两条铁律：**
1. **廉价否决优先**：任何候选在消耗一次新仿真之前，必须先通过可重放计算完成的否决门（机会计数、oracle 上界、瓶颈分解、残留时效）。43 格技术格的历史成本结构（每个阶段 5–10 格、每格独立构建约 6 分钟＋仿真）意味着"先跑效果再看"是最贵的路径；而可重放计算全部可以用零控制四格已验收的 raw 起步。
2. **共同前置门**：把"按跳瓶颈分解＋固定分配下的 oracle 收益上界"设为**所有候选共享**的前置门，任何候选不得绕过。理由：三类候选都只改变源侧首包行为（C1 改评分、C2 改时机、C3 改集合），若首跳在固定 QP 分配下没有可分走的收益空间，三个假设同时死亡——这是比逐候选 V0 更先验、更便宜、且对全部候选同权的裁决。

### 3.2 共同前置门的具体设计（构思，未实现）

**G1 · 按跳瓶颈分解（只读，零新仿真）。** 复用 WS-28 已揭盲反例的方法（`failure-evidence-audit-r1.md` L91 的三例逐跳最长等待），对零控制 q12 格的 606,168 条路径事件做全量分解：每条 QP 的逐跳最大等待与批尾组成，统计"批尾等待集中在源 ToR 队列／脊上联／目的 ToR／末跳"的占比。产出：`hop-attribution.json`。判定：若批尾等待在源 ToR 可绕行上联的占比低于预设阈值（建议冻结值：<20%），首跳机制的理论空间过窄，三类候选共同降级为测量研究。

**G2 · 固定分配下的 oracle 收益上界（1 次新仿真＋零控制 raw 重放）。** 定义：固定 QueuePin 的候选对与路径保持契约，只允许首包决定用未来真值反事实重选（显式离线 oracle，不进入在线决策）：对 104 请求技术输入的每个源首包决定，用 V0 重放已算出的真实后续量排序（`v0-technical-replay-r1.csv` 的 true1/true2）替代队列比较，生成一个"oracle-后续量"臂；再跑一次该臂的完整仿真（1 次新运行，固定同一 SHA/输入/seed），得到 oracle 下的批次与背景 P99。产出：`oracle-bound-r1.json`。判定：若 oracle 相对 QueuePin 的双主改善低于预设阈值（建议沿用项目历史成功线思想、先冻结为批次 ≤−3% 且背景 P99 ≤+3%），则**任何仅凭首包信息的在线机制都不可能达标**——三类候选全部停止效果矩阵，转向测量型负结果；若 oracle 有空间但幅度很小（如批次 −3%～−5%），效果矩阵的样本量/门槛须按此上界校准。该 oracle 显式使用未来信息，只作上界，身份单列（`proposal.md` L25 已允许"离线 oracle 上界须单列身份"）。

**G3 · 解耦输入族冻结（P0）。** 三份确定性生成输入，SHA 冻结、与 G1/G2 同源生成器：
- D0：现有 104 请求双尺寸输入（已冻结，`d45a80a2…`）；

判定：D1 上类别臂与大小克隆臂若逐条等价（预期如此，因为尺寸相同），类别模板的"语义"成分被隔离；D2/D2' 上大小克隆与类别臂应逐条等价（大小绑定下必然），用于验证生成器与口径。

### 4.2 机制 M1：类别条件比较死区（Class-Conditional Comparison Deadband，CCB）

**身份与状态声明**：研究构思。未实现、未运行、无任何性能数据。编号 `ws31-m1`（建议模式编号 53 起，沿现有 36–50 序列之后）。本设计只承诺"规则可证伪、否决最便宜"，不承诺收益。

**研究假设与立项依据**：
- 历史事实：类别加权（F5：C16/Q16 同步批次 +0.058%、背景 P99 +0.059%，区间跨零）与固定分割（ClassLane v4 批次中位 +20.851%、0/4）均失败；组成夹具证明"改变选择可以不改变任何完成时间"（F7，探针 25.665 μs、批次 45.665 μs 全同）。
- 待检验机制假设：MoE 首包决定的队列读数大量落在"空或微小"区（V0 技术重放：92 对不同候选中仅 7 对双空；旧日志 30 次双空中 10 次后续有包），微小差异由少数在途包造成、对 8 KiB 请求的竞争前景几乎没有预测力；对这些差异采取行动只会引入噪声。**类别在这里不是评分项，而是"对队列差异采信的最低幅度"**：MoE 只对超过 ε₂ 的差异行动，背景保持全敏感。
- 立项依据编号：F5、F7、H1（`failure-lessons.md` L12–L15、L32）。

**在线可见信息表**：

| 信息 | 用途 | 禁止项与时间纪律 |
| --- | --- | --- |
| 四元组、候选对（12 B 键双哈希） | 网络信息：两个固定候选端口 | 不改变候选生成；重合时退化为单出口 |
| Q(p1)、Q(p2)（`CalculateInterfaceLoad`，队列字节） | 队列长度：比较对象 | 只读决定时刻当前值；同一纳秒保持事件顺序 |
| 策略标签 c（trace→QP→`WorkloadTag`） | 类别：选择死区宽度 ε_c | 未知/缺失→ε_u；未来到达、精确总大小、批尾身份一律不得进入决定 |
| ε_c（每类常量） | 工程初值：ε₂=8,192 B（一条 MoE 请求载荷）、ε₁=0 B、ε_u=0 B | 待冻结；禁止从效果数据校准 |

**伪代码规则**（单位：队列字节；平局：死区内保留第一候选；边界：|δ|=ε 属于死区；回退：未知类别 ε=0 → 与 QueuePin 逐字节一致）：

```text
On source-ToR first packet of new QP with class c (only fresh keys):
    q1 = CurrentQueue(p1); q2 = CurrentQueue(p2)
    e  = eps[c]                       # eps[1]=0, eps[2]=8192, else 0
    if q2 + e < q1:  chosen = p2      # 第二候选严格更短（超出死区）
    else:            chosen = p1      # 死区/平局/第一候选严格更短 → 保留 p1
    cache chosen; 后续包沿缓存出口（QP 路径保持）
```

**最小状态机 S0–S3**：

| 状态 | 出口缓存 | 死区状态 | 允许动作 |
| --- | --- | --- | --- |
| S0 新键 | 无 | 读取 ε_c | 首包按死区规则选择；缓存出口 |
| S1 已选择 | 保持 | 不变 | 后续包直接转发（零额外逐包操作） |
| S2 生命周期清理 | 随 QueuePin 路径表清理 | ε_c 是常量，无状态 | tuple 复用后新实例回 S0 |
| S3 退化 | 沿 QueuePin | ε=0 | 类别未知/缺失/控制关闭时与 QueuePin 逐字节一致 |

**状态与成本**：软件状态＝3 个每类常量（ε₁、ε₂、ε_u），0 条目、0 表。首包操作＝1 次减法＋1 次比较（相对 QueuePin 的增量）；逐包操作＝0（相对 QueuePin 无增量）。无新增网络反馈。硬件成本不评估（表项/查表时延/线速/头部开销均不属本设计范围）。

**可发表价值与收缩路径**：若死区在 D1 上改善 MoE 批次且不伤背景——"固定 QP 首包分配中类别条件比较灵敏度的价值"，属机制深化/边界贡献，配平局匹配与随机平局两对照后可与 QueuePin 稿件 W1 形成姊妹结论；若类别臂=统一臂（D1）——收缩为"类别无关死区"测量（仍有价值：回答"首包队列信息的噪声带"）；若大小克隆复制（D2）——收缩为大小先验工程利用；若全部负——V0 即停，零成本负结果。

**最便宜的否决实验**：V0 重放（0 次新仿真）。命中数=0 或方向无信息 → 停止。此实验在 §3 的 S0 阶段内完成。

**尚未成立的主张**：死区有信息、死区改善双主、类别条件优于统一死区、ε₂=8,192 B 合理——均未成立。ε₂=8,192 B 只是"一条 MoE 请求载荷"的工程初值，不是校准值。

### 4.3 机制 M2：类别条件队列时间尺度（Class-Conditional Queue Timescale，CQT）

**身份与状态声明**：研究构思。未实现、未运行、无任何性能数据。编号 `ws31-m2`。与 M1 正交、不堆叠；与 C2 的动作点不同（C2 改源端启动时机，M2 改交换机比较信号的时间尺度）。

**研究假设与立项依据**：
- 历史事实：H1"瞬时类别字节与总队列高度重叠，首包时刻的新增信息有限"（`failure-lessons.md` L32）；C16/Q16 的类别加权在瞬时队列上未产生稳定增量（F5）；WS-28 三例批尾的入队前背景字节达 97,464–167,680 B（`failure-evidence-audit-r1.md` L91），说明背景压力是持久量。
- 待检验机制假设：背景 QP 的路径选择应基于**持久压力**（时间平滑信号）而非瞬时值——瞬时值被背景自身脉冲主导，噪声大；MoE 的竞争是"现在"，应保留瞬时比较。**类别选择"比较哪个时间尺度的队列信号"**，不是加权：对 tag 1 比较指数衰减平滑字节 S(p)，对 tag 2 比较瞬时 Q(p)。
- 立项依据编号：F5、H1；观察依据：`failure-evidence-audit-r1.md` L91。

**在线可见信息表**：

| 信息 | 用途 | 禁止项与时间纪律 |
| --- | --- | --- |
| 四元组、候选对 | 网络信息：两个固定候选端口 | 不改变候选生成 |
| Q(p)（瞬时队列字节） | tag 2/未知的比较信号 | 只读决定时刻当前值 |
| S(p)（每端口指数衰减平滑字节） | tag 1 的比较信号 | 每包因果更新：S ← S·(1−Δt/τ) + wire_bytes（Δt≥τ 时清零重计）；只用该包到达前的信息 |
| 策略标签 c | 选择信号（Q 或 S） | 未知/缺失 → Q（与 QueuePin 一致） |
| τ（时间常数） | 工程初值：τ=20,000 ns（与既有 20 μs 活动窗口同量级） | 待冻结；禁止从效果数据校准；Δt<0 不可能（同纳秒保序） |

**伪代码规则**（单位：队列/平滑字节均为线速字节；平局：保留第一候选；边界：Δt≥τ 时 S 重置为该包字节；回退：未知类别用 Q）：

```text
每包到达（任何端口 p，含非首包）：
    dt = now - lastUpdate[p];  lastUpdate[p] = now
    S[p] = (dt < tau) ? S[p] * (1 - dt/tau) + wireBytes(packet) : wireBytes(packet)

源 ToR 首包决定（新 QP，类别 c）：
    v1 = (c==1) ? S[p1] : Q[p1]     # tag1 用平滑信号，tag2/未知用瞬时队列
    v2 = (c==1) ? S[p2] : Q[p2]
    chosen = (v2 < v1) ? p2 : p1    # 严格小于；平局保留 p1
    cache chosen; 后续包沿缓存出口
```

**最小状态机 S0–S3**：

| 状态 | 出口缓存 | 平滑状态 | 允许动作 |
| --- | --- | --- | --- |
| S0 新键 | 无 | S 已随历史包更新 | 首包按类别选信号比较；缓存出口 |
| S1 已选择 | 保持 | 每包更新 S | 转发；S 更新不计入决策 |
| S2 清理 | 随 QueuePin 路径表清理 | S 是端口级状态，不随 QP 清理 | tuple 复用后新实例回 S0 |
| S3 退化 | 沿 QueuePin | τ=0 或控制关闭 | 与 QueuePin 逐字节一致 |

**状态与成本**：软件状态＝每交换机每出口 2 个字段（S、lastUpdate），8 上联×2×8 B 量级；0 逐键条目、0 预测表。逐包操作＝1 次乘加（平滑更新，仅该包所在端口）；首包操作＝1 次信号选择＋1 次比较。平滑用线性衰减近似（`1−dt/τ`），无指数函数。硬件成本不评估。

| 维度 | M1 CCB（死区） | M2 CQT（时间尺度） |

| 主要受益方 | MoE（对小差异钝化、少被噪声驱动） | 背景（对持久压力敏感、少被瞬时脉冲驱动） |

### 4.5 机制 M3：类别条件钉扎均衡（Class-Conditional Pinned Balance，CCPB）——独立于 C1/C2/C3 与 M1/M2 的完整机制

> 本节为后续补充（2026-11-04，应"独立于 C123、继承 QueuePin、依据仓库证据推导完整创新机制"的要求追加）。M1/M2 的定位是"最廉价否决器"（单杠杆、V0 零仿真可否决）；M3 的性质不同：它从已核验证据链推导出一个此前五个候选都未触及的合法杠杆——**交换机自己的路径钉扎表**。

**身份与状态声明**：研究构思。未实现、未运行、无任何性能数据。编号 `ws31-m3`，双臂：模式 53（平局臂，D=0）／模式 54（批量臂，D>0）。

**推导链与研究假设（立项依据全部引用可复核编号）**：
1. F7 组成夹具（`failure-evidence-audit-r1.md` L106）：等总量 FIFO 下背景换向不改 FCT → 队列总量相等时首包决定没有队列信息 → **平局域是首包队列信息的结构性盲区**；
2. QueuePin 稿件 v14 P0（`E:\研\毕业论文\thesis\ws30-paper-v14-supervisor-current-handoff.md` L13）：首次选择 1,815,468 次中双出口平局 9.66%、哈希重合 4.90%、单下一跳 60.96%——平局域在正式输入族中不是零测集；且稿件 W1 的 +5.46% 归因正是因平局处理撤回；
3. F5/H1（`failure-lessons.md` L12–L15、L32）：在 Q 有差异处加类别权重已两次无稳定增量 → 新机制不竞争"Q 有差异"域，而完成"Q 无差异"域；
4. 杠杆盘点：C1 占预测项、C2 占启动时机、C3 占候选集合、M1 占灵敏度带、M2 占信号时间尺度；唯一未被使用且交换机已持有的合法状态＝路径钉扎表（QueuePin 的 `m_ws31Pairs`）按类别分解的钉扎计数；
5. **假设**：QP 钉扎下，同类突发波在波起点队列为空/相等，QueuePin 退化为"每波都平局保 p1"，造成**跨波持续极化**（每波压到同一上联）；用"本交换机已钉扎的同类别 QP 数"作为平局与批量决策的词典序次关键字，可在不迁移任何 QP、不读未来、不加权重的前提下实现跨波均衡。类别不是评分项，而是**选择次关键字所统计的钉扎子群体**。

**在线可见信息表**：

| 信息 | 用途 | 禁止项与时间纪律 |
| --- | --- | --- |
| 四元组、候选对（12 B 双哈希） | 网络信息：两个固定候选端口 | 不改变候选；重合（p1==p2）时无次键 |
| Q(p1)、Q(p2) | 队列长度：词典序主键，严格小于 | 只读决定时点当前值；同纳秒保序 |
| 策略标签 c | 类别：决定次键统计的钉扎子群体（P_c）及是否启用平局修正（仅 tag 2 启用；tag 1/未知即时 QueuePin） | 未来到达、批尾身份、精确总大小不得进入 |
| P_c(p)＝路径表中已钉扎到端口 p 的类别 c QP 数 | 钉扎状态：词典序次键 | 只读事件时点以前已钉扎状态；随路径表清理递减 |
| D_c（批量窗口） | 工程初值：D₂=500 ns、D₁=0、D_u=0；pending 上限 1,024 | 待冻结；禁止从效果数据校准 |

**伪代码规则**（单位：Q 为队列字节，P_c 为 QP 条数，D 为 ns；平局：主键 Q 严格小于→次键 P_c 严格小于→仍相等保留第一候选；边界：候选重合无次键、pending 满则立即按平局臂处理；回退：tag 1/未知、机制关闭、D=0 且 Q 不等时与 QueuePin 逐字节一致）：

```text
源 ToR 首包（新 QP，类别 c）：
    if c != 2: return QueuePin(键)                      # 背景/未知即时 QueuePin
    if D2 == 0:                                         # 平局臂（模式 53）
        q1=Q(p1); q2=Q(p2)
        if   q2 < q1: chosen = p2
        elif q1 < q2: chosen = p1
        else:         chosen = (P2(p2) < P2(p1)) ? p2 : p1   # 钉扎次键；再平局保 p1
        Pin(k, chosen); P2(chosen) += 1
    else:                                              # 批量臂（模式 54）
        将 (k, p1, p2, 时刻) 放入本交换机 pending（上限 1,024；溢出→立即走平局臂）
        安排 epoch = 到达时刻 + D2
    批量 epoch（按到达顺序处理全部 pending）：
        q1=Q(p1); q2=Q(p2)                             # 同批包读同一时点队列
        (q2<q1)→p2; (q1<q2)→p1; 否则 P2 少者；再平局保 p1
        逐个 Pin 并转发；P2(chosen) += 1
后续包：沿缓存出口转发（QP 路径保持，零额外逐包操作）
清理：路径表清理时 P_c 同步递减；QP Stop/Dispose 时取消其 pending 条目（取消数/字节单列）
```

**最小状态机 S0–S3**：

| 状态 | 出口缓存 | 钉扎计数/pending | 允许动作 |
| --- | --- | --- | --- |
| S0 新键 | 无 | P_c 随既有钉扎 | tag 2 首包按（Q, P₂）词典序决定或入 pending；tag 1/未知即时 QueuePin |
| S1 已钉扎 | 保持 | 钉扎时 +1 | 后续包只转发；P_c 不随逐包变化 |
| S2 清理 | 随 QueuePin 路径表清理 | 清理时 −1；pending 随 QP 取消 | 复用后新实例回 S0 |
| S3 退化 | 沿 QueuePin | 次键关闭 | 与 QueuePin 逐字节一致 |

**状态与成本**：每端口×每类别计数（8 上联×3 类×8 B）＋pending 队列（上限 1,024 条，每条四元组＋候选＋时刻约 24 B）＋每交换机一个批量计时器。首包操作：＋1 次比较、＋1 次计数读、钉扎时＋1 次计数写；逐包操作：0；批量臂每批＋N 次比较。无新网络反馈；不建立逐 QP 预测表（P_c 是聚合计数，路径表是 QueuePin 既有状态）。硬件成本不评估。
