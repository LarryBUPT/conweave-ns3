# C2 决策标签接口修订

日期：2026 年 11 月 1 日。状态：源码已提交并推送，实际验证待完成。

## 1. 问题与修改

固定 c4 中，`WS30_TAG_TRANSFORM` 只在发包阶段移除或交换包标签，启动等待仍读取应用原始标签。此前没有执行或验收错误的标签干预格；已验收零控制及在途动态目标均关闭该开关。来源见[原接口审计](evidence/c2-tag-intervention-source-gap-r1.json)。

修订 `50603927fc09a68d9f2e038129aaee3a3d021081` 在 `RdmaClient::StartApplication` 调用 `StartPolicyTag`，使相同开关作用于启动资格：移除映射为 0，交换仅作用于 1 和 2，其他值保持原标签。原业务标签仍传给 QP，需求日志追加策略标签和变换值。统一、大小及零等待模式继续使用各自原资格规则。

## 2. 已完成核对

主核对九项静态条件，包括哈希／偏移／计数实现及放行／取消路径未改、原业务标签仍进入 QP、头文件已导出、改动仅限三个预定文件、运行入口未改、提交已推送且实现克隆干净。[收据](evidence/c2-policy-tag-source-fix-r1.json)保存固定源码对象哈希。可移植测试已补充移除、交换、未知标签及统一／大小／零等待控制的断言，但本机没有 C++ 编译器，本轮未执行该测试。

默认变换 0 时，策略标签等于原标签，等待计算与放行路径保持原实现；此项目前是源码判断，仍须用实际默认回归确认。

## 3. 验证承接

唯一副继续完成冻结在 c4 的 C1 → C2 → C3 动态技术目标，主独立核对 raw。当前三个隔离源码副本已建立，修订不替换其源码，也不新增并行目标。

当前目标主核后，另行冻结新 SHA 的核心执行、完整构建及 C2 默认／移除／交换网络验证。默认格须与已验 c4 C2 主模式结果比较；移除和交换格按固定四元组重算每个请求的等待，核对原始业务身份、策略标签、需求／放行／完成时刻及字节守恒。未知输入及统一／大小／零等待匹配控制继续保留在完整正确性清单中。具体新 ID、资源门及执行目标尚未派发。

标签接口只支持决策可见干预；候选类别增量、业务批次、背景代价及独立效果仍按后续协议验证。本修订不涉及 Ofan，不建立新组合基线。
