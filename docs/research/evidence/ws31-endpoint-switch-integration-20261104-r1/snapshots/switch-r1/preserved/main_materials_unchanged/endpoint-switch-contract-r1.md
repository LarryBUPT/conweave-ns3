## 2. 交换机读取边界

新增 fixture 专用 Ws31EndpointSwitchProbe，以 setup 捕获的完整 NodeList 为范围，绑定节点、角色、精确 SwitchNode 动态类型和全部接口。至少包含一个实际交换机，拒绝未知角色、缺失范围、节点／接口变化和路由模式改变。当前仅支持 Q12 与 C1／C2／C3 表所属模式 33～50；其他正式对照不由本探针认证，不改变其对照身份。

Read 接收同刻、同请求／tuple／generation 的端点 Observation，要求原覆盖位为 127、交换机计数尚未填写，并核节点范围一致。逐 switch 读取目标四元组的 Q12 pin、WS-31 pin、预算条目和配额条目，再填入 SWITCH_STATE 位。端点 tuple 的 PG 不进入交换机键；跨 PG 的资源别名仍由端点账本准入门拒绝，不另造交换机键。

代码预期输出 mask 255 不表示已经测得完整快照。实际对象纯度夹具和真实网络接线尚未运行；通道 token、held copy、队列、发送器、端点事件、历史和最终复用判据仍分别核验。

## 3. 只读接口与共享状态

BudgetLedger 和 QuotaAdmission 仅增加 const Contains；ObservedMemory 增加 const PortCount；QuotaAdmission 增加复制出的共享活动窗口、seen 和 last。SwitchNode 只增加窄 friend，不新增成员、虚函数或生产 cc 改动。删除新增接口／friend 后，三份原头文件精确恢复父源。

读取不调用 Expire、Pressure、Value、Erase、Reset 或 GetObject。过期但尚未被生产路径清理的条目仍作为实际存在状态报告。目标条目和全表大小、端口共享记忆、配额活动历史、liveBorrowed 分开输出；清理目标 tuple 不等于全交换机或共享状态归零。

本阶段没有新增清理动作。后继在排空条件满足后使用已核定点清理接口时，必须分开记录清理前后的实际目标与共享状态，不为获得证书擦除无关历史。
