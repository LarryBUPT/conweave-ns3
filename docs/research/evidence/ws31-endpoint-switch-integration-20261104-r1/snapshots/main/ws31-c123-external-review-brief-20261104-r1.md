# WS-31：实验背景、C1／C2／C3 方案与后续验证计划

版本：2026 年 11 月 4 日，r1。用途：交由其他模型或研究者独立审阅创新性、方案合理性和改进空间。

本文汇总现有设计、源码与技术验收记录。C1、C2、C3 均已完成首版实现和部分动态验证，独立效果验证尚未完成。文中的“待审改进”是供讨论的方向，没有自动纳入实现或实验计划。

## 1. 希望审阅者回答什么

本研究关注一个具体问题：在 RDMA QP 保持路径的条件下，业务类别还能通过哪些信息或动作改善负载均衡？候选分别作用于首次选路、请求启动和新流准入。

请重点判断以下四项。

1. 每项方案相对最接近工作，是否有明确且有价值的增量？请比较信息、状态、动作、约束和证据，避免只按机制名称判断。
2. 当前方案最可能失败在哪里？哪些问题可由最小修改解决，哪些需要改变研究问题？
3. 哪些对照和实验最能区分“规则生效”“类别有信息”“性能有收益”？
4. 如果只保留一条主线，应保留哪项？另外两项适合作为独立候选、解释性实验，还是负结果？

本项目不以“绝对原创”为门槛。已有相似方法时，允许有意义的改进、约束下的深化或机制边界研究。请同时评估这些贡献形式，给出具体证据和修改建议。

## 2. 实验背景与研究起点

### 2.1 场景、单位和目标

平台是 ConWeave 的 ns-3 数据中心网络模拟器个人 fork。当前研究用混合合成流量表示 MoE 通信与背景传输。MoE 是混合专家模型，但仿真只表示通信需求，不模拟专家计算和完整训练过程。

QP 指 RDMA 队列对，是当前发送与完成统计的重要对象。源 ToR 指主机直接连接的机架顶交换机。三项候选以单个 QP／请求和交换机本地状态为操作单位。

主要技术验证使用 `leaf_spine_128_100G_OS2` 拓扑：128 台主机、8 台叶交换机和 8 台脊交换机。每台叶交换机连接 16 台主机和 8 台脊交换机，接入与上联容量比为 2:1。预置链路均为 100 Gbit/s，传播时延为 1 μs。

主要研究起点中，MoE 请求大小为 8 KiB，背景请求大小为 8 MiB，分别使用业务标签 2 和 1。标签是仿真输入提供的提示，不是已经实现的线上分类器。另有每条请求均为 16 KiB 的标签技术夹具，用于验证错误、缺失和变化行为。

研究目标有两项：降低 MoE 合成通信批次完成时间，同时保护背景流的第 99 百分位流完成时间，即 P99 FCT。批次从原始需求起点计到全部目标流完成。C2 引入的等待必须计入；未完成请求不能从统计中删除。

后续正式协议还须固定背景统计窗口、未完成请求处理和联合成功线。通信批次时间不等于训练迭代时间；当前也没有真实集群性能结果。

### 2.2 共同对照：QueuePin

QueuePin 是本项目已有的类别无关对照。其核心规则如下。

- UDP 数据使用统一的 12 B 四元组键：源／目的 IP 和源／目的端口。
- 两个固定哈希从合法下一跳中产生两个候选，允许候选重合。
- 新键首次选择时比较候选出口的当前总队列；第二候选严格更短才选择它，平局保留第一候选。
- 后续包沿已缓存出口转发，保持该 QP 的路径。

C1 和 C3 的新增动作放在源 ToR；其他跳沿 QueuePin。C2 继续使用 QueuePin 选路，只改变源端启动时机。三项先独立比较，没有将它们堆叠成一个已验证系统。

正式对照保留 DRILL、ConWeave、CONGA、ECMP、LetFlow 和 QueuePin。Ofan 暂缓。新增正式机制须先核实正式发表及 CCF A/B 资格，再评估相关性、必要性、成本和实现忠实性。该准入规则不限制相关工作检索：非 A/B 或预印本中的相似思想仍必须比较。

### 2.3 为什么提出这三项候选

此前类别加权机制可以改变部分首包选择，但匹配对照未识别稳定的时间增量。已有实验还显示，改变出口选择不必然改变批次完成时间。后续跳或目的瓶颈可能主导批尾，额外类别评分也可能重复当前队列已有的信息。

本项目还尝试过两类直接近邻。其一是“当前队列＋近期活跃背景 QP 数的固定字节权重”，已经涉及源 ToR 的活动记忆。其二是固定 2:6 类别路径划分，四个筛选需求的业务批次均变慢。这些结果促使新方案分别追问后续量估计、启动竞争和借用回收，而非再次增加一个类别权重。

当前最重要的识别问题是大小与业务标签绑定。在主要两尺寸输入中，标签可由大小重建。若其他状态转移相同，大小映射控制就可以复制类别模板。因此，机制相对 QueuePin 有用、类别优于统一先验、业务语义超出大小，必须分别证明。

## 3. 共同信息与设计约束

| 项目 | 当前契约 |
| --- | --- |
| 在线可见信息 | 当前请求、已到达包的字段、当前本地队列、此前保存的本地状态，以及明确声明的类别提示 |
| 精确大小 | 模拟器现有统计 PacketTag 携带 QP 总大小；只在命名的大小控制中使用，不能据此认定线上取得成本为零 |
| 时间纪律 | 只使用当前事件以前的信息；同一纳秒内也保持实际事件先后顺序 |
| 离线评价真值 | 可以读取未来实际到达量和最终完成，用于打分；这些信息不进入在线决定 |
| 传输与路径 | 各对照保持共同传输参数；已有 QP 不因新类别或预算变化迁移 |
| 类别错误 | 分开记录原业务身份、策略标签和实际包标签；未知标签有明确回退 |
| 参数来源 | 下文的预算、期限、等待和配额均是已编码工程初值，不是独立校准所得最优值 |
| 证据单位 | 先按独立需求比较；单一需求内的包、路径事件或技术格子不充当独立重复 |

当前一些正确性实验采用 DCQCN 拥塞控制，关闭优先级流控 PFC，开启 IRN 可靠恢复，并固定 seed 1。这是对应实验 ID 的技术配置，不代表正式效果实验已冻结，也不代表覆盖了所有传输分支。

## 4. C1：类别条件的后续突发记账

### 4.1 研究假设

当前出口队列可能为空，但已经分配到该出口的 QP 仍有后续数据到来。C1 用类别提示预测这部分“本交换机尚未观察到的后续量”，帮助后来的新 QP 首次分配。

“本地尚未观察到”包含主机已经发送、尚在到达 ToR 途中，以及此后才发送的数据。C1 没有精确测量端到端在途量，也没有读取尚未出现首包的未来 QP。

### 4.2 已实现规则

对候选出口 p，评分为：

```text
S_p(t) = Q_p(t) + R_p(t)
R_p(t) = 各个已固定到 p 的有效 QP 剩余预算之和
```

Q 为当前物理队列字节，R 为预测量。实现将载荷预算按共同 MTU 和报文开销换算到估计排队字节域，再进行比较。

一个手算例子是：两候选队列都为空，第一候选已有 7 KiB 预测压力，第二候选为零。QueuePin 平局取第一候选，C1 则选择第二候选。这个例子说明规则可以改变动作，实际收益仍需实验。

新 QP 先根据已有 QP 的 Q＋R 选择出口，然后在选中出口建立自己的预算。初始载荷模板为：MoE 8 KiB、背景 64 KiB、未知／统一模板 8 KiB。到期时刻是该 QP 首次源 ToR 选择后 20 μs，后续包不滚动续期。

本地观察到该 QP 的包后，按序号区间的新增唯一载荷扣减预算。重叠或重复字节不重复扣减，序号空洞不算已见。预算耗尽或到期后撤销预测，原出口缓存继续存在，重传不重新创建预算。

观察发生在交换机准入判断之前。因此，之后被交换机丢弃的这次到达也已属于“本地见过”，不再计入未见预算。可靠性仍由原传输负责。

实现最多保存 65,536 个预测条目，每条最多 32 个区间。超限撤销相应预测并回退，已有 QP 仍保持原出口。64 KiB 背景预算是有意限制的初值，并没有将整条 8 MiB 背景流当成物理队列。

### 4.3 对照与可识别贡献

| 控制 | 用途 |
| --- | --- |
| QueuePin／零预算 | 检查整体策略增量及关闭信号后的完整回归 |
| 类别／统一模板 × 扣减／不扣减 | 分开检验类别先验、发送进度和两者交互 |
| 同位置已观察字节衰减记忆 | 比较预测后续量与通用历史记忆；不将该控制称为 SRv6 系统复现 |
| 大小模板克隆 | 判断当前两尺寸输入中类别规则能否被大小先验复制 |
| 未知、移除、交换、延迟和部分错误标签 | 检查信号依赖、缓存纪律与失准代价 |

四个预算臂有共同容量上限，但实际占用和运算不同。扣减臂保存区间，也可能提前撤销耗尽条目；不扣减臂跳过区间更新。因此，进度开关不能被描述为已经严格同运算成本的消融。

可能的贡献是：在固定 QP 分配中刻画后续到达压力，并识别类别、进度和状态成本的价值。需要证明的增量超出了“队列外记忆”这一已有思想，尤其要超过加权活跃流计数。

### 4.4 已有观察与主要疑问

信息检验阶段记为 V0。在一个技术输入的离线重放中，共有 104 次源首次决定。83 个不同候选对的真实后续量不相等，结果如下。MAE 指平均绝对误差；排序判断两个出口真实后续量的大小关系。

| 预测规则 | 载荷 MAE／B | 严格排序正确数 |
| --- | ---: | ---: |
| 类别／扣减 | 120,894.73 | 76/83 |
| 统一／扣减 | 200,374.69 | 34/83 |
| 类别／不扣减 | 81,501.63 | 74/83 |
| 统一／不扣减 | 178,804.98 | 47/83 |

类别扣减的排序略好于类别不扣减，但数值误差更大。类别扣减臂的非零误差均为低估，说明 64 KiB 初值不能覆盖该条件下完整期限内的后续到达。该重放沿用 QueuePin 的历史路径，不能推出 C1 的端到端收益，也不用于事后挑选参数。

请审阅者重点判断：选路更需要排序还是绝对量准确？预算与物理 Q 直接相加时，量级失准会产生什么后果？固定初值与期限是否只把活跃计数换了一种表达？

## 5. C2：按类别实施有界启动分散

### 5.1 研究假设

同步到达的短请求可能在相近时刻竞争同一网络资源。C2 在请求已经到达后施加小幅偏移，希望减少同步竞争，同时保留固定 QP 选路的传输行为。

### 5.2 已实现规则与计时

主模式仅对策略标签 2 计算等待。固定四元组哈希产生 0 ns 至 500 ns 的偏移，不消耗模拟器随机数。标签 1 和未知类别立即放行。

```text
eligible = 策略标签为 2
delay = eligible ? H(四元组) mod 501 : 0
launch = demand + delay
FCT = finish - demand
```

QP 在实际放行时创建，拥塞控制也在放行时初始化。统计起点保留原需求时刻，单独记录等待。应用 Stop／Dispose 时取消尚未放行事件，取消数和字节单列，不计作完成。

对照包括：所有请求统一错峰、仅 8 KiB 请求错峰、全部零等待，以及决策标签移除或交换。标签干预直接作用于启动决策，原业务身份继续用于结果分组。四个启动模式都沿 QueuePin 选路，没有叠加 C1。

在 104 请求的默认兼容技术输入中，实际有 80 次正等待，总等待 18,002 ns，最大 497 ns；需求、放行、完成和原点 FCT 已逐条核对。这个结果证明计时链路和规则生效，不说明等待值得支付。

### 5.3 贡献与风险

C2 希望研究类别条件的等待预算与非迁移选路能否协同。其实现简单，创新性需要更严格判断：固定哈希抖动本身可能只是常规错峰，类别选择也可能被大小控制完全解释。

500 ns 是工程初值。它对多少个同步请求、哪些链路速率和排队尺度才有意义，尚无独立效果证据。源端延迟还可能使请求与其他竞争流更重叠。必须从原需求起点评价批次，并同步检查背景尾部。

请审阅者比较：类别选择是否优于对所有流实施同成本错峰？是否存在无需类别的简单规则，能取得同样效果？引入拥塞反馈后，会不会已经变成另一类调度或拥塞控制问题？

## 6. C3：新 QP 的类别配额与空闲借用

### 6.1 研究假设与实际规则

C3 希望在类别保护和容量共享之间调整新 QP 的准入。每个源 ToR 根据最近 20 μs 观察到的数据判断类别活动；当前活动状态按交换机聚合，而非单独为每个目的地建立活动窗口。

对 N 个合法出口，按端口号排序，前 ceil(N/4) 个归 MoE，其余归背景。只有一个出口时不分割。排序只确定归属，哈希索引仍沿原 next-hop 顺序。

- 对方类别活跃：新 QP 只能在本类别出口集合中二选一。
- 对方类别不活跃：新 QP 可以使用全部出口。
- 未知类别：使用统一规则。
- 已有 QP：保持首次出口和首次类别；后续包只更新活动与租期。

二选一继续使用固定双哈希、严格小于比较和平局保留第一。C3 会改变可用候选集合，这是配额的实际动作。因此，C3／QueuePin 不能解释为只增加一个类别信息字段。

### 6.2 借用、残留和状态

已知类别首次选择另一类别所属出口时，记作借用。借用者在出口所有者重新活跃后继续到达的包，记入残留包和线速字节，包括重传。

20 μs 活动租期到期，只改变活动计数及后续新 QP 的资格，不迁移或删除原 QP 的路径。一个静默长 QP 还可能再次发送并恢复冲突。路径和准入记录按四元组保留，其容量与长运行回收仍需共同核验。

对照包括始终分割、不允许借用的固定配额；按 8 KiB／8 MiB 大小重建类别的借用控制；直接 QueuePin；以及标签扰动。清理目标四元组时，其他 QP 和共享活动历史须保留。共享历史包括类别是否出现及最近出现时刻，即源码中的 seen／last。

已有技术格实际触发了限制、借用和残留。例如，标签交换格出现 20 次借用，残留 3,150 包、3,301,200 B。该数字只对应规定技术输入及标签干预，不能当作正常负载的平均回收成本。

### 6.3 贡献与风险

类别路径划分和空闲借用已有直接先例。C3 更可能有价值的问题是：当旧 QP 不能迁移时，新准入限制能在多长时间内产生实际保护？回收时长是否短于目标通信突发？

如果旧背景 QP 持续占据借来的出口，逻辑归属改变也不能立即创造物理容量。此时可能得到的是非迁移借用的可行域或负结果，而非优于固定分割的新算法。

还需检查：固定约 1:3 分割的依据、全 ToR 活动是否过粗，以及目的地、路径重合和活动稀疏如何影响借用判断。将旧 QP 拆分或迁移可能改善回收，但会改变当前路径与传输契约。

## 7. 已知相似工作与需要继续核对的差异

以下为定向近邻集合，不是穷尽文献综述。正式论文、作者版和预印本的阅读深度不同，参考文献列出实际版本。

| 相似工作 | 已有思想 | 与当前方案的具体关系 | 创新性审阅重点 |
| --- | --- | --- | --- |
| 本项目旧活跃 QP 加权方案 | 源 ToR 记活动，当前队列加常量乘活跃数，首包二选一并保持 | C1 增加按唯一到达扣减的有限预算；旧整臂还含其他候选及转发差异 | 必须用新匹配计数控制隔离进度增量，不能只比较旧完整版本 |
| TR［R1］ | 活跃短流计数、已发字节分类、ACK 辅助的逐包有序路径筛选 | C1 是有限后续预算与固定 QP 首次分配 | 预算对象和决策单位的差异是否带来实质价值 |
| Host-Driven Flowlet Balancing［R2］ | 主机估计已发在途字节，在 flowlet 边界选择路径 | C1 在源 ToR 预测本地后续量；两者可能覆盖一部分相同字节 | 需要同位置通用记忆控制，不能只强调“有预测” |
| CASSINI［R3］ | 利用作业通信形态及时间平移，交错共享链路上的通信 | C2 是已到达单请求的固定有界偏移，显式计入背景竞争 | 更少信息和更小实现是否构成贡献，还是过度简化 |
| Karuna［R4］ | deadline／非 deadline 混流调度，结合速率与优先级 | C2 保持公共传输制度，动作是启动时机 | 需要区分启动、整形、调度与拥塞控制，而非把混流保护都算作新问题 |
| APS［R5］ | 短／长流分类、类别路径划分、活动与空闲借用 | C3 只影响新 QP，已有 QP 不迁移 | 重点是非迁移回收时效，而非重新提出隔离和借用 |
| DeFlow［R6］ | 包长／间隔分类，按类别及拥塞改变迁移纪律 | 提醒三项方案说明为何保留固定 QP，以及类别提示如何取得 | 应比较约束与代价，不能把固定路径条件直接当作创新 |
| DiffFlow［R7］ | 类别决定整流或逐包粒度 | 支持类别与决策粒度分开审查 | 其简化传输及独立队列不能提供本项目 RDMA 证据 |
| SeqBalance［R8］ | 用独立 QP 子请求改变负载均衡单位 | 是考虑拆分或快速回收时的重要近邻 | 拆分将改变父请求完成定义、资源和可靠传输成本 |

FAMG［R9］目前仅有元数据和出版社预览核对，完整算法未取得。不能据现有检索判断它与 C1 没有重叠。Flowcut［R10］可作为在途关闭条件的参考。它采用 ACK 字节清账；本项目还须等待 Receive 接收函数返回，再关闭一次链路交付的记账凭据，即 token。

## 8. 已完成到哪一步

| 层次 | 已有证据 | 仍需回答 |

43 格来自不同目的和固定源码版本，不是 43 个独立需求，也不是同一源码完成所有能力。最新已验默认网络兼容源为 `1f917f44fcfb88e61f3ad22c5cc75fa3a06b6c0e`。实际对象预检源为 `8cd1ba69469bf80143d5c89edc17fa72611018e8`，只观察到端点覆盖位 127，没有自然网络完成。

后续 channel／switch 的组合观测、完成回调中的 RX 保存、历史释放、实际输入门和身份生产路径仍在补齐。当前受审的新源码不继承旧版本的运行验收。这些工作服务于正确性与证据可信度，本身不作为 C1／C2／C3 的创新贡献。

## 9. 后续计划与每一步的判断依据

### 9.1 先完成共同正确性，再按 C1 → C2 → C3 收束

| 顺序 | 实质工作 | 产出和判断依据 |
| --- | --- | --- |
| 共同工程门 | 完成真实对象、通道返回、全范围队列／事件、输入身份和历史接线 | 正常完成及拒绝反例；完整请求／字节守恒；关闭新机制后恢复对照 |
| C1 独立 V0 | 冻结独立需求，对同一事件前状态评价类别／统一 × 扣减／不扣减及通用记忆 | 每需求误差、低估／高估、排序、动作分歧、实际状态和处理成本 |
| C1 机制与效果 | 检查有可绕行竞争和唯一目的瓶颈两类条件，追踪首次动作至完成 | 识别决定是否影响实际竞争，再做冻结需求下双侧比较 |
| C2 机制与效果 | 固定等待规则，比较类别、统一、大小与零等待；核原点计时 | 分解主动等待与传输时间，检查同步度和背景竞争影响 |
| C3 回收与效果 | 比较动态借用和固定配额，跟踪所有者活动、旧借用者及后续新准入 | 残留持续时间、实际容量使用和批次／背景共同结果 |
| 最终判断 | 综合三项的证据、成本和适用条件 | 支持、修改或否定各版本；最终采用交由用户决定 |

这些是已有任务的后续验证路线。具体新实验格数、样本量、资源和数值判据尚待相应协议冻结，不继承历史大矩阵。

### 9.2 正式验证需要事前固定的内容

首先固定参数来源和评价对象。校准需求、技术输入与确认需求分离；对每个独立需求先计算配对结果，再跨需求汇总。相同需求的包级观测和多条件运行按相关数据处理。

主要比较是候选相对 QueuePin，同时报告与共同正式对照的完整策略比较。候选内消融分别识别信息和动作；原生 DRILL 等完整方法的差别不作单因素归因。

联合判断同时包括 MoE 批次、背景 P99、背景最大值和未完成请求。报告状态峰值、逐包／首包操作、运行时间、额外等待、重传与控制字节。预测准确、动作不同或构建通过均不能替代这些结果。

同一固定输入、源码、种子和观测配置应成对比较。停止、修复和负结果按事前判据处理；不依据确认结果放宽收益门槛或反复扩大参数搜索。
