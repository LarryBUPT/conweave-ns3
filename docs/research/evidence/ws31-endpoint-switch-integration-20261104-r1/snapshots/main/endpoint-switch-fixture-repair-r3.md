## 1. 问题与证据

r2 审查新增一项 P1，编号 R2-F1。owner 拒绝例把一个 switch 设备的 owner 改成 host；指纹先按改坏后的角色进入主机分支，再解引用该 switch 设备尚未绑定的空 QP group。预期的 Read 守卫还未执行，后续分支因此不能按源码认定可达。这是静态缺陷，没有实测崩溃或失败网络格。

主已核 62 项证据、28 份固定父源副本和 68 个精确锚点，十份当前与封存 WIP 一致。旧配额失败、恢复和中间收据保持原身份。S1／S2 的复合范围与接口绑定修订在源码层通过，见[主验收据](evidence/endpoint-switch-local-review-main-acceptance-r2.json)。副于 06:58:12 UTC 显式释放十文件约束，主实查终态 idle cursor 3 后才修订。

## 2. 最小改动

只改 `scratch/ws31-endpoint-switch-test.cc`。指纹直接记录实际存储的 egress、ACK 和 group 指针，并在访问成员前检查存在性；它不再依据被故意修改的 owner 选择协议分支。保留完整字符串前后比较，不在指纹里补 group、修 owner 或清理状态。QP 槽位也先记录空指针身份，再访问非空对象。

owner 拒绝例明确要求异常消息为 `WS31 switch scope device owner/index/uniqueness changed`，防止其他失败被误计为目标守卫。另九份 WIP 完全不变，生产探针、核心和 channel 本轮均不改。

## 3. 验证范围

指纹覆盖明确列出的协议字段，以及 pin／budget／quota／observed 的内容。它不是全对象内存或全部队列状态的比较。重复 Observation 只核既定目标计数；重复 AddDevice 会同时改变接口数量和编号，不能单独证明唯一性拒绝分支的动态覆盖。

25 组双读、63 次组合 Read、53 次成功返回、10 次 Read 拒绝和 19 次全部拒绝仍是静态计划量。另一次直接端点读取用于保存同纳秒旧结果。它们尚未执行，没有 mask 255 实测、自然完成或网络生命周期证据。
