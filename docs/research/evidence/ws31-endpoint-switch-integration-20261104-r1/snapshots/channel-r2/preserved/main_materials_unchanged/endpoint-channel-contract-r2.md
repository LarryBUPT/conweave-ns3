## 2. 默认路径与成本

默认仍调用原直接 ScheduleWithContext，保持目的 context、原 Packet Ptr、延迟及动画顺序；新增使用标记写入。观察路径保持一个交付事件，整个 Receive 返回后才关闭账本，再扣 channel pending。

删除新增观察分支、包装和成员后，channel cc／头文件精确恢复父源；删除 include guard 后，tag 头文件也精确恢复。默认功能、事件次序和成本仍须真实运行验收。新增成员、标记写入、失败检查与回调均有成本，不以静态恢复检查声称零开销。

## 3. 夹具与故障边界

夹具继续使用替代的虚函数 Receive，未进入生产 NIC／交换机／RDMA 接收。新增类型／编码边界、旧默认事件后的晚绑定、空闲和在途 owner 丢失、Receive 与 leave 异常、账本 Enter 后与 history 后异常、pending 后调度前异常、实际动画 trace 异常和原子 Bind 重试。

history／open、调度及 Bind 的异常为指定变更边界处的受控抛出，不是实际分配器耗尽或调度器插入失败。动画用真正的 TxRxQbb trace 回调抛出。须分别报告每例原始计数、失败锁存、能否 Finish、未闭合 token 和后续调用；不能因退出码或汇总 PASS 就声称资源回收、真实传输或完整网络正确。

owner 丢失后回调保留 shared State／ledger，没有访问已销毁会话；它没有产生正常 Finish。原设备／channel 的强引用关系和失败事件引用问题分开判断，不声称 Destroy 清空所有对象。
