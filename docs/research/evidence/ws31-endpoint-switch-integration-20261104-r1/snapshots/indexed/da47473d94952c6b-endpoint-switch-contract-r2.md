## 1. 已确认的问题

主对照原字节核对了 r1 审查的 43 项证据、16 份固定父源副本和 68 个源码锚点，见[主验收据](evidence/endpoint-switch-local-review-main-acceptance-r1.json)。副已明确释放九文件只读约束，无后台任务。channel 的 const 引用修订在源码层得到确认，原五份 channel 文件本轮不再改变。

S1 为 P1：旧入口允许外部端点 Observation。即使时间戳相同，也可能在端点读取之后添加接口或入队，再用新 switch 范围升级旧端点结果。S2 为 P2：接口向量未改变时，公开 owner 或 ifIndex 字段仍可能改变。两项均是静态反例，没有执行产生的假排空证书。

## 2. 修订后的唯一读取入口

`Capture(drivers)` 在一个私有 Scope 中保存端点范围和交换机范围。`Read` 接收实际 TX／RX 硬件、保存的 TX／RX 对象及所选 NIC；先验证范围，再直接调用实际端点读取，随后同步读取交换机表。入口不再接收外部端点 Observation。输出保留完整端点 Observation、复合 snapshot 和逐交换机行。

捕获和每次验证都检查所有接口非空、实际 owner、ifIndex、全范围指针唯一性，以及 Qbb 或 loopback 类型。至少一个精确 SwitchNode、节点角色、节点及接口数量、接口身份和模式 33～50 的原有守卫保留。读取期间不调用回调、推进事件、执行 aggregate 查找或清理状态。setup 阶段的 `GetObject` 仍限定在端点 Capture 中。

## 3. 新夹具的范围

新文件为隔离实现树的 `scratch/ws31-endpoint-switch-test.cc`。使用两个真实 SwitchNode、两个主机、三条实际 Qbb 链路、真实 driver 初始化和保存的 TX／RX；协议状态由夹具赋值，没有实际传输或自然完成。

夹具拟检查两交换机计数累加、四元组不含 PG、所有支持模式、未命中不插入，以及过期但未清理的预算和配额。重复读取前后比较 pin 全内容、预算条目／范围／期限／端口总量／计数器、配额决策／期限／借用／活动历史、端口记忆的字节和时间，以及设备绑定、队列和端点状态。新增窄 friend 仅供夹具生成语义指纹，不新增成员或生产清理路径。

S1 的队列反例改为同纳秒保存旧端点结果、入队后执行复合读取，要求实际队列字节可见；接口变化使旧复合 Scope 被拒绝，重新捕获时端点范围也同步更新。S2 覆盖 owner、index 和重复设备。另设默认范围、模式改变、错误保存对象／资源、未知角色、伪 switch 角色和 switch 子类拒绝。

夹具使用两个人工 token 检查覆盖位不能绕过账本，再在账本允许后调用原 `ResetWs30V13Tuple`。清理必须只移除目标 K，保留 K2 和共享活动／端口记忆；stored liveBorrowed 仅按原 Erase 下降。人工 ACK_COMPLETE、token 关闭和状态赋值不计作真实网络生命周期证据。
