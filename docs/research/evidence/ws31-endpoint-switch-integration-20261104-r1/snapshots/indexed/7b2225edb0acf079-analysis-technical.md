## 3. 算法与数据流

第 III-A 节没有伪代码，图 2 和文字给出以下过程。

```text
新流数据 → 源 ToR 默认 ECMP
                 ↓ 周期抽样看到同流的两个包
             ToR 上报 MAC、IP 和 TCP 端口
                 ↓
             SDN 保存标识并向汇聚／核心安装规则
                 ↓ 中间规则全部建立
             SDN 通知源 ToR 开始 RPS
                 ↓
             长流匹配规则 → 各节点随机选择可用出口
             其他流       → ECMP 的固定出口
```

规则示例包含输入端口、源／目的 MAC、Ethertype、VLAN、IP 和 TCP 端口。图 2 表头的 TCP 源／目的端口与正文叙述存在对照歧义：正文称 6543 为源、1234 为目的，图中按 TCP Dst、TCP Src 列列出 6543、1234。它不改变混合粒度思想，但复制实现前应澄清字段映射。

控制器不进行拥塞最优路径计算。中间规则完成后才启用源 ToR 喷洒，意图是保持规则更新的先后顺序。但原文未给出确认协议、安装失败处理、超时、规则优先级、长流结束检测或规则回收策略。

检测依据是流持续出现，分类门槛受抽样周期影响。它没有读取应用类型，也没有在真实部署中提前知道总大小。实验却按生成的短／长尺寸分组，未说明如何联结实际抽样检测和分类结果。因此，不能确认性能图已包含检测延迟或误分类损失。

这是分类状态广告，不是拥塞反馈。喷洒不使用队列或路径质量测量。大规模可扩展性由“控制器不算最优路径”和“仅长流上报”作定性论证；每条长流还要向多个交换机安装规则，缺少消息率、表项、处理时延和规模曲线。

## 4. 理论模型逐式核对

第 IV 节假定所有链路等容量，源目的之间的 N 条路径已知。路径端到端时延 τ 按升序排列，路径包含 y 个中间转发节点。第 III-B 节另用 M/D/1/K 描述有限缓冲路径。它们是简化模型，并非完整协议证明。

| 公式 | 原式要点 | 解释及限制 |
| --- | --- | --- |
| （1） | `t_ideal = Σ_l (y_l+1)L_flow/c × P_l^u/P_U` | 全流长度串行服务的加权参考；未推导流水线条件下的实际最小 FCT |
| （2） | `P_U = Σ_l P_l^u` | 正文称为至少一条路径被用的概率；RPS 取值会使该和为 N，语义不一致 |
| （3）～（4） | ECMP `P_l^u=1/N`；理想项加加权路径时延 | 描述固定一路时的平均值；没有在线控制状态 |
| （5） | RPS `bar_tau_RPS=t′+tau_(N−1)` | 按最慢已用路径描述完成；t′ 与式（1）的记号衔接不清 |
| （6）～（7） | 路径同时送包事件的概率乘积，再枚举超出可用出口的组合 | 依赖可分解的路径事件；共享链路与实际调度造成的相关性未处理清楚 |
| （8） | `bar_tau_Q=bar_tau+Σ_l Σ_q P_B(v_q)rho_q` | 加入排队期望；没有显式路径权重，共用节点计数语义待澄清 |
| （9） | `P_r=1−(1−P_loss)^H` | 流至少丢一包的概率；用同概率、独立包损失近似 |
| （10） | `bar_tau_sum=bar_tau_Q[1+P_r(γ−1)]` | 固定比例放大丢包流的 FCT；不含完整恢复协议 |

式（2）是可以直接检查的记号问题：ECMP 的和为 1；作者对 RPS 设 `P_l^u=P_l=1`，和就为 N。若将其理解成归一化权重总和，式（1）仍可作计算；若理解成“至少一条被使用”的概率，它不能超过 1。本文保留原式，不替作者修正。

RPS“总使用全部 N 路径”的前提也不适用于有限短流。作为阅读者的反例，若 H 个包独立均匀选择 N 条端到端路径，一条路径至少被使用的概率是 `1−(1−1/N)^H`。期望使用路径数为 `N[1−(1−1/N)^H]`。H=1、N=8 时只使用 1 条路径；最慢路径未必被使用。这个简单公式不是作者实验，逐跳选择及共享路径还可能改变其前提。

式（8）的双重求和需要更多定义。它对全部路径上的节点累加，没有说明是否按路径使用概率加权、如何避免共用节点重复计算。正文称排队时间和丢包概率可以测量，但没有给出从这些测量构建全部分析曲线的充分方法。理论与模拟线相近，只能说明作者所选参数下的拟合趋势。

γ 的值见第 5 页：短流 5，长流 1.2，同一类别的三种方法使用同值。作者将它解释为重传导致 FCT 放大的比例，并指出它使分析与模拟存在偏差。不能把 γ 说成 TCP 参数，也不能确认模拟器同样直接按 γ 放大：原文明确描述模拟器等待 RTT 后重传，未给出 γ 的实现路径或标定方法。

## 5. 实验条件与指标

| 参数／条件 | 原文记录 | 注意事项 |
| --- | --- | --- |

| 服务时间 | 表 II 为 core/aggre. `12 µs - 3 µs` | 按表列顺序记为核心 12 µs、汇聚 3 µs；ToR 未单列 |

| 包长 | 1500 Bytes | 统一包长，字节单位未明确十进制／二进制 |
| 短流大小 | 1.5～15 KBytes，1～10 包 | 本文保留作者单位，不改成 KiB |
| 长流大小 | 正文 16.5～1500 KBytes，11～1000 包 | 表 II 下界为 15 KBytes，与正文不一致 |
| 尺寸生成 | 原文称两个独立 Poisson processes，均值 10／1000 KBytes | 对尺寸使用“过程”的说法不够清楚；截断／重采样未说明 |
| 包数均值 | 正文为 6／666 包 | 短流 10 KBytes 折算与 6 包并非精确一致；截断后分布不详 |
| 类别比例 | 90% 短流、10% 长流 | 引言为 80%／20%，不能混成同一实验比例 |
| 到达负载 | 泊松到达，0.1～0.8 | §V-A 称 Erlang；不能直接改成链路利用率 10%～80% |
| 传输 | 不用 TCP；丢包后等 RTT 再重传 | RTT 数值、计时和重复丢包处理未给出 |
| 队列 | 两类独立队列 | 调度、发送能力和公平性未交代 |
| 对照 | ECMP、RPS、DiffFlow | 未实测 CONGA、LetFlow、ConWeave |
| 统计 | 没有 seed、时长、重复数或区间 | 图线没有误差条；稳定性未核验 |

1,500 B 在 1 Gbit/s 上的串行发送时间是 12 µs。这是由表 II 换算的阅读者计算。它恰好与核心服务时间相同，但汇聚服务时间为 3 µs。原文没有交代服务时间与接口发送的重叠关系，不能简单把两者相加或据此推算所有节点的有效容量。

FCT 从首包离开发送服务器，到最后一包到达接收服务器计算，然后除以理想无队列参考值。图标题明确使用 Mean。全流、短流、长流的平均方式和理想值汇总顺序未详述；不能用图 4 与图 5 自行反推类别权重。

吞吐通过丢包比例和已知输入负载计算，再除以理想吞吐。它近似反映模型中的接受比例，未说明重传字节是否进入统计或最终可靠交付如何计数。故应称“作者定义的归一化吞吐”，避免写成应用 goodput（有效吞吐）。

作者以不同路径时延解释短流 RPS 较慢，并称短流 ECMP 避免乱序。但没有乱序率、重排深度、误重传等原始测量。在省略 TCP 的模拟器中，路径到达时延本身与协议对乱序的响应必须区分。“没有给短流引入逐包分路”可以确认；“真实协议没有乱序代价”不能确认。

长流无严格时限、DSACK 与时间戳提高 TCP 乱序容忍，是第 VI 节之前的解释，未由本文 TCP 实验支持。结论又明确指出集中控制器限制当时 DCN 的应用。第 II 节关于 SDN 广泛采用的论述与这一部署判断存在张力。应将其记录为作者的架构期望和自述限制，而非已实现部署。

## 7. 独立队列是否构成混杂

原文只说“our simulator”使用两类独立队列，未说明这是一项仅给 DiffFlow 的额外能力。不能武断认定对照队列不同，或断言全部收益来自隔离队列。

不过，独立队列及其调度决定两类包怎样竞争服务。若三臂相同，这是一项共同实验条件；所得对比仍限定于该条件。若配置或资源分配不同，它才会进一步形成不受控混杂。当前缺少代码、调度细节和共用队列消融，无法区分这两种情况。

可迁移的实验建议是固定队列条件，分别比较分类粒度和队列隔离，再加入完整传输。它属于后续可证伪设计建议，本次不开展实验。
