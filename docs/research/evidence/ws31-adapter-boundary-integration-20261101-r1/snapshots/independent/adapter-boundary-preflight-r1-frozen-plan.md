## 3. 构建、执行和证据

独立副核对个人 origin、已推送分支、干净独占树、旧驱动终态、worker、缓存和新 ID。先做资源门：没有其他用户或未知项目作业、可用内存至少 64 GiB、磁盘至少 100 GiB、初始一分钟负载不超过 4。只允许一个 `-j2` 构建；无网络仿真并发。

完整构建后直接运行新二进制，设置 `LD_LIBRARY_PATH` 为该隔离源的构建库目录，不用 `waf --run` 触发额外构建。先核二进制及动态库实际存在和来源，再启动三个有序命令。环境固定 `WS30_OBSERVE=2`、新标签 profile 0、旧 transform／lifecycle／composition 为 0；清理旧诊断继承值，记录允许字段，避免继承旧实验控制。

逐命令保留 argv、环境白名单、开始与结束、退出码、完整 stdout／stderr、固定源和二进制哈希。C2 原始行保留四元组、实际等待、原点、交付时刻、两个 event uid、请求与字节账。C1／C3 保留逐包 uid、序号、载荷、存在性、端口、队列字节、预测或活动账；另保留只读空闲快照及清表前后账。副先核覆盖，主再从回传原日志独立验收，不能只读 PASS 摘要。

资源收据、实际构建任务数和耗时、固定 Git 对象、完整树、全部日志／二进制／库及收据均进入最终索引。新结果只写新 ID 和副自有目录，不覆盖历史。任一源审查、构建、覆盖、时间或状态失败立即停止后继步骤，保留原源及证据，由主修复后另冻新 SHA／ID。
