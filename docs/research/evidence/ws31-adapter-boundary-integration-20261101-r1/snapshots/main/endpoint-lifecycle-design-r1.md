# WS-31 端点退出与排空夹具设计

日期：2026 年 11 月 1 日。状态：依据实际源码形成的实现草案；未编写端点代码，未授权网络运行。

## 1. 与现有测试的关系

[源码缺口](endpoint-lifecycle-source-audit-r1.md)确认，完成回调先于发送映射删除，发送／接收映射、网卡队列组、当前发送包及链路交付又是不同状态。17 例适配器只能验证真实选路方法、局部状态和 C2 事件，不能代替这些端点条件。

新夹具保持旧 lifecycle、composition 和动态标签 profile 为 0，使用独立 WS-31 入口。原输入业务身份、四元组和优先级保持，两代 flow_id 不同，generation 由显式请求登记账维护。先完成适配器预检及主验，再确认本草案的接口和最小网络计划。

## 2. 请求状态与复用门

每个请求按以下状态推进，所有状态和转换保留时间及来源事件：

`CREATED → ACTIVE → ACK_COMPLETE → ENDPOINTS_RETIRED → DRAINED → SWITCH_CLEARED → NEXT_CREATED`

完成回调只标记 `ACK_COMPLETE`。回调返回后的后继事件再核发送和接收映射已退出、相关重传／DCQCN／接收事件不运行，才可标记端点退役。不得在完成回调中直接创建同四元组，避免旧发送映射尚未删除时覆盖。

完成历史集与旧代观察记录分别保留。测试入口只有在已完成、端点已退役且排空证书成立时，才允许处理该 tuple 的完成历史及队列组，再调用交换机真实清理。网卡队列组可能仍持有已完成 QP；须记录这一事实，不把映射为空等同于对象已释放。最小无背景夹具可在确认该组全部 QP 已完成后清理组；不得清理仍有其他活动 QP 的组。

## 3. 排空账与包身份

现有发送路径无条件附加 `FlowIDNUMTag`，`ReceiveUdp` 构造 ACK／NACK 时无条件复制该标签。夹具可据真实标签关联请求登记账，不必让候选读取大小或新代际信息。关联属于测试观测，不进入 C1／C2／C3 决策。

`QbbChannel::TransmitStart` 将同一包指针传入延迟的 `QbbNetDevice::Receive`。拟在默认关闭的测试入口中，为每次实际链路发送生成单独 token，保存 UID、flow_id、generation 和定向链路。不能只用 UID 去重，因为一个包可以逐跳转发，测试副本也可能保留相同 UID。

token 应在对应接收处理全部返回后闭合。若在进入 `Receive` 前就扣掉，最后一个 ACK 可能令账面为 0，而其完成回调和发送映射删除仍未结束。接收期间转发产生的新 token、真实队列字节、ACK 高优队列、当前发送状态及未完成测试副本必须共同计入复用门。只读排空检查不出队、不推进事件、不清零账本。

## 4. 正例与拒绝反例

正例使用实际 QP 和网络完成两代请求。第二代的原需求可以有预定时刻，但该时刻到来时仍须检查实际排空证书，不能用等待了足够久替代证据。清理前后直接记录交换机状态，第二代须出现真实新准入和最终完成；原第一代全部观察账保留。

拒绝例保留一个明确属于第一代的延迟测试副本及未闭合凭据，再尝试复用，复用门必须拒绝且不能改变端点或交换机状态。测试副本若没有送入网络，应明确记录后续交付或显式丢弃和凭据闭合，不得假称接收端已经拒绝旧包。若要检验旧包实际进入已退役端点，则另冻新的接收隔离行为和验收，不用本拒绝例推定模型已有原生代际隔离。

## 5. 实现与后继门

下一步核定只读状态接口、token 接收包装及测试入口，保证默认关闭时不增加事件或改变普通路径。代码修改后先独立审源和工程预检，再按新固定 SHA／输入／ID／资源门运行最小网络格。任何状态、token、身份、原点或字节不守恒均停止后继并保留失败。

本草案没有源码实现或实测结果。C2 交付入口的[默认回归计划](adapter-default-validation-r1.md)也仍受前置门约束；独立 V0、双侧效果和成本继续保留。
