## 2. 已核实的调用关系

| 位置 | 实际行为 | 后继验证要求 |
| --- | --- | --- |
| `RdmaHw::QpComplete` | 取消 DCQCN 三个事件及重传事件，先调用完成回调，再调用 `DeleteQueuePair` | 回调中的“完成”不等于发送表已退出；不能在回调中立即覆盖同一 tuple。后继事件应核实际删除及事件状态 |
| `qp_finish` | 完成计量后调用目的端 `DeleteRxQp` | 接收表删除和发送表删除的时序不同，两侧都须有收据 |
| `RdmaHw::DeleteQueuePair` | 写完成历史集，再擦除发送映射 | 映射为空不能代表历史集、网卡队列组、在途包及全部事件已退出 |
| `RdmaHw::DeleteRxQp` | 正常路径擦除接收映射；额外代际校验和 QCN 事件取消受旧生命周期开关控制 | WS-31 不打开旧开关。新夹具须独立检查接收事件和历史，不继承旧模式的保护结论 |
| `RdmaEgressQueue::GetNextQindex` | 完成 QP 通过位图跳过，队列组仍可保留对象 | 不能要求“发送表空”就把网卡队列组也写成空；须明确逻辑退役、剩余引用与物理释放的区别 |
| `QbbNetDevice` 与基类 | 数据队列、ACK 高优队列、当前发送包和链路交付事件分处不同对象 | 单一队列字节为 0 不构成排空证据；须覆盖当前发送和链路传播 |
| `RdmaHw::AddQueuePair` | 正常路径写发送映射；额外防覆盖及复用历史清理受旧生命周期开关控制 | 新夹具必须在调用前证明两端旧代退出并显式处理完成历史；不把关闭的旧保护当作已启用 |

上述事实尚未证明真实路径出错。它们说明当前标签和交换机适配器测试不足以验收端点复用，相关任务继续保持未完成。

## 3. 待冻结的最小验证路径

新端点夹具应保持旧 lifecycle 为 0，使用独立的 WS-31 观测账和测试入口。原四元组、优先级和业务身份必须逐项保留，两代使用不同 flow_id 与显式 generation。第一代完成回调返回后，先核发送／接收映射、完成历史、相关定时事件及队列组，再取得排空证据，才允许交换机清表和第二代创建。

排空账至少分别覆盖数据和 ACK／NACK 的已排队、正在发送、链路传播、延迟测试副本与接收交付。账本不能通过清零或固定等待代替守恒。只读状态检查不得触发到期或出队来修补被测行为。

负例应保留一个明确归属第一代的延迟副本，在该副本仍有未交付凭据时尝试复用，并要求复用门拒绝。正确路径待所有旧代凭据闭合后再清理和创建。是否还需包级跨代拒绝、采用何种只读接口、如何退役队列组对象，须经实际调用链设计与独立审查后冻结；此处不预先宣称已解决。
