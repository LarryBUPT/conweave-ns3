# WS-26 ClassReserve v3 独立需求 pilot 协议

状态：v1 因 ConWeave 参数门失败而停止；v2 已冻结，尚未启动。日期：2026-10-08。本协议只决定候选筛选与资源调度。pilot 结果不作为正式收益证据，也不改变 WS-25 的 NO-GO 结论。

## 目标与固定输入

本轮检验 ClassReserve v3 在新需求上能否同时改善 MoE 整批时间和背景 P99，并确认背景占用信号与真实改选是否出现。四个 pilot seed 为 `20262690～20262693`，与预留的 24 个正式 seed `20262601～20262624` 分开。每个 seed 的同档算法共用逐字节相同的输入。seed 是独立重复单位；流、档位和算法臂不增加重复数。

v1 使用源码 `d6fdc5efe9a9aa77a90d24ab3aee931f721b607f`。第 7 格 ConWeave 在仿真前因 `Unsupported ConWeave Parameter Setup` 失败。该 SHA 下的 6 个已完成格和失败 ID `20261008-070000-ws26v3-p90-b192-conweave` 仅作历史记录，不进入 v2 分析。

v1 原计划见[停止批次计划](evidence/ws26-v3-pilot-plan-v1-stopped.json)。对应收据位于本机忽略目录 `results/ws26-v3-independent-pilot/receipts.jsonl`。

v2 固定源码为 `593038416fa16f4982b600d256b563260f9106a8`。该源码为 OS1、PFC=1、IRN=1 的 ConWeave 明确设置 `flush=16`、`waiting=300` 和 `expiry=1000`。这些值属于工程比较配置，不是原版官方校准。

拓扑 SHA-256 为 `74a6f7154ca10c3cd6dfd45046c4f8abf0ce27faa8ad11446b6a52920b83afba`。16 份 trace 的哈希、52 个全新 ID、运行顺序和参数列于[v2 冻结计划](evidence/ws26-v3-pilot-plan.json)。生成器为 `scripts/make_ws26_v3_pilot_plan.py`。

所有格使用 OS1 拓扑、400 Gbit/s、buffer 9、PFC=1、IRN=1 和 ns-3 seed 1。输入含 16,384 条 MoE 流，以及对应档位的 0、64、128 或 192 条背景流。

## 两阶段运行

第一阶段运行四 seed 的 192 档，每 seed 有 ECMP、DRILL、CONGA、LetFlow、ConWeave、ClassReserve v3 六臂，再运行同输入的 ClassReserve v3 诊断开关格，共 28 格。六个业务臂的顺序由固定随机数 `2026100801` 预先打乱；诊断格紧随相同 seed 的候选格。诊断格只检查计数和非扰动，不充当第五个 seed 或收益观测。五个原仓库模式只作筛选背景与回归检查，pilot 不对其作正式 Holm 判断。

第二阶段仅在第一阶段通过下述筛选后运行。它覆盖四 seed 的 0、64、128 档，每档仅 ECMP 与 ClassReserve v3，共 24 格。档位和臂的顺序也由同一固定随机数预先打乱。若第一阶段未过筛，保留这 24 个未启动 ID，不把它们记作成功或失败格；转入一次事前记录的诊断修正或下一候选版本。

## 逐格验收与资源门

每格先核对原 ID、源码与输入 SHA-256、模式、PFC/IRN、ns-3 seed、完整配置快照和资源收据。以 trace 中全部 QP 为分母，按源端、目的端、端口、大小、开始时间和 tag 一一匹配原始 FCT；重复、缺失或未完成的流使该格性能值未定义。MoE 数量必须为 16,384，背景数量必须等于档位值。两类业务共用 RDMA QP 模型，不将其解释成真实 TCP/UDP 与 RDMA 控制消息混跑。

候选格还须满足新建加缓存命中等于对应类别包数、`choices=moe_new`、队列入队等于出队加丢弃加当前占用、缺失目的端和队列违规计数均为零。诊断格须逐 QP 核对路径稳定、类别包数和唯一身份；路径记录数以实际进入多路径分支的 `background_new+moe_new` 为准。相同 seed 的诊断开关与普通候选格必须具有完全相同的 FCT 原始文件 SHA-256。PFC 次数从原始事件文件统计，零次只说明本格未触发。

资源 watcher 必须先于首格启动并产生采样。每格要求终态收据与至少一条采样对应，进程树 RSS 峰值不超过 32,768 MiB，可用内存谷值不低于 32 GiB，剩余磁盘谷值不低于 100 GiB，采样的一分钟负载不超过 20。副对话先确认服务器无人作业、锁和唯一 runner，再从调度上限 1 开始；只有在连续格安全、SSH 与存储保持可用、吞吐确有改善时才逐级提高。任何其他用户作业、阈值突破、吞吐下降或 SSH 不稳定均暂停新格并降载。已启动 ID 保留原始状态，恢复时按收据防重。

正确性失败、身份不符、诊断扰动或资源收据缺失时，停止开启新格，保留失败 ID 并定位原因。修复须使用新 SHA、新 ID，重验受影响的同 seed 配对；不能以失败格的已完成流计算收益。资源暂时异常可在保留原 ID 的前提下按工作流防重恢复，不覆盖现存 raw。

## 高档探索筛选

MoE 整批时间为该档全部 MoE 流的最晚完成绝对时刻减共同 2.000 s 起点。背景 P99 为全部 192 条背景流的 FCT 线性插值第 99 百分位。每个 seed、每项指标计算 `100 ×（候选 / ECMP − 1）`，越小越好。四 seed 的两项配对变化须分别达到中位数不高于 −3%，且各有至少 3/4 个 seed 严格改善，才进入低档阶段。两项必须同时成立；等于零不计改善。

机制覆盖另要求 `with_background>0` 和 `diverted>0` 各自出现在至少 3/4 个 seed，并报告 `with_same_destination`、实际改选比例、两类逐 QP 路径和队列计数。覆盖不足时，即便两个效果数字过筛，也先诊断而不宣称机制生效。若覆盖成立而双侧筛选失败，保留反例并调查末跳、CNP/ECN、PFC 与 IRN 反馈；最多对本候选做一次诊断修正。四 seed 的严筛存在误拒可行机制的风险，故只用于是否投入下一阶段，不用于估计总体收益。

## 低档约束与报告

若第二阶段启动，0 档检查 MoE，64/128 档同时检查 MoE 与背景 P99。各指标相对 ECMP 的四 seed 配对中位恶化不得超过 +5%，且恶化超过 +10% 的 seed 不得多于 1/4。0 档背景 P99 记为不适用。低档越线则不冻结本版本进入正式矩阵，按预留的诊断修正或新候选流程处理；不删除已运行格。

逐格报告 MoE 整批时间、背景 P99、MoE 单流 FCT 均值与 P99、背景单流均值、PFC pause/resume 次数、完成率和候选机制计数。按 seed 列出两项绝对值、配对变化、严格改善方向及最差反例。pilot 全部已启动格终态回传并核验后，实际切至 GPT-6 Sol High 做配对分析。任何正式 seed 结果被读取前，另行冻结唯一候选及参数、正式 24 seed 和 1,152 个原 ID、完整输入哈希、正式分析脚本、资源停止线与预设主判据。正式 GO 仍只由 24 seed 的双主结果及既定低档、Holm 规则决定。
