# WS-26 seed 97 时间对齐诊断设计

状态：2026 年 10 月 10 日事前设计。目标身份来自唯一实验副对话对已验收 raw 的只读提取。本文件固定分析问题与选择规则；固定源码 SHA、新 ID、日志上限核验及资源 pilot 须按冻结计划逐项完成。第三候选未准入，v3 与 v4 的双侧 NO-GO 不变。

## 问题、单位与竞争解释

本诊断只研究已揭盲的 seed `20262697`。ECMP 与 ClassLane v4 r2 使用同一 trace 和传输设置。背景 QP `1124→628:10000/102` 在 v4 慢了 392.383 μs，但其源 ToR 与中转区域的逐 QP 最大等待下降。要判断多出的时间落在哪些发送空档、逐跳队列、反馈到达和速率变化区间，必须沿同一 QP、同一包的时间轴核对。

竞争解释事前列为：可选上游出口排队、目的侧共享出口排队、发送端受 CNP／DCQCN 调速，以及其他流改道后的时序竞争。逐跳等待峰值来自不同包，不能相加为 FCT。两格、目标 QP 和对照 QP 都属于同一个已揭盲 seed；它们是机制诊断观察，不能充作独立重复，也不能重新估计 v4 效果。

## 固定目标与对照

目标集合是两模式各自背景最晚完成三条、MoE 最晚完成三条 QP 的并集。全部 QP 从 `2.000 s` 开始，故该 seed 中按完成时刻与按 FCT 排序一致。副对话已核对两模式 trace 相同，SHA-256 为 `58bbc2d8ca78753c5e6e2fee119341ea94c8ee76cbad58e013c93707833ee3ca`。下表四元组均按 `src→dst:sport/dport` 写，标签 E／V 表示进入 ECMP／v4 前三名，不表示一个新实验臂。

## 观测实现与日志预算

使用新的、默认关闭的 seed 97 诊断开关，保持 ECMP 和 v4 的选路、队列、传输分支不变。仅为表中目标及去重后的对照记录源端实际发包、ACK／CNP 接收、速率变化，以及逐跳设备出口的入队与出队时刻。每次出队输出一行，包含对应入队时刻，避免把两个事件拆成两行。逐包关联键至少包含 QP 四元组、包序号、交换机 ID、出端口及包 UID；出队行还保留队列字节、等待和 ECN 标记决定。记录摘要须给出逐类行数、未配对数、截断数和新增日志字节。现有 `WS13_HOP` 与 `WS26_MOE_HOP` 汇总继续生成，用来复核两类 QP 的逐跳路径与守恒。

先在本地审查日志总量上界，并在最小正确性格实测。11 条去重背景 QP 各约 8,389 个数据包；按 4 跳估算，逐跳合并行约 369,000 条，再加源端发包与 ACK 约 184,000 条。因此，暂定每个实验 ID 的新增日志硬门槛为 192 MiB、总事件不超过 800,000 行，其中交换机上限为 128 MiB／500,000 行，发送端上限为 64 MiB／300,000 行。重传和实际跳数可能增加行数，须由资源 pilot 核对。达到上限时显式计数并判诊断不完整，不能静默截断后解释时间线。任一选中 QP 的必要事件缺失、入队／出队不能配对，或关键包缺少对应时间戳，同样停止机制归因。若预算不足，只能事前缩小观测范围并建立新源码 SHA／新 ID，不能在运行后按结果删流。

## 固定输入、顺序与执行门

计划先运行两个 ECMP 小格，再运行 seed 97 的 ECMP、v4 高档格。小格使用同一份 61 流固定输入，先关闭新探针，再开启新探针。输入包含背景目标 QP `896→628:10000/100` 和 MoE 对照 QP `0→1144:10059/100`。其余 59 条 MoE 流用于保持后一条的端口身份。小格输入 SHA-256 为 `e6e55714818d84971d831ad9dc39e37e0a4cea7eb5ce5636eeb28dc94bd439bd`。开启探针的小格须命中两类 QP。两个小格的 FCT 原始文件须逐字节相同。

四格按上述顺序以 cap=1 串行。拓扑 SHA-256 为 `74a6f7154ca10c3cd6dfd45046c4f8abf0ce27faa8ad11446b6a52920b83afba`。传输参数沿用普通配对格：PFC=1、IRN=1、DCQCN、ns-3 seed 1、400 Gbit/s、9 MiB buffer、`netload=10`、`simul_time=0.01`。高档普通格的 FCT SHA-256 为 ECMP `5782262613100533dd04fbcca515feda56beed12a3db0c27b32b02f16d5c3c68` 和 v4 `537dad823db4de5cf1b2b09ae711f0cd5976a2638024adc685e5317f029bb30e`。

启动前必须把新增探针源码、目标清单、计划和验收器提交到个人 fork，并登记固定源码 SHA、计划 SHA-256 与四个全新实验 ID。唯一实验副对话先核对 ID 未使用、远端唯一 runner、其他用户作业和系统健康，再执行隔离构建与两个小格。小格须证明目标过滤、时间戳配对和 FCT 一致性。首个高档 ECMP 格是资源 pilot：build 与 run 前重新过资源门，run 前启动 watcher 并确认首条采样，终态保留资源摘要。进程树 RSS 峰值上限 32,768 MiB、可用内存下限 32 GiB、剩余磁盘下限 100 GiB、一分钟负载上限 20；任一异常暂停下一格。

## 逐格验收与结论边界

每格先核对固定 SHA、输入与配置，再验 16,576/16,576 条流各完成一次、输入身份／大小／起始时刻一致、两类 QP 的完整逐跳记录、路径连通稳定、队列入出守恒和 `WS13_INFLIGHT unpaired=0`。新格原始 FCT 必须与对应普通格逐字节同哈希，并留存所有 raw、日志、资源收据及哈希。首格任一项失败即停止后续格；保留失败原始数据，以新 SHA／新 ID 修复，不覆盖。

两格通过后，按相同 QP 与关键包时间线列出发送间隔、逐跳等待、ECN 标记决定、CNP 到达、发送速率及最终完成。分别检查背景反例、MoE 两模式尾流身份迁移和同目的 ToR 对照；报告能定位的区间与仍未解释的时长。队列、反馈与 FCT 的先后关系是机制线索，不自动证明因果。该诊断既不重判 v4 pilot，也不解除第三候选及正式矩阵的门槛。

设计方法参考 Kassis 等人的 [Scientific Agent Skills](https://arxiv.org/abs/2609.00065)（2026 年，当前 v2）中 experimental-design 流程，用于明确观察单位、对照和伪重复边界；没有引用该文作为网络性能证据。候选论文的本节点借鉴和适用限制见[失败原因与既有方法对照](ws26-failure-cause-and-method-gate.md)。
