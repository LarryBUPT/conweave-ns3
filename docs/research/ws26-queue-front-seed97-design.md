## 探针范围与日志

环境开关 `WS26_QUEUE_FRONT_DIAG=1` 开启记录，默认关闭。窗口从仿真时间 2 s 起算。四个 MoE 上游出口 `1382:16`、`1543:10`、`1657:5` 和 `1575:4` 各记录 25 μs；背景反例共有目的出口 `1347:6` 记录 50 μs。出口与窗口均按既有原始时间线事前选定。

交换机成功入队记录 `E`，出队记录 `D`，发送开始记录 `T`，链路关闭时队列清理记录 `X`。每行含时间、交换机、端口、优先级子队列、包 UID、包字节、事件后的出口总队列与子队列字节、负载类别、目的 ToR、四元组的稳定 64 位哈希和包序号。`T` 另含链路下次可发送时间。探针仅读取既有状态、格式化日志；不注册新仿真事件，不改变队列、路由或拥塞控制。QP 哈希仅用于日志关联；已知地址与端口小域时可反查，不具匿名安全性。

受控运行器使用 `--ws26-queue-front-diag 0/1`。开启时必须同时开启已有的 seed 97 时间诊断和 MoE 逐跳诊断，并提供固定 trace。worker 只在该格的仿真进程设置环境开关；关闭时清除继承值。实验元数据记录该参数。worker 在标记成功前核对唯一结束摘要、行数、字节上限，以及 FCT 与 trace 的 QP 四元组、大小和起始时间逐项对应。失败时保留原实验 ID、日志与 raw，并标记失败。

新增 `WS26_QFRONT` 每格最多 400,000 行或 96 MiB；达到上限立即中止该格，并保留失败收据。既有高档格的完整 `config.log` 实测如下，包含原有诊断及其他日志，不是新增探针的独立大小。

## 回放与验收

`scripts/verify_ws26_queue_front.py` 从 `raw/<数字 ID>/config.log` 逐行回放。它校验五个固定出口及窗口、`E/D/X` 的出口总队列和每个子队列字节守恒、同一子队列的 FIFO、`D/T` 的包身份配对、发送结束时刻、端口事件时间顺序、行数与字节预算，以及唯一结束摘要。命令示例：

```text
python scripts/verify_ws26_queue_front.py results/<实验ID>/raw/<数字ID>/config.log --target-uid <末包 UID>
```

窗口开始前可能已有包驻留，脚本按子队列报告初始未知字节和先行出队。窗口结束时可能仍有包排队，脚本报告剩余观测包与出口剩余字节。若目标包入队时仍有同子队列的未知前置字节，脚本将前方组成标为不完整。目标包还必须在窗口内观察到出队，才能用于完整等待链。链路正在发送的包单独列出，不混入排队包。不同优先级子队列和发送中包可能影响等待，不能仅凭 FIFO 列表归因。

主对话复核后，先在相同源码和固定输入上运行关闭／开启探针的 smoke 正确性对照，并要求 FCT 原始文件 SHA-256 完全一致。再做单格资源 pilot，检查日志上限、CPU、内存和磁盘，然后仅考虑 `10/11` 两臂高档诊断。`00/01` 已有原始数据，可作参照，无须自动重跑。每格仍需逐项核对源码 SHA、输入哈希、完整流、既有时间线、探针日志摘要和原始 FCT。任何编译、parity、资源或回放失败均停止推进并修复，不得把部分日志写成完整观察。
