## 资源与可比性边界

16 档逐格资源样本重算：峰值 1 分钟 load **16.06**（门槛 ≤20），最低可用内存 **51.976 GiB**（门槛 ≥32），最低空闲磁盘 **5461.677 GiB**（门槛 ≥100），最大单格进程树 RSS **4561.723 MiB**。按本档最低可用内存再为两格各留 5 GiB 的粗略投影，仍约 **41.98 GiB**；这只是升档依据，18 档每次启动仍由 worker 在锁内做实时准入。终态无活动 ns-3，内存恢复到约 122.94 GiB；检查时没有其他普通用户作业。

两档均复用冻结的 seed05–08 trace、相同仿真 SHA 和传输条件，FCT 为确定性回放；12 档由两个 seed 各六模式构成，16 档由三个 seed 的 16 个格组成，模式数量略有差异。此试跑支持在资源门槛下**试 18 档**，不估计跨负载分布的最优并发，也不把重复格当作新的独立需求。load 是平滑可运行任务数，不能直接当作 CPU 利用率百分比。18 档仍须通过全部预设 ID 的原始核验、资源安全线和同口径吞吐比较；若增益不足 5%，正式矩阵采用前一通过档。

## 执行边界

[原冻结计划](evidence/ws25-resource-capacity-plan.json)中的 18 个 ID 均已预构建；截至本次审计，容量收据没有任何 18 档 `started` 事件，本机没有其正式结果目录。18 档仍用原 SHA、trace 哈希、拓扑、参数和 ID。远程执行前再次核对无其他用户作业、无未知仿真、资源线及 18 个 ID 的 `BUILT` 状态，进入后台静默运行阶段时由主对话实际切到 Luna High。完成后切回 Sol High，从 raw 与 metadata 重算 18 档墙钟、吞吐及全部验收，不使用轮询等待计时做最终选档。
