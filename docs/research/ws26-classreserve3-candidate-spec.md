# WS-26 ClassReserve v3 候选规格

状态：候选机制已实现并完成独立需求高档 pilot；双侧筛选 NO-GO，后续非扰动诊断未支持唯一修正。本规格保留原候选与冻结常量，不构成正式收益证据。更新日期：2026-10-08。本版是 WS-26 最多三个新候选中的第一版。正式 seed、双侧判据和五个原仓库对照保持[执行清单](ws26-classmix-execution-plan.md)中的约定。

## 选择依据与证据边界

WS-25 ClassReserve v1 在正式需求上改善了 MoE 批次时间，但背景 P99 没有稳定改善。v2 的逐包改路产生乱序；v2r1 恢复逐 QP 缓存后，双侧探索仍未过筛。[配对诊断](ws26-paired-tail-mechanism-notes.md)显示，部分最慢背景流在 ClassReserve 下经过同一个可选的上游端口，收到更多 CNP。第二组[时间探针](ws26-time-aligned-tail-probe.md)的四格均通过非扰动与资源验收：64 档五条事后选出的尾流在 ClassReserve 下更早出现上游 ECN 与 CNP；192 档两条同目的主机尾流也出现类似时序。另有一条尾流的标记和反馈更晚，FCT 仍然变差。

这些是已揭盲流上的机制线索，不证明选路造成了尾延迟，也不预测新需求的总体收益。它们足以检验一个不同于瞬时队列的本地信号：**近期仍在发送的背景 QP 在源 ToR 的路径占用**。同一源 ToR 的背景 QP 即使去往不同目的端，也会占用同一上联；同目的端的 QP 还可能共享下游链路。替代解释是不可选的目的端末跳、源端拥塞控制的非线性响应，或 PFC/IRN 设置改变反馈链。独立 pilot 须同时报告支持和反对这些解释的流。

## 冻结的选路规则

新模式名为 `classreserve3`，独立于旧模式 21、22。仅源 ToR 对有 `tag=1/2` 的 RDMA UDP 数据使用新规则；控制包、缺失标签、其他交换机及单路径情况走原 ECMP。两类业务继续使用相同 RDMA QP 模型，不声称真实控制消息与 TCP/UDP 混跑。

背景 QP 始终使用原 ECMP 的源/目的 IP 与端口哈希路径。源 ToR 按四元流身份记录所选上联、目的 ToR 和最后一次看到该 QP 数据包的时间；同一 QP 后续数据包只更新时间，不重选路。这样不会因本模式的背景队列选择，主动改变背景 QP 的 ECMP 路径。

MoE QP 在源 ToR 的首个数据包上，从四元流身份生成两个不同的确定性候选上联。对每条候选上联，统计过去 20 µs 内本源 ToR 见到的活跃背景 QP 数；其中去往相同目的 ToR 的 QP 再计一次。候选分数为当前本地出口排队字节数，加 `8,192 ×（活跃背景数＋同目的背景数）`。取分数较小者；平分时取第一个哈希候选。所选上联按 QP 缓存，后续数据包不得逐包换路。20 µs 覆盖两个时间探针的 10 µs ECN 桶；8,192 字节是本实验单条 MoE 流的固定大小。两项活跃计数分别代表本地上联占用与可能的下游路径重合；不把第二项当成已观测的远端负载。这两个常量在独立 pilot 前固定，不按已揭盲尾流调节。

记录首包双候选数、活跃背景信息非零及同目的背景信息非零的决策数、改选数、两类 QP 新建及缓存命中、源 ToR 各出口的类别包数、失配或退回数，并沿用队列字节守恒检查。只有非零信号与真实改选同时出现，才能说候选规则被有效触发；仅有模式入口不算机制覆盖。

## 可证伪预测与停止条件

独立需求 pilot 应先证明所有输入 QP 完成、身份和字节守恒、两类逐 QP 路径稳定，以及四种 PFC×IRN 设置的传输正确性。背景 QP 与同输入 ECMP 的源 ToR 路径须一致；旧五个基线的路由和 FCT 指纹不因新增模式改变。任一正确性失败先修复，并用新 SHA 和独立 ID 重验。

效果预测是：在背景占用信号非零的需求里，MoE 首包减少与同目的背景 QP 的可选上联重合，背景 CNP/尾流风险下降，同时 MoE 批次时间不因避让而明显恶化。若信号多数为零、改选罕见，或背景 P99 与 MoE 批次不能同时改善，则该本地代理不足以支撑正式双侧收益；按事前 pilot 规则决定一次诊断修正或转向下一个候选。即使 pilot 表现正向，也只能在新 24 seed 和全部预设对照、敏感性格验收后依据 3% 双主门槛判 GO。

本模式只知道本源 ToR 看到的背景 QP，不知道其他源 ToR 在下游端口的负载；不填造 SGLB 的远端队列、利用率或路径质量。不可选的目的主机末跳仍可能主导背景 P99。这些限制须在反例分析中报告。

## 独立 pilot 与尾流诊断结果

v2 高档 28/28 格全流完成，输入、源码 SHA、raw 和资源收据通过；预设双侧效果筛选未通过，低档 24 格未启动。机制覆盖门虽通过，但高档结果不满足同时改善 MoE 批次和背景 P99 的筛选要求。

随后 8 格逐 QP/逐跳复跑全部完成 16,576/16,576 条流，且 FCT SHA-256 与高档对应格完全相同。四个 seed 各 192 条背景流的源 ToR 出口与 ECMP 一致。最大等待位置跨 seed 改变，CNP 总量变化方向不一致，没有得到支持某个权重或路由规则的唯一诊断依据。完整逐流结果见[Handoff 81](../handoffs/2026-10-08-81-ws26-v3-tail-diagnostic-analysis.md)。

本结果不重算筛选门，也不授权自动修正参数。该候选仍作为 WS-26 已测试的第一版保留；后续候选须另有独立机制依据，并按执行清单通过正确性和新的独立需求 pilot 门槛。
