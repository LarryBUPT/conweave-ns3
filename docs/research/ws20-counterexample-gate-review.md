## 证据链与口径

固定仿真源码 `b52e66f0fbf786fb57672b12a5633cf45b9311c1`；需求 seed `20261701–03` 是仅有的三个独立需求单位，ns-3 seed 均为 1。12 个区组、48 格的实验 ID、输入/拓扑哈希和 raw 校验见 [run-map](evidence/ws19-pilot-run-map-v1.json)、[原分析](evidence/ws19-pilot-analysis.json)及 [Handoff 20](../handoffs/2026-09-28-20-ws19-admission-pilot.md)。本审查脚本 [`analyze_ws20_counterexamples.py`](../../scripts/analyze_ws20_counterexamples.py)从其中 ToR/192 的 12 格 `metadata.json`、`raw/<raw_id>_out_ws18.txt` 和 `config.log` 重新按流 ID/四元组连接；对计时原始文件再次验 SHA，核实源码与完成状态，产出[逐轮/逐流/逐跳机器记录](evidence/ws20-counterexample-audit.json)。它只读取本地忽略目录的原始结果，不生成或替换仿真格。`WS13_HOP` 的逐 QP 行按拓扑的源 ToR 上联和目的 ToR→主机端口分类；排队峰值来自包级观测的 QP 汇总，并非同一时刻的全网物理 MMU 占用。

WS-19 的 MoE 主指标是每轮最晚 `finish−最早 demand` 的八轮均值。逐流 `total=finish−demand=wait+(finish−release)`，所以低单流平均不能替代轮尾。背景 P99 是 192 个全部完成背景流的线性插值，靠近第 190/191 小值；它不是某一条“P99 流”。本次完成率和字节守恒均已通过，故这里的 P99 没有完成者截尾问题，但仍只适用于该人工负载。

## 观察到的反例

| --- | ---: | ---: | ---: | ---: | ---: |
| 20261701 | +4.344 µs | 7/8 轮 | 14.268–17.876 µs | +197.345 µs | 92/72/28 |
| 20261702 | +4.739 µs | 8/8 轮 | 10.824–14.104 µs | +10.737 µs | 84/92/16 |
| 20261703 | +4.219 µs | 8/8 轮 | 12.300–15.416 µs | +38.601 µs | 94/84/14 |

三 seed 的联合臂全 24 轮均慢于 ECMP；逐轮对齐见机器记录。源端准入在 ToR/192 的每格对约 14,339–14,347 条 MoE 流产生正等待，而背景 192 条全部等待为 0。准入/联合使 MoE 完成者的网络段均值从 ECMP 的 `4.686–5.381 µs` 降至联合的 `2.165–2.189 µs`，但联合轮均从 `16.241–20.186 µs` 升为 `20.980–24.530 µs`。这直接否定“网络段均值降低便可改善轮次”的替代口径。准入代码在 [`ScheduleFlowInputs`](../../scratch/network-load-balance.cc) 对 tag=2 按目的主机维护 `next_release`，以 400 Gbps 名义服务时间串行放行；tag=1 背景未被延后。路径代码在 [`DoLbWs18`](../../src/point-to-point/model/switch-node.cc) 对跨 ToR 的 tag=2 流首次采样两个上联端口负载，并将选口固定到流结束；背景仍走 ECMP。上述源码解释了开关的直接动作，并不单独证明尾部损害的完整因果链。

尾流身份与等待的例子：seed `20261701` 最后一轮 ECMP 尾流 ID 15176、22.074 µs；联合尾流换为 ID 16512、37.654 µs，其 `wait=15.088 µs`、`network=22.566 µs`，同 ID 在 ECMP 的 `total=17.346 µs`。seed `20261702` 第一轮联合尾流 ID 2096 为 32.021 µs，`wait=11.644 µs`、`network=20.377 µs`，同 ID 的 ECMP 总时延 13.863 µs。两例均有等待与网络段共同变化；把联合结果简单减去等待当作“无准入反事实”会忽略网络时序的改变。

背景尾部也有同 ID 和位置反例。seed `20261701` 联合 P99 附近的 ID 44 从 ECMP 2574.431 增到 3509.617 µs；同一 QP 的目的主机出口包等待最大值从 12.068 增到 17.694 µs，队列前字节最大值从 634,312 增到 928,976 B，而源 ToR 上联等待峰值仅 0.251/0.258 µs。seed `20261702` ID 52 从 2352.557 增到 2543.627 µs，目的出口峰值 5.425→6.736 µs。seed `20261703` ID 64 从 2324.760 增到 2557.309 µs，目的出口峰值 7.176→8.659 µs；同 seed 的另一尾部流 ID 188 虽然目的出口峰值升高，其 FCT 却缩短 3.941 µs。这支持“目的出口竞争与尾部损害同现且存在反例”，不支持“排队峰值单独决定 FCT”。背景最慢流身份在 seed `20261701/02` 的 E 与 J 间改变，seed `20261703` 保持 ID 64；P99、最大与逐流差须并列看。

路径单臂在 ToR/192 三 seed 的背景 P99 相对 ECMP 分别改善 `467.097/78.451/101.097 µs`，但轮均为 `−0.185/+0.129/+0.046 µs`，联合比仅路径慢 `4.529/4.610/4.173 µs`。源端选口计数表明路径分支触发，却没有保存每条 MoE 轮尾流的实际端口、沿途排队和到达时序；既不能据背景改善把联合机制判为有效，也不能排除其他端口竞争或反馈时序解释。

## 可证伪解释与缺失观测

1. **固定逐目的串行准入压低平均网络段，却推迟该轮最后一批 8 KiB 流。**可检验预期：轮尾 ID 的 release 次序靠后，等待与总尾部差同向；在不引入下游拥塞的边界输入中放宽/旁路准入后，轮尾应缩短，而网络段拥塞收益可能缩小。已有数据支持“等待存在、尾流换位、轮均反向”，不识别放宽准入后的反事实。当前按目的主机 400 Gbps 记账，没有真实可用出口容量或在途字节反馈。
2. **上游路径/放行时序改变背景与 MoE 在唯一目的出口的竞争，进而经 ECN/DCQCN 反馈影响背景长尾。**可检验预期：损害流的包到达/出队时间、目的出口队列轨迹、CNP/发送速率变化在时间上对应；同输入仅改变准入的对照须显示可区分的时序。已有 `WS13_HOP` 仅为每 QP 逐跳包等待的总和/峰值，`WS13_QP` 只有部分反馈事件，主机 CNP 另有聚合计数；缺按时间连接的单 QP 发送速率、重传/丢包、完整上下行路径和 MoE 尾流跳点。峰值差是几微秒，FCT 差可达数百微秒，不能由数值大小直接归因。IRN×PFC 的历史压力不完整格亦不能用来填缺口。
3. **需求相位、ECMP 哈希和共同 ns-3 seed 也可能影响尾部排序。**三条需求各自重抽端点，但每 seed 内 8 轮是同步生成且共享拓扑/传输，0→192 同时增加总字节。24 轮不是 24 个独立重复，背景 192 流亦非 192 个独立负载。后续须在新需求 seed 中复现反例，并在同输入随机化臂顺序；不能用旧顺序置换补样本。单次非扰动观测开/关 pilot 仅证明既有诊断未改变该输入的 FCT 指纹，新增观测也需重新证明非扰动。

## 研究决定

**有理由另写一个条件性、双侧的探索小样设计；尚无理由启动或冻结新效果矩阵。**优先修订“可观察性 + 有界准入”而非继续调整上游哈希评分：准入已经直接损害 ToR 轮尾，路径单臂未给出稳定 MoE 增量，目的出口是不可绕行的共享末跳。下一版先证明新观测非扰动、准入何时旁路有可实现的输入信号，并让候选在未见过的需求上同时对照 ECMP、仅路径和旧联合臂。具体可审查方案见[WS-20 后续探索设计草案](ws20-next-exploratory-design-v0.md)。它不是事前协议、仿真授权或业务 SLO。导师/业务方若不能提供训练轮次/背景服务的重要性、损害容忍与真实需求分布，仍只报告双侧连续权衡，不宣称部署安全。
