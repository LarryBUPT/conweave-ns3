# WS-17 瓶颈可控性与独立需求审计

记录：2026-09-28。性质：**本地源码、拓扑、旧原始 ID 复核与新输入静态构建**；没有新仿真或机制收益。分支 `feature/ws17-bottleneck-demand` 从已核验个人 `origin/research/post-ws16-mechanism-directions@5cf603abdec4ec3d37f400cae82b30eb6ec8751d` 分出。旧 WS-10/11/12 no-go 与 WS-14 停止规则不变。

## 事前问题、资源和停止条件

主问题是：对于同一批有原始需求时刻的 MoE 与背景流，发送端错峰能否降低唯一目的主机出口的瞬时争用，而上游路径分担只处理可绕行的拥塞？可证伪预测为：在**同输入、同总字节、同传输条件**下，路径单开在主机唯一出口热点不应凭空增加容量；准入单开即使降低交换机等待，也可能把等待转到源端；联合方案须相对两种单开对 MoE 从需求起点算的轮次完成时间和背景尾部给出可解释增量，且不牺牲完成率。任何一侧恶化、源端等待被漏计、或仅在理想下游信息下改善，均不能称联合机制收益。

本阶段停止条件：若源码/拓扑显示无可控制的发送时刻，或跨 ToR 没有可替代路径，停止相应原型；若现有数据缺口须靠远程探针回答，先冻结最小探针输入、观测、对照与终止条件。此次静态审计足以判定资源可控性与输入规格，故**没有启动远程探针或效果矩阵**。

## 源码和拓扑核对

`config/topo_1280_400G_400G_OS1.txt` SHA-256 为 `74a6f7154ca10c3cd6dfd45046c4f8abf0ce27faa8ad11446b6a52920b83afba`。逐边解析：1856 节点、3840 条 400 Gbps 链路；1280 台主机全部度为 1；160 个 ToR 各接 8 台主机和 8 条非主机链路。生成输入选出的三条跨 ToR 样例，源 ToR 到目标有 8 个等跳最短下一跳，目的 ToR 到目标主机仅 1 个，见[输入 manifest](evidence/ws17-demand-manifest.json)的 `route_audit`。这核实了**上游路径可分担、固定目标主机最终出口不可绕行**；不能把 8 个上游选择写成 8 倍目的容量。

`scratch/network-load-balance.cc::ScheduleFlowInputs` 按六列 trace 的 `start_time` 安装客户端，`RdmaClient::StartApplication` 随即调用 `RdmaDriver::AddQueuePair`；`RdmaQueuePair` 构造函数把 `startTime` 设为当前仿真时刻。`qp_finish` 输出 `startTime` 至完成的 FCT。当前没有独立保存“业务需求出现”与“准入放行”两个时刻；如果以后通过延后安装 QP 实现准入，原 FCT 会漏掉源端等待。因此 WS-18 必须新增不随释放时刻改变的 `demand_ns`/稳定 flow ID，在逐流原始结果中保存 `demand_ns ≤ release_ns ≤ finish_ns`，并同时给出等待 `release−demand`、网络完成 `finish−release`、用户所受完成 `finish−demand`。轮次完成从该轮**原始需求时刻**至该轮最后一条流结束，缺失流不得从最大值或 P99 中静默剔除。

`SwitchNode::SendToDev/GetOutDev` 在源 ToR 按当前包、路由表和本地真实出口队列选路，`DoSwitchSend` 在已选出口执行 MMU 准入、随后进入设备队列。源端在发起前知道输入目的和需求数；源 ToR 的本地队列在选路时可见。**目的 ToR→主机出口的即时队列**只有包抵达目的 ToR 后直接可见，当前发送端/源 ToR 没有可用的零延迟真值；CNP 经传输反馈后到达，且目前缺全流逐 QP 的可靠即时速率、NACK/超时和物理 MMU 总占用。因此方向 1 的首个准入规则只能依赖本地已知需求、容量和经明确成本/年龄标记的反馈；不能把事后目的队列写成发送时刻已知信息。方向 2 若用下游反馈，需另测传递时间、状态和开销。

## 原始证据与因果边界

- `scripts/analyze_ws13_feedback_probe.py` 从四个 `20260927-160000-ws13-feedback-*` ID 重算通过，原始 192 档两个模式每格 16,576 流全完成且共享 trace SHA `bf1a1960…5d9c8a`；所选慢背景 QP 在目的 ToR 出口出现约 3–4 µs 最大排队等待并收到 CNP，未观察到 SACK。它定位了包路径及反馈**相关性**，没有随机干预或分解唯一成因。
- `scripts/run_ws14_small.py verify` 从七个 `20260927-233000-ws14-*` ID 核验 7/7。192 档 ECMP/普通双候选/GuardHash 的 MoE 批次为 18.920/19.099/19.651 µs，GuardHash 背景 P99 为 1431.183 µs，但最慢背景流身份转移，目的出口最大等待未一致下降。因此继续执行旧停止规则，不做中档补判。
- `scripts/analyze_ws13_calibration.py` 与 `scripts/make_ws13_calibration_traces.py --verify` 从三个独立需求 seed `20261301–03` 的六个旧 ID 复核 `complete=true`；ECMP 背景 P99 范围 1292.771–2179.572 µs。这三条是旧校准数据，**不作为 WS-17 新需求或以后确认性重复**。WS-13 压力 11 格仍只有 13/16 完成，不能当性能对照。

这些旧 ID 不操纵发送时序，也不隔离目的出口与其他跳。目的排队和 CNP 可能是长尾的一部分，但不能凭共现计算“准入可改善多少”。

## 可重生的独立需求与测量契约

[`scripts/make_ws17_demand.py`](../../scripts/make_ws17_demand.py) 以独立 RNG seed `20261701/02/03` 分别重抽 256 个 rail-0 专家源、每轮普通目的、192 条背景源/目的与热点 ToR/主机。每源每轮 8 条 8 KiB MoE 流，8 轮、轮距 50 µs，共 16,384 条；背景为 0 或额外 192 条 8 MiB 流，在第一轮同时出现。每轮前 2/8 的目的集中到一个主机（`host_hotspot`，热点主机自身作为源时改投同 ToR 另一主机以避免自发自收）或同一 ToR 的多个主机（`tor_hotspot`）；其余目的及背景中非热点部分重新抽样。三 seed 对应不同成员、热点和字节级 trace，不是旧流记录的行顺序置换。热点是人工压力布局，不是实测训练作业轮次；仅 rail 0，不能推断多 rail 或真实 job CCT。

每 seed 的两种热点、0/192 背景构成配对输入，**独立推断单位仍是 seed，只有 3 个静态设计样本**。0 与 192 档保持同 seed、同热点的 MoE 需求不变，追加背景会增加总提供字节。输出的 12 份六列 trace 与逐流 `demand_ns` sidecar 位于忽略目录 `results/ws17-demand/`，完整 SHA、规模、热点与跨 ToR 路径审计在[manifest](evidence/ws17-demand-manifest.json)；清单自身 SHA-256 `0513d4b0f2cadea768220739fe8eadcd71e636f8ca763b9c6cf84fe233fead5a`。`python scripts/make_ws17_demand.py --verify` 已逐字节重生并核验 12 对资产。sidecar 带输入顺序、源/目的、按当前解析器顺序预期的端口、类别、轮次和原始需求时刻；**端口仅用于旧模式静态配对，未来准入改变安装顺序时须以稳定 flow ID 为准**。这些 trace 尚未进入仿真，哈希证明可重生，不证明行为或效果。

WS-18 最小正确性与 WS-19 小样在运行前须另外冻结共同源码 SHA、上述输入 SHA、拓扑、仿真 seed、DCQCN/PFC=0/IRN=1、调度参数、运行顺序及资源条件。同一需求做 ECMP、仅准入、仅路径、联合四臂；仅路径必须使用与联合相同的上游候选与状态预算，另列普通双候选/DRILL 等强对照，避免把信息预算差写成联合收益。两个热点布局同时报告绝对 MoE 轮次/合成批次、背景逐流 FCT 与 P95/P99/最大值、所有类别输入/完成数和字节、源等待分布、目的及上游出口排队/丢包/ECN/CNP、NACK/超时及控制开销。P99 只在完整完成门禁后解释；任何 8 MiB 背景尾流转移都逐流报告。无可核验业务 SLO 时只画连续权衡和研究性停止条件，不设新的通用百分比安全线。

## Go / no-go

**Go：只对 WS-18 的最小机制与计时正确性工程开放。**发送时刻在应用/QP 创建前可控制；跨 ToR 上游有等跳候选；新需求可独立重生且原始起点/双侧指标可定义。**No-go：路径单开解决唯一目标主机出口容量、利用现有 FCT 宣称准入收益、直接启动 WS-19/20 效果矩阵。**目的出口真实排队的发送前可见性和准入因果收益尚未证明；必须在 WS-18 建稳定 ID 和三时刻计量、四臂正确性及强对照，并核验全流完成，再决定是否做双侧小样。此决定不重判任何历史 no-go。
