四格均为 16,576/16,576 流完成，即 16,384 条 tag=2 的 MoE 流与 192 条 tag=1 的背景流全部完成。四格 `_out_pfc.txt` 均为空文件，说明本轮共享参数（PFC=0）下没有 pause 事件；CNP 计数只来自 ECN 标记，乱序 CNP 均为 0。

四格的最低可用内存为 113.82～118.14 GiB，最低可用磁盘为 4,734 GiB 以上，均高于资源门禁（内存 32 GiB、磁盘 100 GiB、1 分钟负载 20）。GuardHash v2 与 HarmGate v2 的 QP 新建加复用正好等于 MoE 包总数，说明逐 QP 固定路径按设计生效，没有出现未命中缓存的回退路径。

## 能说明与不能说明的内容

本次四格在机制层面成立：两种新模式都对 MoE 生效、对背景回退 ECMP，包级计数守恒，队列计数守恒；背景只在早于 MoE 起始时使用的资源上与原 ECMP 有少量差异，没有出现额外丢包或暂停。

本次四格不能支持效果结论。单条输入、单一 ns-3 seed 的批完成时间差分从 −7.0% 到 −10.8%，但这类单 trace 差分在 WS-11 与 WS-14 中方向相反且幅度远大于正式矩阵的中位数，说明它主要由该 trace 的哈希落点决定。批完成时间只有十几微秒量级，任何对最后一条 MoE 流的数十纳秒级扰动都会显著改变比值。三格运行时的并发上限分别为 2、2、1，虽然 WS-25 资源 pilot 已验证同输入 FCT 指纹不随并发变化，仍应把并发差异记入工程条件而非效果解释。

因此，是否在独立需求 seed 上具备可复现的正向效应，只能由筛选与确认阶段回答；本报告不提供该结论，也不用于调整候选、评分权重或门槛。

## 参考借鉴复核

本节点已按项目要求复核 DiffFlow（arXiv:1604.05107v1）、DeFlow（Computer Networks 257，2025）与 SeqBalance（arXiv:2407.09808v1）的技术附件与核验记录，另在累计阅读文档中核对 ECMP RFC 2992、Fastpass 与 DRB-TTC 三条条目。

可借鉴的部分是批完成时间的口径与代价报告方式。SeqBalance 用父请求的最大子请求完成时刻定义完成时间，与本轮用全批最后完成时刻定义 MoE 批完成时间一致，因此本轮同时报告单流 P50 与 P99，避免只用平均值掩盖尾部。DeFlow 把乱序代价与换路时机一起分析，本轮据此逐格报告乱序 CNP 与队列守恒，而不是只报 FCT。DiffFlow 的分类粒度提醒本轮须先确认逐 QP 固定路径是否真的被复用，本轮用新建与复用计数直接验证，而非推断。

不能外推的部分是它们的收益数字与硬件条件。三篇候选的流量分布、传输协议或硬件前提与本轮不同，且都没有报告 MoE 批次完成时间与背景 P99 这两个指标；它们的作者结论不构成本项目的效果证据。三篇候选也不因此自动成为最终引用。
