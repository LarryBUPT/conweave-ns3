## 机制、信号与生命周期

v1 保留 ClassReserve v1 的两候选、候选盐、类别本地评分和每跳 QP 出口固定。仅源 ToR 的新 QP 决策可消费状态。CE 是包沿全路径得到的 ECN 标记率，包含共同目的出口；它不是首跳专属拥塞或下游真实队列。两候选别名、共同出口标记和不可区分样本分别记录。

两个不同候选都满足下列条件，才允许比较 CE 比例：非零样本；windowEnd 不在未来；决策时样本年龄不超过 20,000 ns；当前接收会话的样本；物理链路 up；邻接已收到当前心跳会话的有效 ACK；邻接非 UNKNOWN；最近有效 ACK 不超过 800,000 ns。比例用 64 bit 交叉乘法比较。比例相同则采用原本地评分；任何资格缺失均退回本地决定。每个决策保留两份 windowStart/windowEnd、样本数、CE 数、producer session、sequence、资格原因及本地/建议/实际出口。

STATE 聚合间隔固定 10,000 ns，心跳固定 200,000 ns。两样本时间窗可不齐，逐决策记录这一事实，不做未声明的插值或对齐。接收端仍以“生成至到达不超过 10,000 ns”拒收过期报告；缓存还要在决策时按 windowEnd 再次验龄。上述值是 v1 工程起点，不是最优值或业务 SLO。

STATE v3 增加 32 bit producer session 和 64 bit windowStart，负载由 v2 的 26 B 增至 38 B。模拟封装后的实际包长预计由 60 B 增至 72 B，最终以入队 raw 为准。HELLO/ACK 负载仍为 10 B，模拟实际包长为 44 B。旧 v2 默认路径保留，并安排同输入行为回归与头部单测。

producer session 单调递增；接收端保留每个目的/候选的 incarnation 高水位，旧 session 被拒。序号到达 `UINT32_MAX` 后进入新 session，从 1 重新计数，不在同 session 回绕。接收控制会话重启会清空缓存，并拒绝 windowStart 早于重启时刻的报告；producer 高水位保留。旧 Flush 和心跳 Tick 不能更新新会话；心跳 epoch 隔离旧 ACK。这里模拟控制会话重启，不声称覆盖主机进程崩溃、持久存储丢失或硬件重启。

缓存及 incarnation 高水位各以每 ToR 16,384 键为上限。无样本不当作零拥塞。STATE 接收、心跳会话与物理链路是三条不同状态链；UNKNOWN 仅取消反馈资格，不能直接当作物理断链。

## 对照与共同链路处理

| 臂 | 参数 | 状态与报文 | 实际决定 |
| --- | ---: | --- | --- |
| C0 | `--ws29-arm 0` | 身份及决策观测开启，STATE/心跳关闭 | ClassReserve v1 本地规则 |
| C1 | `--ws29-arm 1` | 联合控制正常发送、接收和缓存 | 本地规则；记录潜在采用结果 |
| C2 | `--ws29-arm 2` | 与 C1 共用控制实现 | 合格时消费状态，否则本地退回 |
| STATE-only | `--ws29-arm 3` | 发送 STATE，心跳关闭 | 本地规则 |
| 旧版回归 | `--ws29-arm -1` | WS-21 原参数，v2 | WS-18 原路径 |

C2−C0 衡量包含通信代价的总增量；C1−C0 衡量自然控制扰动；C2−C1 仅说明闭环采用的系统差异。改路会改变后续采样、活动端口和报文时序，不能宣称 C1/C2 的通信扰动逐包相消。ECMP 只提供语境。

所有 WS-29 臂共用物理 down 过滤和 QP 缓存失效逻辑。缓存出口已不可用时重新执行同一臂的首决策规则；可用旧 QP 保持原出口。所有候选都 down 时明确丢弃、记包长并等待传输恢复，不任选失效端口。链路 down 的已排队包通过既有 MMU/类别队列丢弃路径逐字节释放；取消旧 PFC resume 事件，恢复时重新确认邻接。

工程故障仅改变源 ToR 直接相连的交换机上联两端，不调用旧 `TakeDownLink` 的全网路由重算，不把路由重算算作反馈收益。协议传输固定 PFC=0、IRN=1；没有验证 PFC=1 或任意远端链路故障。两端物理事件、队列丢弃、传输恢复与反馈资格分别保留收据。

## 观测、验收和停止线

`WS29_DECISION` 逐首决策记录样本与采用理由；`WS29_ACK` 记录实际有效邻接确认；`WS29_STATE_SEND/CACHE` 记录报告身份与窗口；`WS29_CONTROL` 记录逐类型、逐链路入队/出队/丢弃字节；`WS29_QP` 记录应用输入与实际发送 payload。复用 `WS25_QP` 的接收 OoO 包、SACK/CNP、重复发送与超时恢复计数。接收缓冲峰值和独立 NACK 字节未补测，不填零。诊断仅增加记录，不添加网络事件；C0 行为回归检验适用范围内的非扰动。

冷启动审计已读取旧 24 个主档 raw，全部 QP 在同一需求时刻发起。旧 raw 没有首决策时戳，因此实际双新鲜状态比例仍未知。新验收器逐条复算 CE 比例、决策年龄、本地/建议/实际出口及有效 ACK，核对跨 ToR QP 覆盖。报告分别给出记录决策数、two_fresh 数与比例、would_change、adopted_changed；样本单位不混淆。自然流量若没有采用机会，记录这一机制缺口，不用合成格抵补。

入口为 `scripts/verify_ws29_engineering.py --plan <计划> --results <原始目录> --id <固定ID> --output <新收据>`。验收器拒绝覆盖不同的旧验收输出。源码和头部的实际单测由远端 `devices-point-to-point` 套件执行；本地只通过 Python 语法、参数链审查、diff 检查及 5 项证据验收器测试，不能据此称 C++ 单测通过。

资源阈值固定为单进程树 RSS 不超过 32,768 MiB、可用内存至少 32 GiB、空闲盘至少 100 GiB、1 分钟负载不超过 20、单份文本日志不超过 50 MiB。WS-29 事件上限 500,000 行，heartbeat 既有事件上限 20,000 行；overflow 必须为 0。逐点资源采样与终态摘要必须齐全。初始串行、每份构建 `-j2`；本协议不授权跳过资源 pilot 提高并发。

执行顺序为：固定源码 optimized 构建和单测 → 旧 v2 与 C0 两项回归 → 小拓扑协议/链路/采用退回 → 同输入联合主档成本。任何编译失败、指纹不符、身份错误、未完成流、守恒错误或资源越线，立即保留原 ID 并暂停后续格，定位后用新 SHA/新 ID 重验。不删除失败数据，不放宽预期。全部工程格和资源验收通过后，再审自然采用机会；独立 pilot、资源阶梯与正式矩阵另行冻结。
