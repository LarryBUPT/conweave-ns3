# WS-25 候选 v2：目的地分散的包流混合选路假说

状态：**候选机制已实现，12/12 个冻结正确性小格及 1 格同输入非扰动诊断验收；独立需求探索筛选 28/28 格已验收且双侧未过门槛**。日期：2026-10-06。筛选分析和唯一一次 v2 诊断修正决定见[报告](ws25-v2-independent-screen-analysis.md)；尚无 v2 正式效果证据。v1 正式 NO-GO 和其 24 个已揭盲需求不因本文改变。第一课题累计候选 v1=1/3、v2=2/3；v1 唯一诊断修正已用，v2 最多一次诊断修正。

## 从已见数据提出问题

在 v1 的正式 192 档，ClassReserve 对 ECMP 的 MoE 批次时间中位 −3.536%（20/24 改善），背景 P99 −0.065%（13/24 改善），未过共同主门槛。**事后描述**显示原 DRILL 模式对 ECMP 的 MoE 中位约 −13.637%、24/24 改善，却使背景 P99 中位约 +4.620%，只有 3/24 改善。它提示不同类别可能需要不同的选路粒度，不能把这两个独立全模式结果拼接成一个已经测得的混合收益。下述描述数字由[机器审计](evidence/ws25-v2-hypothesis-inputs.json)从正式逐格表和两格诊断重建。

两格已揭盲 v1 诊断中，背景首次双候选决策的本地两出口队列均为空分别为 85/98（64 档）和 179/312（192 档）。在这些时刻 v1 的瞬时队列信号不能区分候选端口，固定哈希容易主导背景长流的首次选路。尾流的 CNP 反馈与部分目的出口排队同现，且 192 档最差尾流的目的出口累计等待并不高于其余流，因此不能宣称这个空队列现象已解释背景 P99。跨五种现有完整模式逐 seed 事后选最优背景 P99 的虚拟包络，中位也仅约 −3.092% 对 ECMP；它不是新机制的性能上界，只表明简单从已测整臂挑选难以构成可信双侧方案。

## 可证伪机制

候选名称暂定 **DestSpread Hybrid**，仅使用当前交换机的本地数据，不引入下游状态报文；因此不与投稿后的第二课题混用。

1. `tag=2` MoE 数据包采用原 DRILL 的本地多候选短队列选择粒度，以争取正式数据所提示的批次时间空间。必须保留类别身份、路径合法性和独立观测，并明确其逐包改变可能引发 RDMA 乱序；不能把 v1 的逐流缓存安全性移植过来。
2. `tag=1` 背景流**仅首包选路**，其后逐流缓存。首次选择在可用下一跳中取本地总队列最短者；同样最短时，以每个目的地址的轮转指针分散背景长流，避免所有空队列平局由固定哈希决定。轮转只在首次分配时前进，不能按包轮转。单下一跳、未知标签和控制包仍走既有合法回退。
3. 观察链分别记录 MoE 逐包选择与重复发送/乱序反馈，背景首次选择中的空队列平局、轮转分散度、按流复用、目的跳等待/CNP，以及两类完成率和 FCT。轮转计数只是机制触发证据，不代替背景 P99 改善。

**失败预测：**MoE 逐包变化可能触发乱序、NACK/重传并抹去批次收益；背景流即使在上联被分散，最终仍在唯一目的主机出口汇聚，P99 可能继续近零或恶化。若这些情况出现，应保留负结果而非改动已揭盲 v1 seed 或放宽共同门槛。当前方案不设新的业务 SLO；v2 的数值门槛、样本量和统计方法须在独立校准后、最终需求揭盲前另行冻结。

## 准入与验证顺序

先做代码审查与本地单测：在新的模式号/独立源码 SHA 下检查单下一跳、未知标签、按流背景缓存、空队列轮转、MoE 路由分支及旧五模式回归。用新实验 ID 的小拓扑单类/混合输入验证完整完成、字节守恒、路径和队列账目，尤其核对 MoE 乱序、NACK、重复发送与超时；正确性失败时保留 ID/raw，允许该候选至多一次诊断修正。随后以**未用于 v1 筛选、校准或最终验证**的独立需求 seed 做筛选和资源 pilot，并与五原始模式同输入配对。若技术和双侧方向均支持继续，再在新的预注册文件中冻结正式 seed/trace SHA、算法 SHA、全部 ID、共同双主判据、低档约束、次级多重比较、资源线和停止条件。正式数据未产生前不写任何 v2 收益结论。
