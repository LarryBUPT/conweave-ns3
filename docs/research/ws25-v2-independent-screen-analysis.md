## 路径诊断与反例

源码中 `tag=2` MoE 每包调用原 `DoLbDrill`；`tag=1` 背景流在每个交换机首次选择本地最短队列、平局时按目的地址轮转，之后逐流缓存。四个候选主格的 `queue_violations=0` 且无 fallback；诊断开关未改变 FCT。因此计数支持两条代码路径确实执行，但不直接给出端到端因果分解。

四个非扰动诊断格分别记录 **5,931–6,818** 个 MoE 接收端乱序包、**6,039–7,013** 次重复发送；有乱序的 MoE QP 为 **4,607–5,119/16,384**。对应 SACK 反馈为 6,283–7,292 次。小输入诊断曾全零，此次全量需求直接推翻了“小输入无乱序即可安全逐包选路”的外推。MoE 在四 seed 对原 DRILL 也均较慢，说明直接调用 DRILL 分支并未保留整臂 DRILL 的本次批次表现；乱序及恢复代价是有力线索，但没有“关闭乱序而只改这一因素”的同输入对照，不能定量归因。

背景流的逐流配对 FCT 差值中位仅为 **+0.236、−0.242、−0.907、−1.991 µs**，而每个 seed 最差单流恶化 **+2,546.6、+1,226.1、+1,239.6、+1,170.7 µs**。seed45 最差三流都到主机 `756`；seed47 最差两流到 `1236`；seed48 最差两流到 `1000`。这些尾流的候选 QP 分别有 CNP 反馈，12 条最差流均无接收乱序、SACK、重复发送或超时恢复。故背景 P99 恶化由少数尾流驱动；不能用背景大多数流接近不变来替代共同主结果。目的端汇聚与 CNP 同现，不证明具体某个源上联选择或末跳队列是唯一原因，也不能将 CNP 计数直接换算为 FCT 增量。

四格背景首次选路中，各有 **80–83** 次“所有候选队列为空”的平局，记录的首次选择总数为 **872–876**，表明轮转分支确实遇到空队列情形，但该观测和 P99 改善没有形成同方向证据。背景缓存复用约 731–735 万包/格；标签 1 的 QP 没有乱序或重复发送。即使保持逐流路径，背景尾部仍可能受到汇聚及另一类流的额外流量影响。目前没有与 ECMP 对齐的逐 QP 速率/队列时标，不能断言 MoE 重传是背景尾部恶化的唯一原因。

本次最高单格 RSS **4,562.44 MiB**、最低 MemAvailable **105.04 GiB**、最低空盘 **4,926.93 GiB**，逐格资源线通过。runner 在全部 raw 验收后退出；恢复过程中保留原 ID 和 raw，没有覆盖或重复运行。

## 迭代决定

第一课题候选台账为 v1 **1/3**（一次诊断修正已用）、v2 **2/3**（尚有一次诊断修正）、第三候选尚未启动。v2 原方案未过探索门；不打开校准或正式矩阵。两类退化可能共享逐包 MoE 乱序/恢复这个上游因素，故先使用 **v2 唯一一次诊断修正**：仅将 MoE 改为每 QP 首包按 DRILL 本地选择、后续在该交换机逐流缓存；背景首次选择/轮转/缓存不改，控制包与未知标签继续 ECMP 回退。该修正首先针对可观测的 MoE 乱序，不预设背景 P99 必然改善，也不在已见 seed45–48 上调参。

修正版必须用新源码 SHA、独立 ID 先做小输入正确性和非扰动诊断，再用与已有筛选、校准、正式池均不重合的新需求 seed（拟 `20262577–80`）另冻四 seed 同输入六臂探索筛选。只有两项重新满足预设方向门，才可使用仍未见的 `20262549–52` 做校准 pilot、再决定是否冻结 `20262553–76` 的正式矩阵。若修正版失败，v2 修正额度耗尽，保留负结果并评估第三候选；不得再修 v2、放宽门槛、用校准代替正式证据或并行第二课题。

复算命令：`python scripts/analyze_ws25_v2_screen.py`。脚本重验 28 格 raw，输出[机器结果](evidence/ws25-v2-screen-analysis.json)。
