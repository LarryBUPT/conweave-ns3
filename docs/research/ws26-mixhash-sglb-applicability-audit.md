# WS-26：MixHash 与 SGLB 机制适用性审查

日期：2026-10-07。用途：为 WS-26 的单一主候选选择提供源码和文献边界；这里没有新仿真结果，也不将参考模式加入正式对照。

## MixHash 源码核验

只读参考仓库 `maplerime/conweave-ns3` 的 `switch-node.cc::DoLbFlowECMPWithCounter` 将源/目的 IP、端口和 `ecmp_counter % reorder_queue_num` 一起哈希，按计数位置分散同一 QP 的包。`rdma-hw.cc` 仅在模式 16 给每个发包递增该计数；模式 16 的交换机分派对所有数据包使用计数哈希，控制包退回普通 ECMP。`ProcessReorderBuffer` 位于目的 ToR，但显式排除 `tag=2`；因此不能将其接收重排保护概括为覆盖全部 MoE 包。`run.py` 关于 tag 分流的注释与实际交换机分派不同，设计依据以源码执行路径为准。

这种分散可作为“多路径机会”的启发；包级换路还会产生乱序、接收缓存和恢复代价。WS-25 v2 的全量需求已观察到 MoE 乱序与重复发送，v2r1 消除这些计数后仍未过双侧筛。WS-26 不直接复制 MixHash 的计数哈希或目的 ToR 重排实现，也不把它列为正式第六个基线。若将来考虑细粒度分散，必须逐 QP 核验完整性、乱序、重传和批次尾部，并在新需求上独立验证。

## SGLB 五项路径质量

[SGLB 原论文](https://doi.org/10.1145/3718958.3750527)定义加权路径质量：`V = α₁Q(L) + α₂L(L) + α₃Q(R) + α₄L(R) + α₅B(R)`。`Q(L)`、`L(L)` 分别是本地出口队列与链路利用率；`Q(R)`、`L(R)` 是下一跳对应状态；`B(R)` 是下一跳各出口平均队列，表示下一跳后续路径的平均繁忙程度。论文还按质量分级保留多个较优路径，以减轻所有流同时追逐单一路径造成的振荡。上述定义已在[论文全文的可访问副本](https://www.scribd.com/document/981638832/Sigcomm2025-LoadBalance)第 4.1.3 节与式（1）核对；ACM 正式 PDF 在本次检索环境返回 403。[SIGCOMM 会议摘要](https://conferences.sigcomm.org/sigcomm/2025/program/papers-info/)明确其依赖跨交换机的全局拥塞状态及控制面。

| 因子 | 当前个人 fork 的可观测性 | 对 WS-26 的决定 |
| --- | --- | --- |
| `Q(L)` | `SwitchNode::CalculateInterfaceLoad` 可在决策时读本地出口队列；WS-25 v1/v2 已使用 | 可作为诊断量，但单独使用已不足以预测背景尾部 |
| `L(L)` | `_out_uplink.txt` 提供采样累计发送字节，可事后算窗口利用率；当前路由决策没有同口径的在线利用率窗口 | 先做非扰动在线量与事后采样的口径核对，不能把全程累计值直接当瞬时负载 |
| `Q(R)` | 当前候选分派无下一跳逐路径新鲜队列状态 | 不在 WS-26 假设为已知，不能取本地队列或零值代替 |
| `L(R)` | 当前候选分派无下一跳在线利用率与年龄收据 | 不将缺失状态填零或使用事后全程统计作为在线输入 |
| `B(R)` | 当前候选分派没有下一跳所有相关出口的平均队列与目的条件 | 不直接移植该项；末跳唯一出口也无法由源 ToR 的局部均衡消除 |

后三项若要用于在线决策，需要新增状态传播、时效和采用/退回语义，会进入 ADR-010 规定的投稿后反馈第二课题。WS-26 只借鉴“局部空队列可能遮蔽后续瓶颈”的问题定义，先通过 ECMP 与候选同输入诊断判断可控上游路径是否解释尾流，再选用本地可观测且不同于 v1/v2 的信号。不能为了套用五项公式而无依据地选择权重。
