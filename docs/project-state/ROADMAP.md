# 下一阶段路线与停机条件

更新：2026-09-24。集成工作流只维护顺序和证据门槛；具体代码和实验在对应 workstream 执行。参照 [CURRENT_STATE.md](CURRENT_STATE.md) 的实时快照，在执行前再核验 Git 与远程资源。

1. **WS-06 输入兼容：**从当前个人 fork 分出 `feature/*` 或 `experiment/*` 分支；实现显式流文件、五/六列兼容及 tag 到选路处的数据通路。用旧五列 trace 回归四个 baseline，再用缩比六列 trace 核对解析、标签计数和流完成。记录固定 SHA、trace 哈希和实验 ID。此步不宣称新算法。
2. **WS-07 双轨基线：**定义 tag 与选路粒度、接收端语义的关系，确保所有算法使用相同拥塞控制、PFC 与重排规则；实现单类退化与双类共存正确性检查。若无法给逐包类建立正确的乱序处理模型，则先收缩研究主张或停下修正模型。
3. **WS-07 MixTax：**制作固定总负载、可重生的 trace。以独立 trace seed 为重复单位，配对比较“逐包类用 packet”和“逐包类用 flow/flowlet”，同时报告两类 FCT/CCT、PFC、重传和利用率。先跑小规模 pilot，冻结主指标、参数及正式重复数。
4. **Go / No-go：**若预先规定的混合条件下没有稳定、可解释的跨类损害，停止把 GuardHash/HarmGate 当主论文机制；可保留负结果与评估资产。若损害存在，才进入 WS-08。
5. **WS-08 强对照：**与普通两选短队列、始终共享、静态隔离及可核查的 APS/FLB-like 实现比较。若收益只来自额外即时信息、调参或牺牲另一类流量，应缩小或放弃机制主张。最后再做拓扑不对称、反馈延迟、错标和资源开销边界实验。

当前只授权把本项目的状态工作流建起来；本路线**不自动启动**代码实现、远程实验或旧结果清理。
