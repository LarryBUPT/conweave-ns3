## 4. 按截图落实的研究流程与交付

| 阶段 | 工作 | 必须交付 |
| --- | --- | --- |
| A | 整理本项目失败与消融证据；核对类别信息是否实际改变决策、混杂因素和证据范围 | `failure-lessons.md`：事实、来源、待验解释和可继承经验 |
| B | 拆解相关论文：文献信息与摘要；数据及方法；结果及证据；每幅图支持的结论；明确局限与阅读推断 | 论文卡片、图表—结论对应表、版本与页码；复用已有全文阅读但补查关键原文 |
| C | 建立共识区、分歧区、待解决区；解释数据、方法、场景差异；保留局限及未来方向的关键短引 | `controversy-map.md`，每项判断关联来源，不凭“未搜到”宣称空白 |
| D | 反向追问：真实任务、现有假设、不成立条件、超越模块替换的贡献、尚属猜想的内容 | `research-questions.md`：研究问题—现实约束—待验假设—证据路径 |
| E | 形成少量候选并逐项比对相似工作、类别增量与实现条件；当前不预定具体机制 | `candidates.md`，区分主张、假设与已验证事实 |
| F | 模拟审稿：三项主要疑问；贡献/数据/难度/周期/价值评估；最低补强清单 | `review-and-feasibility.md`；如评分为 1～5 分，低于 3 分须解释，分数不替代证据 |
| G | 建立选题漏斗和选题地图，并设计增量文献雷达 | `topic-funnel.csv`、`topic-map.md`、`literature-radar.md` |
| H | 综合证据与候选，给出推荐及替代方案、最小实现/消融/正式验证计划、停止条件 | `proposal.md` 和九节交接；交用户决定候选，尚未运行的实验保持计划身份 |

选题漏斗字段至少包含论文来源、核心问题、已有方法、局限、项目切入点、证据状态、潜在投稿方向、实现条件、优先级和决定理由。选题地图连接“共识/分歧 → 未解决问题 → 项目切入点 → 预期贡献 → 待验假设 → 验证路径 → 当前决定”，每个关键节点带来源。证据状态分别记录已检索、已读全文、已有项目证据、待实验验证。

文献雷达按网络领域选择 IEEE、ACM、USENIX、作者公开全文和 arXiv 等适当来源。每项列真实链接、核心贡献和对候选的强化/冲突/其他影响；不为了凑篇数纳入无关论文。当前先形成检索式、时间窗和更新模板；定期自动化由主对话依据本阶段实际需要设置，保持无实质变化静默。

## 5. 阶段门槛和边界

1. 第一节点先完成 A、B 的可核验起点与 C、D 的框架，不在未核旧失败证据前直接给机制命名。
2. 选题可为有意义的改进、深化或新视角；相似论文应形成具体差异表，不能成为自动否决或省略引用的理由。
3. 类别可得性、误分类、额外状态、控制开销、业务批次与背景性能分别安排验证；具体实验规模待候选明确后冻结，不照搬旧 892 次计划。
4. 控制组需隔离类别信息的增量；不把改动候选、平局处理或传输语义的版本当作只删除类别信息的消融。
5. 既有正式 NO-GO、原始数据、成功 ID、失败控制器和历史收据均保留，不通过改门槛或改数据获得正结论。
6. 重要完整节点按项目规则复核候选参考文献并留下记录；例行状态读取不重复触发全文审查。
7. WS-29 不读取、不唤醒、不归档；只保留其未来以新基线接续的依赖。
8. 主、副的实际模型取真实上下文，初始采用用户配置的默认模型。未来长矩阵的模型切换遵循工作流且必须实际核验，不能从提示词追认生效。
