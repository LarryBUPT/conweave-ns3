阶段更新：下表 WS-20“独立需求确认性验证”是 WS-19 **通过**时的原条件计划，实际 WS-19 未通过。WS-20 随后仅按[反例审查 Handoff 21](../handoffs/2026-09-28-21-ws20-counterexample-review.md)完成本地失败分析；原确认性矩阵没有运行且继续 no-go。[条件性探索设计 v0](../research/ws20-next-exploratory-design-v0.md)不是下表所列确认性矩阵的改名或续跑。

WS-21 阶段更新：已从 `cdb2d1b` 完成[下游反馈本地可行性审查](../research/ws21-downstream-feedback-feasibility.md)和[Handoff 22](../handoffs/2026-09-28-22-ws21-downstream-feedback.md)；仅技术设计闭环，效果矩阵 no-go。下表 WS-21 的对照尚未运行。WS-22、WS-23、WS-24 保持各自条件，WS-25 只整合真正执行的证据；编号不构成自动开跑顺序。

## 主线及分支

| 任务 | 工作、分支与交付 | 进入下一步的门槛 |
| --- | --- | --- |
| **WS-17 瓶颈可控性与独立需求审计**（首先启动） | 在独立 `feature/ws17-bottleneck-demand` 分支，以源码、WS-13/14 原始 ID 和拓扑核对最终出口/上游路径的容量与可绕行性；明确各信号在发送端、源 ToR 和目的出口的可见时刻。构造可重生、互相独立的 MoE 轮次/目的热点与背景负载输入规格，定义发送等待计入完成时间的口径，冻结最小观测及强对照契约。优先本地只读分析；确有数据缺口才做事前定义的最小探针。交付可证伪机制假说、输入/源码/指标映射、go/no-go Handoff。 | 已定位**可改变的资源**，独立输入有种子及 SHA，目标/背景双侧指标和总完成率均可测；若只剩唯一最终出口且无法控制发送时序，则先说明不可行，不启动新机制仿真。 |
| **WS-18 最小发送准入原型与正确性** | 仅在 WS-17 go 后建独立 `feature/ws18-admission-routing` 分支。实现发送准入、稳定路径和可绕行上游路径控制的分离开关，完整记录原始需求起点、放行时刻与完成时刻；同源码跑 ECMP、仅准入、仅路径、联合模式的最小正确性格。GuardHash/HarmGate 保留为历史原型/可选消融锚点。 | 输入流数、完成数、字节、等待时间、队列/重传事件守恒；任何收益不能由漏计源端等待造成。传输语义及旧基线行为回归通过。 |
| **WS-19 双侧小样与因果拆分** | 在 `experiment/ws19-admission-pilot` 固定机制源码、参数与独立校准输入。先资源 pilot，再比较四臂在无/有背景和可绕行/最终出口热点下的 MoE 合成批次、背景 FCT 尾部、完成率、发送等待及拥塞位置；报告逐格实验 ID、原始哈希、反例与连续权衡。 | 事前双侧停止条件通过，且联合项对“仅准入/仅路径”有可解释增量；否则停止 WS-20，保留机制边界或转条件分支。旧 5% 不是自动沿用的业务线。 |
| **WS-20 独立需求确认性验证** | 仅 WS-19 go 后在 `experiment/ws20-admission-formal` 冻结正式输入生成、重复单位、判据、参数、对照、预算与停止规则。运行独立需求 trace 的配对矩阵，追溯到固定 SHA 与逐格 raw。 | 完成率与双侧限制全部满足才写确认性效果；任一 no-go 保留，不能用事后格或顺序置换补判。 |
| **WS-21 下游反馈替代机制** | 仅 WS-17 证实**可绕行上游热点**且反馈信号可实现时在 `feature/ws21-downstream-feedback` 比较本地队列、理想下游信息、真实延迟/成本和等信息消融。 | 零延迟 oracle 的收益不能直接算作可部署机制收益；反馈过期、状态成本或背景尾部转移可触发停止。 |
| **WS-22 重排预算与粒度机制** | 仅 WS-17/21 显示路径分流机会且接收重排/重传成本可测时在 `feature/ws22-reorder-budget` 比较流、flowlet、小段与预算退化，特别分开大量 8 KiB 短流和 8 MiB 背景流。 | RNIC 乱序、NACK/超时、接收占用、双侧 FCT 和完成率均完整；若粒度成本大于路径收益则停止。 |
| **WS-23 拥塞流隔离** | 仅 PFC=0 下的跨类阻塞得到证明，或 IRN×PFC 压力完成性修复并另立 PFC 契约后，在 `feature/ws23-flow-isolation` 对照类别/长度隔离、ECMP 和等信息机制。 | 不能用旧 13/16 压力格作性能对照；需测饥饿和保留容量。 |
| **WS-24 多 rail 与放置** | 仅存在可核验的多 NIC/跨 rail 连通、任务映射与真实新需求输入时，在 `research/ws24-multirail-placement` 比较固定放置与联合规划。 | 当前只打 rail 0 的输入不可支持跨 rail 收益。 |
| **WS-25 证据与论文收束** | 整合实际启动的分支 Handoff，复核 ID、SHA、raw 与论文表述；区分正式效果、pilot、诊断和未运行。 | 新机制结论须与导师确认的论文范围一致；各历史 no-go 不改判。 |

## 每个分支必须执行的准则

1. 每个 WS 从前序已推送的个人 fork 提交建立独立科研分支；记录父 SHA、实验源码 SHA、输入哈希、seed、预注册、远程实验 ID 和 Handoff。仅向个人 `origin` 推送，不碰两个只读参考仓库。未满足前置门槛时保留 `CONDITIONAL`，不因编号存在就跑仿真。
2. 远程运行遵守[工作流](../REMOTE_EXPERIMENT_WORKFLOW.md)：先核对其他用户、运维与资源，资源 pilot 后按吞吐安全并行；后台静默，正常约每 30 分钟仅看精简完成/异常/资源收据。仿真监督阶段使用 **GPT-6 Luna High**，终态原始结果回传后使用 **GPT-6 Sol High** 分析和收束；实际切换应由任务/编排工具确认，不能把提示当切换事实。
3. 每个分支都在启动前写明主问题、可证伪预测、双侧指标、强对照、独立需求重复单位、限制指标的文献/校准/业务依据及停止条件。若业务 SLO 不可得，报告连续权衡并标注研究性门槛。最小正确性运行和单输入 pilot 不作正式性能主张。
4. 每个分支闭环时产出九段 Handoff，并用自然语言向用户解释**任务流程、哪些实验数据真正支持、任务结论与尚未验证的范围**。表格、SHA、术语只作为可追溯附录，不代替易懂的结论。先集成交接，再决定是否创建下一个任务；除已请求的 WS-17 外，本计划不自动创建后续对话。
