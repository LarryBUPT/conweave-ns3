## 每个分支必须执行的准则

1. 每个 WS 从前序已推送的个人 fork 提交建立独立科研分支；记录父 SHA、实验源码 SHA、输入哈希、seed、预注册、远程实验 ID 和 Handoff。仅向个人 `origin` 推送，不碰两个只读参考仓库。未满足前置门槛时保留 `CONDITIONAL`，不因编号存在就跑仿真。
2. 远程运行遵守[工作流](../REMOTE_EXPERIMENT_WORKFLOW.md)：先核对其他用户、运维与资源，资源 pilot 后按吞吐安全并行；后台静默，正常约每 30 分钟仅看精简完成/异常/资源收据。仿真监督阶段使用 **GPT-6 Luna High**，终态原始结果回传后使用 **GPT-6 Sol High** 分析和收束；实际切换应由任务/编排工具确认，不能把提示当切换事实。
3. 每个分支都在启动前写明主问题、可证伪预测、双侧指标、强对照、独立需求重复单位、限制指标的文献/校准/业务依据及停止条件。若业务 SLO 不可得，报告连续权衡并标注研究性门槛。最小正确性运行和单输入 pilot 不作正式性能主张。
4. 每个分支闭环时产出九段 Handoff，并用自然语言向用户解释**任务流程、哪些实验数据真正支持、任务结论与尚未验证的范围**。表格、SHA、术语只作为可追溯附录，不代替易懂的结论。先集成交接，再决定是否创建下一个任务；除已请求的 WS-17 外，本计划不自动创建后续对话。
