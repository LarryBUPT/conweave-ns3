## 3. 已完成工作

新建[可行性设计记录](../research/ws21-downstream-feedback-feasibility.md)，逐点核对 `DoLbWs18` 的本地队列和流锁口、目的 ToR MMU/设备队列、`WS13_HOP/WS13_QP` 离线诊断、RNIC CNP/速率，以及 CONGA 的量化反馈路径。定位现有日志缺少按时轴连接的逐 QP 跳点与反馈；给出默认关闭、每 QP 汇总加有界时间桶的非扰动观测规格、静态日志/状态预算与同 SHA 开/关技术 pilot 门槛。提出四级信息对照及等成本消融，并标明 oracle 不能当部署收益。动作仅是设计和状态集成，没有新增仿真 ID 或效果数据。

## 4. 已形成的设计决策

决定：**WS-21 效果矩阵 NO-GO；仅开放进一步的观测/反馈工程设计审查。**原因是模式 20 当前只有本地队列和名义准入计时；目的出口即时状态不在源端，CONGA PacketTag/反向数据捎带也不是本机制可直接复用的有成本、定时反馈。候选规则为准入关闭、两个固定上联候选、逐流锁口，用有界年龄的下游 2-bit 等级与同量化本地等级评分；过期或缺失时退回本地选择。候选只针对可区分的上游后续跳点，不给共享最终出口伪造路径差。替代方案“直接拿零延迟目的队列选路”被排除，因为是 oracle；继续旧逐目的固定串行准入被排除，因为 WS-19 轮尾等待已显示副作用。参数只是待校准设计值，未冻结实验协议或宣称效果。
