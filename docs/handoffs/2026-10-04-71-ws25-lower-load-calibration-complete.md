# Handoff 71：WS-25 低负载校准执行完成

日期：2026-10-04。来源任务：`01a0fc98-726e-76e1-8f85-2fb5dbe8d0c4`，WS-25 第一课题。此 Handoff 交接终态实验数据给 Sol High 做分析；不含性能结论，WS-25 仍 ACTIVE。

## 1. 本对话目标

按已冻结 r3 计划执行 0/64/128 档探索性约束校准。用户要求实验与分析自动衔接，人工只作内容问询与方向纠偏；后台运行使用 Luna High，数据终态后由主对话实际切换到 Sol High 分析。两项业务结果为共同主要目标：MoE 批次完成时间与后台流尾部时延。

## 2. 已确认的项目事实

- 机器计划 [r3 JSON](../research/evidence/ws25-v1fix-lower-load-calibration-plan-r3.json)：4 个独立需求 seed × 3 个后台流档位（0/64/128）× 6 种方法，共 72 个 ID，按 16/16/16/16/8 五批随机化执行。方法为 ECMP、DRILL、CONGA、LetFlow、ConWeave、ClassReserve。
- 所有仿真固定源码 SHA `a656104d05c681f9b3a998b5ef4ce3e644558d02`、拓扑 SHA `74a6f7154ca10c3cd6dfd45046c4f8abf0ce27faa8ad11446b6a52920b83afba`；每份流量输入 SHA 在 manifest 与计划中固定。每格为 16,384 条 MoE 流，并按档追加 0/64/128 条后台流；共用 ns-3 seed 1、PFC=0、IRN=1、400 Gbps、9 MiB buffer、`netload=10`、`simul_time=0.01`。0 档背景 P99 记为不适用。
- tag1/tag2 代表模拟器内的业务类别，两类均由 RDMA QP 承载；本实验不代表真实 RDMA 与 TCP/UDP 混合传输。
- 首次启动前因高容量 worker 白名单缺少 12 个低档 trace 被拒，未启动仿真。只扩展该白名单、部署并验证后，原冻结计划恢复执行。控制器首次运行在第一批完成之后因汇总字段缺失退出；第二次尝试的预检拒绝发生在启动新格之前。修复本地恢复逻辑后按相同 ID 继续：第一批 16 格只运行一次，断点恢复时复验而未重跑。

## 4. 已形成的设计决策

- 72 格只是 0/64/128 档描述性约束校准，没有显著性检验或正负效果门槛，不应用于正式 GO/NO-GO，也不重复计算已看过的 192 档样本。
- 正式分析须把需求 seed 作为独立单位，在同一 seed 与背景档内配对六种方法；MoE 批次完成时间和后台 P99 是共同主要结果。不得把 0 档背景 P99 填成 0，不得只将背景损害作为单向容忍线。
