# Handoff 32 — WS-21 精简报文与局部心跳实验前准备

## 1. 本对话目标

用户要求把 SGLB 启发的拥塞信息与状态监测改为适合本项目的精简报文，评估局部心跳，以及更新间隔与额外通信开销的权衡；方案、测试和最终解释须区分 Sol High 分析与 Luna High 实验。本阶段完成本地设计与代码准备，尚未进入实验模型阶段。

## 2. 已确认的项目事实

权威工作流和 baseline 审计已按序读取；个人 fork 分支 `feature/ws21-downstream-feedback` 的前一源码 HEAD 为 `c7faa4a`，开始时工作树干净。旧长尾反馈 pair 固定 SHA `9964203cf6d3de4bc1061d61b6f959bcb537c120`，原始 ID `20260929-170600-ws21-feedback-longtail` / `20260929-171900-ws21-feedback-longtail-on`，机器收据见 `docs/research/evidence/ws21-feedback-longtail-pair.json`：两格各 16,576/16,576 完成；开启格 29,388 条报告全送达、9,003,540 逐跳字节、13,916 条流的完成时间改变，缺运行中峰值 RSS。报告缓存没有影响选路。旧工程门槛失败、效果矩阵关闭，不因新的权衡口径而重判。

静态拓扑文件首行与链路表核验为 1,280 主机、576 交换机、3,840 链路，其中 2,560 条交换机间链路；160 台 ToR 各有 8 条上联。全链路高频心跳的消息数不可接受，需限于活跃的局部上联。SGLB 官方论文页面/DOI 见新契约；原论文 GLB 硬件与 BGP/SyncMesh 控制面不等同于本项目现有反馈头。

## 3. 已完成工作

写入 `docs/research/ws21-compact-control-protocol-and-tradeoff-contract.md`，逐项区分原论文功能、项目保留/排除范围、STATE 与 HELLO/ACK 的独立计费、先正确性再技术/效果的阶段门槛，以及没有业务 SLO 时只报告 Pareto 非劣集的选择规则。旧数据推算 51→26 B 在**相同报告数/路由/无填充**假设下约少 734,700 B 交付字节和 2,648,100 B 逐跳字节；明确标为反事实估算，不是仿真结果。

把 `Ws21FeedbackHeader` 改为 v2 26 B：省去由 IPv4 地址可推得的两端 ToR、窗口起点和 64 位序号；保留候选端口、CE 分子/样本分母、窗口末时间、32 位序号、16 位生成延迟。增加非法版本/类型/空样本/零序号校验与接收端长度检查。报告聚合间隔由固定 10 µs 改为可配置 1–60 µs，并在汇总计数中单列“样本末至送达年龄”，以免只看传输年龄掩盖旧样本。扩展现有报文头往返单测。`python -m py_compile run.py` 和 `git diff --check` 均通过。

## 4. 已形成的设计决策

采用“同一控制报文族、两种消息用途、分别计费”：状态报文只对有样本的候选窗口发送，心跳只监测有业务的本地 ToR 上联。静态路由与既有选路规则保留为失效退回；不复刻 SGLB 专用硬件、BGP、SyncMesh KV 同步或全网泛洪。报告体积缩小与更新周期是两个分开的因素；心跳第三阶段单独验证后才合并。未获数据前不设唯一“最优”周期，不以新讨论更改旧 no-go。

## 5. 当前状态

新源码尚未在远端编译/执行；26 B 报文与可配置窗口只是本地准备。`HELLO/ACK`、局部租约、丢失/恢复故障注入、缓存参与选路、独立需求效果实验均未实现。静态检查通过不代表编译或通信正确。当前模型是否为 Luna High 尚无任务/编排工具确认，不能启动远程 build/run 并宣称符合模型流程。

## 6. 未解决问题

必须先确认远端 `Ipv4Header`、Waf 单测和完整模拟对新头的实际支持；实际包长是否有填充、不同窗口的报告数/样本年龄与业务扰动均未知。需为邻居直连心跳定义真实报文路径、订阅/撤订、会话重启/乱序、失效与恢复语义。需量测决策前候选信息可用率，才能考虑把缓存接入选路；业务 SLO 仍缺，不能做唯一最优选择。

## 7. 后续推荐动作

先提交/推送本地准备变更、记录新 SHA 与输入哈希；由任务工具**实际**切换 GPT-6 Luna High。检查远端无人作业及健康资源后，隔离构建和运行 point-to-point 单测，失败先修复。通过后按新契约先做 40 流最小正确性，再考虑固定 16,576 流的反馈间隔技术矩阵；每个新 ID、SHA、输入/拓扑哈希和资源收据独立，正常长时运行半小时精简监督。终态 raw 回传后**实际**切回 GPT-6 Sol High，对原始数据计算双侧开销、样本年龄、流完成与 Pareto 集；再决定是否实现/测试局部心跳和进一步效果探索。若正确性或收据不完整，停止扩展。
