## 3. 已完成工作

用户确认 Luna 监督已生效。启动前远端审计显示无登录用户、无在途仿真，负载约 0.01–2.7，可用内存约 122.8–123.0 GiB，磁盘约 5.6 TiB。pair 源码以 optimized `-j2` 分格隔离构建，两格固定 SHA 相同。使用 5 秒采样器记录每格负载、内存、磁盘、进程 RSS、日志及输出文件规模。

首个旧日志实现 `fdedcd770f22491a612e76372973538b16ca31b6` 的关闭格 `20260929-130119-ws21-longtail-diagnostic` 状态为 `SUCCEEDED`，运行 303 s、16,576 流和总字节守恒，但 `config.log` 达 260,177,114 B；其中 1,610,688 行是普通 IRN ACK，QP 总行数 1,623,113。按 50 MB 文本日志门槛，这个诊断格不合格，因此未启动旧版本开启格，也未将它纳入 pair。

修复日志粒度后，在源码 `478eca21b626113aa9dc58a33085b0d0a287f740` 上完成新 pair：`20260929-132600-ws21-tail-off` 运行 287 s，`20260929-132700-ws21-tail-on` 运行 297 s。两格 FCT SHA 均为 `964b7f757f93397d56f2ab1434aa4647dfc4b23d083ecd08ef6486fac7f0e18f`，WS18 SHA 均为 `e12ab3388a27f2ccec9b85acf1d590680816e7b7d91a9e22b90e2a9e58e5fbab`；各 16,576 QP 完成，总字节 1,744,830,464。`config.log` 分别 2,141,391 / 2,141,523 B。开启格身份检查覆盖全部 16,576 QP，其中 16,205 跨 ToR QP 的源/目的记录完整且零错误；上游 CE 计数 10,123 包、分布在 3,707 个目的侧观测 QP。端口事件覆盖 1,280 端口、7,035,136 条、raw 164,219,537 B、overflow=0，峰值队列 641,648 B。原始数据已回传，`verify_ws21_pair.py` 和[专用分析器](../../scripts/analyze_ws21_longtail_pair.py)均通过，机器摘要写入[证据 JSON](../research/evidence/ws21-longtail-pair.json)。

## 4. 已形成的设计决策

长尾输入的观测、身份、出口事件和同 SHA 诊断非扰动子门槛**通过**。普通 ACK 改为每 QP 首条进度记录后，QP/仿真文本日志低于 50 MB，SACK/CNP、超时、恢复、重传及 DCQCN 速率转折仍逐事件记录。首个超限版本作为诊断工程反例保留，不与新 SHA pair 混合。

开启格看到 10,123 个实际所选路径上的上游 CE 包；这消除了此前 40 流样本 CE 为零导致的观测空白，但没有对替代候选路径做 CE 对照，也没有真实反馈报文，因此不证明信号能区分候选或机制有收益。**WS-21 完整技术 pilot 尚未就绪，效果矩阵仍 NO-GO。**

## 5. 当前状态

仿真终态均为 `SUCCEEDED`，两个 raw 均已 fetch 并完成配对核验。运行资源收据每格约 5 分钟、每 5 秒采样：off/on 仿真最大进程 RSS 为 4,500.7/4,503.9 MiB；最小可用内存约 121,439 MiB；最大单个文本日志约 2.14 MB。开启格结构化端口事件 raw 约 164.2 MB，低于其 256 MiB 字节上限，且无溢出。此结构化 raw 文件由独立字节上限控制；50 MB 限制针对文本日志与 QP 时间线。

默认 `analyze_result.py` 在两格都报“分析窗口无已完成流”：它只取 2.005–2.060 s 窗口，而本 trace 的 start time 为 2.000000–2.000350 s，所有流在其前完成。专用分析器使用全部 WS18 demand-to-finish 时长，按 nearest-rank 给出单输入描述性分位数；不得把它们与默认窗口的历史指标混排。

## 6. 未解决问题

本轮没有实现目的 ToR 到源 ToR 的反馈报文，没有测生成/送达/丢失/过期/采用、报文字节、排队与传播、反馈年龄和陈旧回退。CE 只按当前实际选路记录，不能比较未选候选的信号质量。QP 时间线有 9,114 个 CNP、3,086 次 DCQCN rate decrease 等事件；本 pair 未记录到 SACK、timeout、retransmit 或 recover-queue 事件。单输入没有独立需求重复，也没有业务 SLO。

## 7. 后续推荐动作

若继续该研究方向，先设计并实现可计费的显式反馈通路，定义序列化、送达时延/年龄、丢失/过期和退回行为，再逐消息核验并建立候选路径信息差异收据。只有该工程 pilot 通过且另行冻结新的双侧独立需求协议后，才讨论效果实验；当前 pair 不自动解锁效果矩阵。
