# Handoff 40：WS-22 重排预算与粒度机制门槛审查

1. **来源与目标：** 来源任务“WS-22 重排预算与粒度机制审查”（Codex task `01a0f124-3c54-7843-b183-57d2cbf0ea5c`），在个人 fork 基线 `330596a2d22752e88deaba56e76d10164e8af186` 建立分支 `feature/ws22-reorder-budget`。目标是判断流/flowlet/小段粒度与接收重排预算能否进入仿真阶段。

2. **本轮工作：** 只读核对项目流程、ConWeave 指标审计、`ConWeaveVOQ`、RNIC 序号/IRN SACK/NACK/超时/重传代码、WS-19 代表性原始结果及 WS-13/21 既有诊断；查阅 ConWeave、Presto 与 ParaLet 的机制和适用假设。未修改源码或实验输入，未启动远程编译或仿真。

3. **路径机会与限制：** 当前 1280 主机拓扑中，跨 ToR 业务有八条等跳上游候选，但固定目的主机共用唯一最后出口。WS-19 结果表明路径臂在特定 ToR/192 情景出现背景 P99 改善，但不能推出把同一 QP 切成小段会更好；WS-19 联合臂原结论仍 no-go。WS-21 反馈缓存尚未参与选路，其通信引起的时序变化不是候选路径收益。

4. **接收端证据缺口：** `ConWeaveVOQ` 只处理受控的相邻 phase 换路；现有实现没有字节/队列深度预算。可用观测主要是 ToR/目的地周期样本与全局入队计数，不能恢复逐 QP 的乱序字节/深度、持有时长和峰值接收占用。RNIC 有序号检查、IRN SACK、超时及重传路径，但协议类型 `0xFD` 在 IRN 模式也承载普通 ACK；不能按类型直接计 NACK。SACK 区间长度不等价于真实 RNIC buffer 占用。WS-13 探针只覆盖选定背景 QP，无法提供全体 QP 序列。当前运行器对目标拓扑的 ConWeave 参数组合也有兼容限制。

5. **成熟方案边界：** ConWeave 的 FIFO 重排依赖每流至多两条在途路径等受控切换假设；Presto 的 64 KB flowcell 依赖 TCP/TSO/GRO；ParaLet 针对少量大 RDMA 流。它们支持将粒度、重排与传输成本作为研究变量，但其粒度或性能数字不能直接移植为本项目 RDMA 混合流的阈值。8 KiB/8 MiB 是当前合成类别，尚非经业务或文献验证的代表分层。

6. **结论：NO-GO for remote simulation。** 目前尚无可信的逐 QP 接收预算和成本序列，无法把重排代价与潜在路径收益做双侧归因；因此不冻结流/flowlet/小段矩阵，不选择小段长度或通用损害百分比。该结论是实验前门槛未满足，不是重排机制无效的性能结果。

7. **必要前置：** 若以后重开，先在本地设计非扰动计量，覆盖路径切换、乱序字节/深度、VOQ 持有字节/时间、IRN SACK、真实与抑制的超时、重传字节和完成状态；核验编译模式下计数确实生效。再证明候选路径存在可绕行拥塞，冻结输入、源码、seed、对照、独立需求、双侧完成率与时间指标、资源/停止条件。若无业务 SLO，保留连续成本权衡。

8. **WS-21 结论与后续位置：** STATE 与局部 HELLO/ACK 试验只证明报文代价、有限状态新鲜度和连续控制消息丢失检测；心跳 `UNKNOWN` 不触发改路，反馈缓存也没有 adopted/fallback 选路收益证据。其待办包括单份丢失/异常 ACK/会话重启/真实 link down-up、长尾 STATE+心跳联合成本、候选区分与 adopted/fallback。它们与 WS-23 拥塞隔离不同，列入 WS-25 证据收束清单逐项判定是否为论文主张所必需；不得为追求进度自动扩大为仿真。

9. **CONTEXT SNAPSHOT：** WS-22 已完成本地机制/可观测性审查，远程仿真 no-go。下一步 WS-23 仅审计 PFC=0 跨类阻塞和旧 IRN×PFC 13/16 压力格是否满足前置；门槛未满足则本地 no-go。WS-21 残余验证决策放入 WS-25。项目路线见 `docs/project-state/WS17_PLUS_PLAN.md`，状态见 `docs/project-state/WORKSTREAMS.md`。
