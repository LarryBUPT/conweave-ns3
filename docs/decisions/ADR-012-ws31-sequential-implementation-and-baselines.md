# ADR-012：WS-31 按 C1、C2、C3 顺序实现并自主评估新增基线

状态：Accepted。日期：2026 年 11 月 1 日。来源为 WS-31 主对话 `01a19322-95a5-76e3-a4f5-1f1e9dde81ce` 的直接用户消息，turn `01a193ea-2ccf-79d0-959c-d375143f95e4`。Integration 已读取原消息，未仅依据另一对话的转述更改权限。[原文证据](../research/evidence/ws31-implementation-authorization-20261101/user-instruction.json)保留准确指令。

## 决定

1. 用户已指定 C1 → C2 → C3 的提案判断与实现顺序。原“仅做提案、等待用户选候选”的阶段门已解除，不再重复请求该许可。先前提案和选题地图保留为阶段产物。
2. 正式对照以 DRILL、ConWeave、CONGA、ECMP、LetFlow 为基础；QueuePin 保留为类别增量的直接对照。Gemma 等额外负载均衡方法的实现成本、必要性和准入由 WS-31 主对话自主决定，并记录理由和版本，不自动要求所有相关方法实现。
3. 主对话负责顺序判断、隔离实现、协议与决策，以及从本地 raw 独立核验。唯一副先完成新增基线准入核对，后续按单目标和冻结计划承担独立复核或唯一远端执行。Integration 只维护权威状态和协调记录。
4. 实现授权不替代实验门槛。每个候选仍需准确的状态/信号/控制/消融契约、默认关闭回归和正确性，再冻结独立输入、指标、分析、资源、运行 ID 和停止条件后进入相应新实验。构建、单测、启动与性能验收分别记录。
5. 相同信息和代价的无类别控制、大小先验或历史记忆等近邻控制按候选实际需要设置，不能用同时改变候选生成、平局或传输语义的版本充当只删除类别信息的消融。具体选择及成本由主在实现方案中说明。
6. 已验证的 QueuePin 源版本映射、旧 NO-GO、成功 ID 和失败记录均保留；不恢复旧控制器、旧 v14 的 840 次或 WS-26 的原矩阵。WS-29 继续后置、未归档，不读取或唤醒。
7. 新组合基线必须依据实际正确性和独立效果验证形成。当前用户授权的是判断与实施次序，没有产生新的性能结论或自动判定最终机制成立。

## 协调与持续推进

原提案阶段心跳已由 WS-31 主对话在交付后删除；该删除不视作当前用户要求停止研究。Integration 在确认新直接授权且未发现同目标自动化后，按原 30 分钟频率重建唯一主对话续作，登记于 [协调文件](../project-state/ws31-coordination.json)。目标无实质变化时保持静默，主、副 active 时不重复派发。当前科学执行状态由 `docs/research/ws31/main/current-status.json` 管理。

本 ADR 更新 [ADR-011](ADR-011-ws30-closure-ws31-and-ws29-deferral.md) 对 WS-31 阶段范围的描述；历史归档与 WS-29 后置决定不变。完整当前流程见 [WS31_EXECUTION](../project-state/WS31_EXECUTION.md)。
