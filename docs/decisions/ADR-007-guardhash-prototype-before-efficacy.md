# ADR-007：先做 GuardHash/HarmGate 工程原型，效果主张仍过证据门槛

状态：Accepted for engineering exploration。日期：2026-09-26。来源：用户在 WS-08 闭环后明确要求最快推进 GuardHash 与 HarmGate 的实现和验证；本决策更新 [ADR-006](ADR-006-conditional-guardhash-selection.md) 中“损害门槛通过后才写机制代码”的顺序，不改变其正式效果判据或 WS-08 的负向结果。

## Decision

WS-09 可在个人 fork 的独立新分支实现**最小、可关闭的研究原型**，并完成编译、计数守恒、旧模式回归、小拓扑和有限资源 pilot。实现本身不表示跨类损害已证实，也不表示 GuardHash 优于强对照。正式论文机制主张仍须在预先冻结的共同传输、固定目标/总字节、独立 trace seed 下通过 WS-07 契约和同模型强基线比较。

术语上，**HarmGate 是跨类损害问题与本地激活门槛，GuardHash 是双候选选路规则**。此前文档没有给出第二套独立的 HarmGate 算法。WS-09 应在写代码前把 HarmGate 的可观测输入、激活/退出条件与 GuardHash 的候选评分分别冻结，提供可关闭门控的消融，而不以两个名字重复计同一收益。若最终决定 HarmGate 是独立机制，须另立规格和对照。

## Rationale

WS-08 的共享 PFC=0、IRN=1 单 seed 四格全部完成，MoE 交互 `−0.053 µs`，背景 P99 差为 0；当前没有支持机制收益的正向信号。用户的新目标是加快实现与验证。先建可关闭原型能提前暴露标签传递、队列统计和路径选择的工程问题，同时保留负结果。把工程验证与效果判断分开，可避免将一次试点或调参结果包装为论文结论。

## Implementation and evidence boundary

- 冻结 `fecmp`、`dualtrack`、普通双候选短队列、GuardHash（类别信号）和 HarmGate 开/关的模式/消融矩阵。两候选的哈希输入、背景流固定路径、控制包路径及 PFC/IRN/DCQCN 必须一致；只让类别统计/激活门槛产生可归因差异。
- 在实际交换机入队、出队、丢包路径核验 per-port/per-tag 字节计数守恒与采样时点。总队列 `q_j` 与背景占用 `b_j` 及门槛、权重、并列规则要写成配置和冻结值；不能由既有四格 FCT 事后挑选。观测若不可用或不守恒，停止效果 pilot，先修正仪表。
- 先做 32 主机和导入拓扑四流的正确性，再在同一 PFC=0、IRN=1 契约下做与普通短队列双候选的资源受控比较。记录每类完成率、MoE 合成批次、背景 P99、CNP/超时、候选改路率、计数器状态和资源消耗。旧 PFC=1、IRN=0 结果只作单独敏感性记录。
- WS-10 负责预注册条件和固定总字节、多独立 trace seed 的现象复核；WS-11 在适用条件成立时做等信息强对照、消融和边界。若现象仍不存在或类别信号没有超过普通短队列的增量，保留代码与负结果，但不称 GuardHash/HarmGate 为有效论文机制。

## Consequences

允许现在编写与技术验证原型；不允许把 WS-08 的 `no-go` 解释为已经反转的性能结论。后续若调整机制定义或筛选场景，应在看新效果数据前版本化条件、预算和比较矩阵。
